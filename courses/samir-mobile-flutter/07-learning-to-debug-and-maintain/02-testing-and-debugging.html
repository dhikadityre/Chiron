Core Knowledge

Dokumentasi ini menjelaskan metodologi pengujian dan diagnostik teknis pada modul SAMIR Flutter (flutter_app_project), menguraikan penggunaan 🦊 flutter/lib/pages/mine/debug/proxy_debug_page.dart learn/Flutter-Arch ↗, konfigurasi intercept proxy jaringan (Charles / Proxyman), pemanfaatan bypass SSL, serta inspeksi HTTP in-app menggunakan Chucker.

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Membuka dan mengonfigurasi ProxyDebugPage pada aplikasi build non-PROD.
  2. Mengarahkan lalu lintas HTTP/HTTPS Dio ke Charles Proxy atau Proxyman tanpa memasang root certificate khusus di sistem operasi perangkat.
  3. Memahami peran badCertificateCallback dalam menyederhanakan debugging di lingkungan testing.
  4. Menggunakan alat inspeksi HTTP in-app (chucker_flutter) untuk debugging mandiri oleh tim QA.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan Anda ingin memeriksa kejernihan air yang mengalir di pipa bawah tanah tanpa membongkar jalan raya:

  • Jalur Standar: Air mengalir langsung dari PDAM ke keran rumah (Koneksi normal ke server backend).
  • Katup Inspeksi (ProxyDebugPage): Anda memutar tuas katup sementara agar air dialihkan melewati tabung kaca transparan di atas meja laboratorium Anda (Charles Proxy / Proxyman).
  • Anda dapat mengamati warna air, mengukur kadar garam, dan bahkan menyuntikkan pewarna uji coba (Mock API Response) sebelum mengalirkannya kembali ke keran rumah.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Layar Pengaturan Proxy: ProxyDebugPage

File 🦊 flutter/lib/pages/mine/debug/proxy_debug_page.dart learn/Flutter-Arch ↗:

void _save() {
  if (AppEnv.isProd) {
    Navigator.of(context).maybePop();
    return;
  }
  final String proxyIp = _controller.text.trim();
  if (proxyIp.isNotEmpty && !_isValidProxy(proxyIp)) {
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('Format proxy harus host:port')),
    );
    return;
  }
  Global.proxyIp = proxyIp.isEmpty ? null : proxyIp;
  httpClient.init(); // Rekonstruksi Dio adapter dengan proxy baru!
  ScaffoldMessenger.of(context).showSnackBar(
    SnackBar(
      content: Text(
        proxyIp.isEmpty ? 'Proxy dinonaktifkan' : 'Proxy diperbarui',
      ),
    ),
  );
}

Cara mengakses halaman ini:

  1. Buka aplikasi build non-PROD (Dev / Test).
  2. Masuk ke Tab Saya (/mine) -> ketuk kartu profil untuk membuka MinePersonalPage.
  3. Gulir ke bagian paling bawah, lalu ketuk teks nomor versi aplikasi sebanyak 5 kali berturut-turut.
  4. Halaman ProxyDebugPage akan terbuka.

2. Mekanisme Injeksi Proxy di IOHttpClientAdapter

Pada 🦊 flutter/lib/common/http/http_client.dart learn/Flutter-Arch ↗ (baris 43–59):

dio.httpClientAdapter = IOHttpClientAdapter(
  createHttpClient: () {
    final io.HttpClient client = io.HttpClient();
    // 1. Bypass SSL Handshake (mengabaikan self-signed cert Proxyman/Charles)
    client.badCertificateCallback =
        (io.X509Certificate cert, String host, int port) => true;

    // 2. Pasang Proxy IP jika tidak di Production
    if (!AppEnv.isProd) {
      if (Global.proxyIp != null && Global.proxyIp!.isNotEmpty) {
        client.findProxy = (Uri uri) {
          return 'PROXY ${Global.proxyIp}';
        };
      }
    }
    return client;
  },
);

3. Mengapa Tidak Perlu Root Certificate di Flutter?

Pada aplikasi Flutter biasa, Dart VM mengabaikan pengaturan HTTP Proxy bawaan iOS Settings dan tidak memercayai certificate authority (CA) yang dipasang di keychain perangkat, sehingga pengetesan Proxyman/Charles sering menghasilkan error HandshakeException: CERTIFICATE_VERIFY_FAILED.

Di SAMIR Flutter:

  • badCertificateCallback => true memberitahu Dart VM: "Terima seluruh sertifikat SSL dari host manapun!"
  • Hal ini memungkinkan Proxyman / Charles melakukan dekripsi HTTPS Man-in-the-Middle (MITM) secara instan tanpa perlu menginstal atau memercayai sertifikat root di iPhone/Android.

4. In-App HTTP Inspector: Chucker Flutter (Branch Testing Nexus)

Pada branch feature/testing di repositori Nexus:

  • Paket chucker_flutter: ^1.9.2 dipasang sebagai interceptor:

_dio.interceptors.add(ChuckerDioInterceptor());

  • Tombol aksi mengambang (Floating Action Button) berikon serangga (Icons.bug_report) muncul di setiap layar.
  • Mengetuk tombol menampilkan dasbor riwayat seluruh request: URL, Request Body, Response JSON, durasi milidetik, dan HTTP status code.

📌 E. Panduan Langkah Demi Langkah: Menghubungkan ke Proxyman / Charles

  1. Jalankan Proxyman di Laptop/Mac:
    • Pastikan laptop dan smartphone terhubung ke jaringan Wi-Fi yang sama.
    • Catat alamat IP lokal Mac Anda (misalnya: 192.168.1.50) dan port Proxyman (default: 9090) atau Charles (default: 8888).
  2. Buka ProxyDebugPage di Smartphone:
    • Ketuk nomor versi 5 kali di MinePersonalPage.
  3. Masukkan Alamat Proxy:
    • Masukkan string: 192.168.1.50:9090.
    • Tekan tombol Simpan.
  4. Inspeksi Traffic:
    • Lakukan pull-to-refresh di Tab Tagihan.
    • Seluruh request repayment/repayOrderList beserta parameter tanda tangan MD5 seketika muncul rapi di layar Proxyman laptop Anda.
  5. Menonaktifkan Proxy:
    • Kosongkan kolom input teks di ProxyDebugPage lalu tekan Simpan.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Kecepatan Diagnosis Masalah QA:

QA sering menghadapi kendala saat memvalidasi API baru: apakah bug berasal dari tampilan Flutter yang salah merender data, atau backend yang mengembalikan nilai kosong? Dengan menyetel proxy IP atau memeriksa Chucker, QA dapat membuktikan sumber masalah dalam hitungan detik tanpa bantuan engineer.

  • Isolasi Keamanan Ketat:

Kode if (AppEnv.isProd) return; memastikan bahwa mekanisme proxy injection dan bypass SSL mati total di build App Store / Google Play resmi, melindungi nasabah dari serangan MITM di jaringan Wi-Fi publik.

⚠️ G. Common Mistakes & Debugging

  • Salah Menulis Format Port Proxy:
    • Menulis http://192.168.1.50:8888 (dengan protokol http://) akan ditolak oleh validator regex _isValidProxy(). Format yang benar adalah murni host:port (contoh: 192.168.1.50:8888).
  • Lupa Menghapus Proxy Setelah Selesai:
    • Jika laptop dimatikan tetapi proxy IP belum dikosongkan di aplikasi, seluruh request berikutnya akan gagal (Connection Refused). Cukup buka kembali ProxyDebugPage dan hapus string proxy.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
