📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Selamat datang di repositori dokumentasi pembelajaran dan panduan teknis mendalam untuk modul SAMIR Flutter (flutter_app_project).

Dokumentasi ini disusun khusus sebagai progressive learning path (kurikulum bertahap) bagi mobile engineer — baik Flutter engineer murni maupun native iOS/Android engineer — untuk memahami bagaimana modul Flutter bekerja di dalam arsitektur hybrid Add-to-App SAMIR. Modul ini menghosting dua tab utama aplikasi secara penuh: Tagihan (Repay) dan Saya (Mine), serta mengelola komunikasi dua arah dengan host native melalui MethodChannel, GoRouter, dan Native Chrome Sync.

[!IMPORTANT] Prinsip Dokumentasi Ini: 1. Teach progressively: Dimulai dari konsep dasar Add-to-App hingga sinkronisasi engine, routing kompleks, dan penandatanganan request. 2. Trace everything to source code: Setiap penjelasan disertai lokasi file konkret, nama class/fungsi, dan nomor baris acuan di repositori aktif. 3. Explain like I'm a junior, analyze like a senior: Bahasa mudah dipahami tanpa mengorbankan ketajaman analisis teknis arsitektur. 4. Honest verification: Fakta dipisahkan secara tegas antara [Verified] (terbukti dari kode aktif), [Inferred] (kesimpulan logis dengan bukti pendukung), [Unverified] (belum ada bukti di repo), dan [Historical] (catatan peninggalan masa lalu).

[!NOTE] Git Reference Baseline / Anchor Branch: Seluruh analisis arsitektur, lokasi berkas, dan nomor baris acuan di dalam dokumentasi ini dijangkarkan ke branch git: learn/iOS-Arch pada repositori 🦊 samir-mobile learn/Flutter-Arch ↗ (terletak pada path Mobile/Develop/samir-mobile-develop/flutter). Catatan pengayaan debugging (seperti Chucker dan pendeteksian System Proxy) turut diperbandingkan dengan branch feature/testing di Mobile/Nexus/samir-mobile-nexus/flutter.

📌 🚀 Panduan Memulai Belajar

Jika Anda adalah developer yang baru pertama kali menyentuh modul Flutter SAMIR:

  1. Buka file kurikulum: Baca 00-learning-roadmap.md. Ikuti materi Level demi Level secara berurutan.
  2. Pahami Peran Add-to-App: Baca 01-project-foundation/01-application-overview.md untuk memahami bahwa Flutter di SAMIR bukan aplikasi standalone, melainkan modul yang di-embed ke dalam Native iOS (IDSamirLoan) dan Android.
  3. Pahami Alur Boot: Baca 02-understanding-app-startup/01-flutter-entry-point.md untuk memahami bagaimana Flutter dihidupkan dari main.dart dan menyapa balik Native host via flutterReady.
  4. Pahami Mekanisme Tab Hosting: Baca 02-understanding-app-startup/04-root-container-and-tab-switching.md untuk mengerti bagaimana satu FlutterRootPage dengan IndexedStack menyajikan halaman Tagihan dan Saya secara instan tanpa recreate engine.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:

Kuis 1 (Memory Recall): Berdasarkan standar Clean Architecture, apa peran utama dari domain layer pada modul FLUTTER?
