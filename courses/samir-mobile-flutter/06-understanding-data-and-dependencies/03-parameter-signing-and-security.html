03 — Parameter Signing & Security

Mekanisme Tanda Tangan Parameter Dua Tahap MD5

📚 Modul: 03-parameter-signing-and-security 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini membongkar arsitektur kriptografi dan mekanisme keamanan data pada modul SAMIR Flutter (flutter_app_project), menjelaskan algoritma tanda tangan parameter dua tahap (Two-Pass MD5 Signature) pada 🦊 flutter/lib/common/http/sign_utils.dart learn/Flutter-Arch ↗, pengurutan alfabetis parameter via SplayTreeMap, pengambilan parameter perangkat keras native di 🦊 flutter/lib/common/http/param_utils.dart learn/Flutter-Arch ↗, serta peran kunci dinamis dynamicSignKey.

Status Verifikasi: [Verified] (diverifikasi langsung dari inspeksi kode 🦊 flutter/lib/common/http/sign_utils.dart learn/Flutter-Arch ↗ dan 🦊 flutter/lib/common/http/param_utils.dart learn/Flutter-Arch ↗).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memahami ancaman keamanan manipulasi parameter (Man-in-the-Middle request tampering) pada aplikasi finansial.
  2. Menjelaskan rumus matematis dan dua tahap hashing MD5 yang membentuk nilai parameter sign.
  3. Memahami mengapa SplayTreeMap digunakan untuk mengurutkan parameter secara leksikografis (A–Z).
  4. Mengetahui asal-usul dynamicSignKey dari native host dan fallback salt rahasia (766b035b-... dan qwer1234_Samir).

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan mengirimkan cek transfer dana melalui kurir:

  • Jika Anda hanya menulis nominal di atas kertas biasa, kurir nakal dapat menambahkan angka nol di belakang nominal tersebut.
  • Untuk mencegah pemalsuan, bank mewajibkan Anda:
    1. Menulis seluruh rincian transaksi berurutan dari A sampai Z.
    2. Menempelkan stempel lilin pertama menggunakan cincin stempel pribadi Anda (Pass 1 MD5 dengan dynamicSignKey).
    3. Menempelkan stempel lilin kedua di atas stempel pertama menggunakan cap resmi lambang bank (Pass 2 MD5 dengan Salt Rahasia Aplikasi).
  • Jika ada satu huruf atau angka yang diubah di tengah jalan, bentuk stempel lilin akan pecah dan kasir bank akan langsung menolak cek tersebut.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Algoritma Dua Tahap MD5 di sign_utils.dart

File 🦊 flutter/lib/common/http/sign_utils.dart learn/Flutter-Arch ↗:

/// Kunci rahasia tahap pertama (dinamis dari host atau fallback UUID)
String _getSignCipher() {
  return Global.dynamicSignKey ?? '766b035b-8d2f-454a-abad-4e8ab138a99a';
}

/// Kunci rahasia tahap kedua (terikat ke nama aplikasi)
String _getSignCipher2() {
  return 'qwer1234_${Global.appName}'; // 'qwer1234_Samir'
}

String signParamMapWithSignKey(
  SplayTreeMap<String, dynamic>? paramsTreeMap,
  String signKey,
) {
  final StringBuffer buffer = StringBuffer();

  if (paramsTreeMap != null) {
    final Iterator<String> itKeys = paramsTreeMap.keys.iterator;

    while (itKeys.moveNext()) {
      final dynamic value = paramsTreeMap[itKeys.current];
      if (value != null) {
        if (value.runtimeType == String ||
            value.runtimeType == double ||
            value.runtimeType == int ||
            value.runtimeType == bool) {
          buffer.write(value);
        }
      }
    }

    buffer.write(signKey);
  }

  // Tahap 1: MD5 dari gabungan nilai primitif + signKey
  String sign = EncryptUtils.encodeMD5(buffer.toString());

  // Tahap 2: MD5 dari (Hasil Tahap 1 + Salt Rahasia Kedua)
  sign = EncryptUtils.encodeMD5(sign + _getSignCipher2());

  return sign;
}

2. Pengurutan Alfabetis Menggunakan SplayTreeMap

Di 🦊 flutter/lib/common/http/param_utils.dart learn/Flutter-Arch ↗ (baris 9–23):

Future<SplayTreeMap<String, dynamic>> addDefaultParamsAndSign(
  Map<String, dynamic>? paramsTreeMap,
) async {
  final SplayTreeMap<String, dynamic> requestParams =
      SplayTreeMap<String, dynamic>();

  // 1. Tambahkan parameter bawaan platform
  requestParams.addAll(await _defaultParamsByPlatform());

  // 2. Tambahkan parameter bisnis spesifik request
  if (paramsTreeMap != null) {
    requestParams.addAll(paramsTreeMap);
  }

  // 3. Hitung tanda tangan dan sisipkan ke key 'sign'
  requestParams['sign'] = signParamMap(requestParams);

  return requestParams;
}

Mengapa SplayTreeMap wajib digunakan?

  • Map biasa di Dart mengurutkan entri berdasarkan waktu penyisipan (insertion order). Jika dua perangkat memasukkan parameter dengan urutan berbeda (misal: page sebelum userNo), string gabungan akan berbeda dan tanda tangan akan dianggap tidak valid.
  • SplayTreeMap secara otomatis mengurutkan semua kunci (keys) secara alfabetis leksikografis (A–Z), menjamin hasil konkatenasi selalu 100% identik di setiap perangkat dan di server.

🪜 E. Step-by-Step Walkthrough: Rekonstruksi Pembentukan Nilai sign

Misalkan request memiliki parameter berikut:

{
  "orderId": "ORD123",
  "clientId": "test_id",
  "timestamp": 1729600000
}
  1. Pengurutan oleh SplayTreeMap:
    • clientId -> "test_id"
    • orderId -> "ORD123"
    • timestamp -> 1729600000
  2. Konkatenasi Nilai Primitif:

buffer = "test_idORD1231729600000"

  1. Penyisipan Kunci Rahasia 1:

buffer += "766b035b-8d2f-454a-abad-4e8ab138a99a"

Hasil: "test_idORD1231729600000766b035b-8d2f-454a-abad-4e8ab138a99a"

  1. Pass 1 Hashing (MD5):

hash1 = md5(buffer) = "e10adc3949ba59abbe56e057f20f883e"

  1. Pass 2 Hashing (MD5 dengan Salt 2):

input2 = hash1 + "qwer1234_Samir"

sign = md5(input2) = "c33367701511b4f6020ec61ded352059"

  1. Injeksi ke Payload Akhir:

Kunci 'sign' disisipkan ke dalam request sebelum dikirim melalui HTTP.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mencegah Serangan Replay & Modifikasi Nominal:

Karena timestamp dan seluruh nominal pinjaman di-hash ke dalam sign, penyerang tidak dapat mengubah nominal tagihan di proxy (misal mengubah repayAmount dari Rp 1.000.000 menjadi Rp 10.000) tanpa merusak nilai sign. Backend akan menolak request seketika dengan respon Sign Invalid.

  • Hanya Nilai Primitif yang Dihitung:

Baris 33–37 di sign_utils.dart membatasi tipe data ke String, double, int, dan bool. Objek nested seperti Map atau List diabaikan dalam pembentukan buffer untuk menghindari inkonsistensi representasi string JSON antara sistem operasi.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika backend memperbarui algoritma verifikasi tanda tangan dan mewajibkan kunci statis baru:

  • Host native mengirimkan staticKey di dalam dictionary getNativeRequestParams.
  • ParamUtils._defaultParamsByPlatform() menangkap staticKey tersebut pada baris 31–34 dan otomatis memperbarui Global.dynamicSignKey.
  • Flutter langsung menghasilkan tanda tangan yang valid tanpa memerlukan rilis update biner aplikasi.

⚠️ H. Common Mistakes & Debugging

  • Menyisipkan Nilai Null ke Parameter:
    • sign_utils.dart secara ketat melewati nilai null (if (value != null)). Jika backend mengharapkan string "null" literal, tanda tangan akan berbeda. Hindari mengirim field bernilai null ke endpoint bertanda tangan.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
