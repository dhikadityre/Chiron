Core Knowledge

Dokumentasi ini membedah arsitektur komunikasi jaringan HTTP/HTTPS di dalam modul SAMIR Flutter (flutter_app_project), menjelaskan implementasi singleton 🦊 flutter/lib/common/http/http_client.dart learn/Flutter-Arch ↗, konfigurasi interceptor, bypass sertifikat SSL, penanganan proxy IP dinamis, format amplop respon BaseResponse, serta penanganan kesalahan jaringan.

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memahami arsitektur singleton HttpClient berbasis pustaka Dio.
  2. Menjelaskan siklus kerja interceptor: HttpLogInterceptor dan LoadingInterceptor.
  3. Mengetahui cara kerja bypass sertifikat SSL (badCertificateCallback) dan injeksi proxy IP di non-PROD.
  4. Menjelaskan format struktur data BaseResponse dan bagaimana kode status HTTP dipetakan ke kode bisnis backend SAMIR.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan sebuah kantor pos diplomatik khusus:

  1. Surat Masuk: Setiap surat yang akan dikirim (API Request) otomatis diperiksa kelengkapan prangkonya dan distempel tanggal resmi oleh staf administrasi (LoadingInterceptor & ParamUtils).
  2. Buku Ekspedisi: Salinan surat dicatat di buku arsip kantor pos agar mudah dilacak jika terjadi masalah (HttpLogInterceptor).
  3. Jalur Terowongan Khusus: Surat dikirim melalui kurir bersepeda motor dengan izin khusus melewati pos pemeriksaan tanpa harus membuka koper diplomatiknya (Bypass SSL badCertificateCallback).
  4. Balasan Diterima: Ketika surat balasan tiba (BaseResponse), jika amplop berisi cap peringatan "Masa Berlaku Paspor Habis" (Error 10006), staf pos segera memberi tahu warga tersebut untuk memperbarui paspornya.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Inisialisasi Singleton HttpClient

File 🦊 flutter/lib/common/http/http_client.dart learn/Flutter-Arch ↗ (baris 17–60):

final HttpClient httpClient = HttpClient();

class HttpClient {
  HttpClient._internal() {
    init();
  }

  static final HttpClient _singleton = HttpClient._internal();
  factory HttpClient() => _singleton;

  late Dio _dio;
  Dio get dio => _dio;

  void init() {
    _dio = Dio(
      BaseOptions(
        baseUrl: AppEnv.apiBaseUrl,
        headers: <String, dynamic>{'language': 'id_ID'},
        connectTimeout: const Duration(seconds: 120),
        receiveTimeout: const Duration(seconds: 120),
        sendTimeout: const Duration(seconds: 120),
      ),
    );
    _dio.interceptors.add(HttpLogInterceptor());
    _dio.interceptors.add(LoadingInterceptor());

    dio.httpClientAdapter = IOHttpClientAdapter(
      createHttpClient: () {
        final io.HttpClient client = io.HttpClient();
        client.badCertificateCallback =
            (io.X509Certificate cert, String host, int port) => true;
        if (!AppEnv.isProd) {
          if (Global.proxyIp != null && Global.proxyIp!.isNotEmpty) {
            client.findProxy = (Uri uri) => 'PROXY ${Global.proxyIp}';
          }
        }
        return client;
      },
    );
  }
}

Fitur-fitur kritis pada konfigurasi:

  1. Bahasa Standar: Header default 'language': 'id_ID' memastikan seluruh pesan validasi error dikembalikan dalam Bahasa Indonesia oleh server backend.
  2. Timeout Panjang (120 Detik): Mencegah kegagalan prematur saat nasabah berada di daerah dengan koneksi sinyal seluler lemah (2G/3G di pedalaman).
  3. Bypass Sertifikat SSL (badCertificateCallback => true): Memungkinkan pengetesan API di staging environment yang menggunakan self-signed certificate atau tunneling internal tanpa error handshake SSL.
  4. Injeksi Proxy Dinamis: Mengaitkan socket HTTP Dart ke alamat IP proxy (Charles / Proxyman) yang diisi melalui ProxyDebugPage di environment non-PROD.

2. Pipeline Interceptor

  • LoadingInterceptor:

Memeriksa opsi options.extra[LoadingInterceptor.showLoadingKey]. Jika true (default), modal loading ditampilkan dan ditutup secara otomatis saat siklus request berakhir.

  • HttpLogInterceptor:

Mencetak tag log terstruktur [HTTP-REQ] dan [HTTP-RESP] di konsol debug untuk mempermudah analisis data oleh developer.

3. Struktur Amplop Respon: BaseResponse<T>

File 🦊 flutter/lib/common/http/response.dart learn/Flutter-Arch ↗ mendefinisikan format kontrak JSON backend SAMIR:

class BaseResponse<T> {
  BaseResponse({this.code, this.msg, this.data});

  final String? code;  // '200' = Sukses, '10006' = Token Expired, lainnya = Error Bisnis
  final String? msg;   // Pesan penjelasan dari backend
  final T? data;       // Payload data spesifik

  factory BaseResponse.fromJson(Map<String, dynamic>? json) {
    if (json == null) return BaseResponse<T>();
    return BaseResponse<T>(
      code: json['code']?.toString(),
      msg: json['msg']?.toString() ?? '',
      data: json['data'] as T?,
    );
  }
}

🪜 E. Step-by-Step Walkthrough: Alur Lengkap Eksekusi httpClient.post()

  1. Pemanggilan Method:

Service mengeksekusi httpClient.post(ServerApi.repayList, params: {'page': 1}).

  1. Penggabungan Parameter & Tanda Tangan:

Sebelum dikirim ke Dio, addDefaultParamsAndSign() menggabungkan parameter bawaan platform (clientId, timestamp, userNo) dan menghitung signature MD5 signParamMap().

  1. Loading Trigger:

LoadingInterceptor.onRequest memanggil Loading.show(). Layar pengguna diblokir dengan spinner transparan.

  1. Transport Jaringan:

Dio mengeksekusi POST ke https://domain-loansapp-test.samir.co.id/api/repayment/repayOrderList.

  1. Evaluasi Kode Status:
    • Jika HTTP Status 200 dan BaseResponse.code == '200', fungsi mengembalikan isi baseResponse.data.
    • Jika BaseResponse.code == '10006', sesi dibersihkan via Global.clearUser() dan layar login native dibuka.
    • Jika code != '200', pesan baseResponse.msg dimunculkan via showToast().
  2. Loading Dismissal:

LoadingInterceptor.onResponse memanggil Loading.hide().

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Menggunakan Timeout 120 Detik?

Sebagai aplikasi pinjaman online inklusi keuangan di Indonesia, sebagian besar nasabah berada di luar kota-kota besar dengan infrastruktur internet berfluktuasi tinggi. Timeout standar bawaan browser (15–30 detik) akan menghasilkan banyak Connection Timeout Error yang merugikan nasabah saat proses transfer pembayaran.

  • Mengapa Otomatis Menampilkan Toast Error di Client?

Alih-alih mewajibkan setiap fungsi Service atau Page menulis try-catch dan memanggil showToast(error) secara berulang di puluhan tempat, HttpClient._getResponse() menangani feedback visual secara terpusat, menjamin tidak ada error backend yang luput dari pemberitahuan pengguna.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika backend mengalami downtime dan mengembalikan status HTTP 502 Bad Gateway:

  • _createErrorResponse() menangkap DioExceptionType.badResponse.
  • Ia membungkus error menjadi BaseResponse(code: 'Network', msg: 'Http status error [502]').
  • Aplikasi tidak mengalami unhandled exception crash; Toast peringatan muncul dengan rapi di layar.

⚠️ H. Common Mistakes & Debugging

  • Lupa Menambahkan showLoading: false pada Panggilan Background:
    • Untuk polling status atau pemuatan data saat tab bar berpindah, selalu tentukan showLoading: false agar pengguna tidak terganggu oleh kedipan spinner modal yang muncul sekilas.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
