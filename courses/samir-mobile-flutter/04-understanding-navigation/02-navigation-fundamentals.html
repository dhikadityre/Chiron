Core Knowledge

Dokumentasi ini menjelaskan konfigurasi sistem navigasi deklaratif menggunakan GoRouter di dalam modul SAMIR Flutter (flutter_app_project), cara kerja kelas pembantu statis 🦊 flutter/lib/common/router/routers.dart learn/Flutter-Arch ↗, observer navigasi, serta perbedaan antara operasi go(), push(), replace(), dan pop().

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memahami arsitektur konfigurasi appRouter (instance singleton GoRouter).
  2. Menjelaskan mengapa Routers.go() dan Routers.push() selalu mengeksekusi NativeRouteChrome.prepareForLocation() terlebih dahulu.
  3. Membedakan perilaku perpindahan stack antara go() (deklaratif/reset stack) dan push() (imperatif/tumpukan baru).
  4. Mengetahui cara kerja Routers.pop() yang aman terhadap dialog dan loading overlay.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan sistem transportasi kereta cepat:

  • Routers.go('/root') seperti menaiki kereta ekspres yang langsung membawa Anda ke stasiun sentral: seluruh gerbong tambahan dilepas, dan Anda tiba di terminal utama yang luas.
  • Routers.push('/mine/personal') seperti memasuki gerbong khusus VIP: gerbong ini ditautkan di belakang rangkaian kereta saat ini, dan Anda dapat berjalan mundur kembali ke gerbong sebelumnya kapan saja (Routers.pop()).
  • NativeRouteChrome.prepareForLocation() adalah pengumuman stasiun sebelum pintu terbuka: memberi sinyal kepada petugas peron (host native) untuk menyiapkan tangga atau menutup pintu pembatas sebelum penumpang melangkah keluar.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Inisialisasi appRouter

Pada file 🦊 flutter/lib/common/router/routers.dart learn/Flutter-Arch ↗ (baris 19–48):

final GlobalKey<NavigatorState> navigatorKey = GlobalKey<NavigatorState>();

final GoRouter appRouter = GoRouter(
  navigatorKey: navigatorKey,
  initialLocation: _initialLocation,
  observers: <NavigatorObserver>[
    NativeRouteChrome.observer,
    pageLifecycleRouteObserver,
  ],
  routes: <RouteBase>[
    GoRoute(
      path: RoutePaths.rootContainer,
      pageBuilder: (BuildContext context, GoRouterState state) {
        return MaterialPage<void>(
          key: state.pageKey,
          name: RoutePaths.rootContainer,
          child: const FlutterRootPage(),
        );
      },
    ),
    GoRoute(
      path: RoutePaths.minePersonal,
      pageBuilder: (BuildContext context, GoRouterState state) {
        return MaterialPage<void>(
          key: state.pageKey,
          name: RoutePaths.minePersonal,
          child: const MinePersonalPage(),
        );
      },
    ),
  ],
);

Aspek-aspek kunci:

  1. navigatorKey: Kunci global yang memungkinkan pemanggilan navigasi atau Toast tanpa memerlukan BuildContext.
  2. Daftar Observers:
    • NativeRouteChrome.observer: Menangkap setiap event didPush, didPop, dan didReplace untuk menyinkronkan visibilitas Tab Bar native secara otomatis.
    • pageLifecycleRouteObserver: Menyalurkan event lifecycle route ke PageLifecycleMixin.

2. Kelas Pembantu Statis Routers

Untuk mencegah developer memanggil GoRouter.of(context) secara acak dengan risiko context tidak valid, tim SAMIR menyediakan kelas pembantu terpusat:

class Routers {
  Routers._();

  static Future<T?> push<T extends Object?>(String location, {Object? extra}) async {
    await NativeRouteChrome.prepareForLocation(location);
    return appRouter.push<T>(location, extra: extra);
  }

  static Future<T?> replace<T extends Object?>(String location, {Object? extra}) async {
    await NativeRouteChrome.prepareForLocation(location);
    return appRouter.pushReplacement<T>(location, extra: extra);
  }

  static Future<void> go(String location, {Object? extra}) async {
    await NativeRouteChrome.prepareForLocation(location);
    if (FlutterRootController.supports(location)) {
      FlutterRootController.select(location);
      if (currentLocation != RoutePaths.rootContainer) {
        appRouter.go(RoutePaths.rootContainer, extra: extra);
      }
      return;
    }
    appRouter.go(location, extra: extra);
  }

  static void pop<T extends Object?>([T? result]) {
    if (appRouter.canPop()) {
      appRouter.pop<T>(result);
    }
  }

  static String get currentLocation {
    return appRouter.routeInformationProvider.value.uri.path;
  }
}

📌 E. Perbandingan Metode Navigasi

MetodePerilaku Stack NavigasiKapan Digunakan di SAMIR
Routers.go(path)Mengganti seluruh tumpukan navigasi ke rute target. Jika path adalah /mine atau /repay, ia mengaktifkan tab di FlutterRootPage.Digunakan saat perpindahan antar-tab utama atau navigasi kembali ke root.
Routers.push(path)Menumpuk halaman baru di atas halaman saat ini. Menampilkan tombol kembali otomatis di NavTitleBar.Digunakan untuk membuka subhalaman detail (misal: /mine/personal).
Routers.replace(path)Menimpa rute paling atas saat ini dengan rute baru tanpa menambah kedalaman stack.Digunakan saat transisi alur satu arah (misal setelah submit form sukses).
Routers.pop([result])Mengeluarkan halaman paling atas dari stack GoRouter jika canPop() == true.Digunakan pada tombol kembali (NavTitleBar.onBack).

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Wajib await NativeRouteChrome.prepareForLocation(location) Sebelum Navigasi?

Animasi transisi halaman Flutter membutuhkan waktu sekitar 300 ms. Jika Flutter baru menyembunyikan Tab Bar native setelah animasi selesai, Tab Bar native akan terlihat melayang di bawah layar selama 300 ms dan kemudian menghilang tiba-tiba (visual glitch / jarring jump). Dengan menjalankan prepareForLocation terlebih dahulu secara asynchronous, native host menyembunyikan tab bar sebelum frame pertama transisi digambar.

  • Isolasi Routers.pop() Terhadap Dialog:

Pada Flutter standar, memanggil Navigator.pop() saat ada dialog terbuka akan menutup dialog tersebut alih-alih halaman. Karena dialog di SAMIR dikelola oleh AppDialogHost yang terpisah, Routers.pop() hanya menutup halaman bisnis, mencegah kesalahan penutupan modal yang tidak diinginkan.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Ketika pengguna menekan kartu "Kelengkapan Profil" di MineHomePage:

void _onPersonalAuthTap() {
  Routers.push(RoutePaths.minePersonal);
}

Urutan kejadian:

  1. prepareForLocation('/mine/personal') mengirimkan setNativeTabBarHidden(true) ke iOS host.
  2. Tab bar native langsung disembunyikan.
  3. Halaman MinePersonalPage meluncur mulus ke layar dengan tombol kembali di kiri atas.

⚠️ H. Common Mistakes & Debugging

  • Menggunakan Navigator.of(context).pushNamed(...):
    • Hindari menggunakan Navigator 1.0 langsung. Pemanggilan ini tidak akan memicu NativeRouteChrome.prepareForLocation, menyebabkan tab bar native tetap muncul menutupi bagian bawah layar.
  • Menggunakan Routers.go() Ketika Ingin Tombol Back Tampil:
    • Routers.go() membersihkan tumpukan halaman, sehingga appRouter.canPop() bernilai false dan tombol back di header tidak akan muncul. Gunakan Routers.push() jika halaman harus bisa di-pop kembali.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Tight Coupling pada Antarmuka Routing & Hardcoded String Paths

Navigasi antar layar dan pembukaan modal masih mengandalkan string URL scheme atau navigasi langsung controller-ke-controller, menyulitkan pelacakan dependensi dan memicu runtime crash jika parameter route tidak valid.

⚠️ Smells 2: Pencampuran Presentasi UI dengan Koordinasi Rute (Melanggar SRP)

ViewController atau Widget UI mengetahui secara langsung hierarki layar berikutnya dan cara menyajikannya (push vs present modal), mengurangi reusabilitas tampilan pada modul lain.

🚀 Blueprint Refactoring Standar Industri: Pola Navigation Coordinator & Typed Route Handlers

Mengabstraksikan seluruh orkestrasi layar ke dalam modul Coordinator independen. UI hanya memancarkan event intent navigasi tanpa mengetahui implementasi rute konkret.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class AppRouteCoordinator {
  void navigateTo(BuildContext context, String destination, {Map<String, dynamic>? args});
}

class StandardRepayCoordinator implements AppRouteCoordinator {
  @override
  void navigateTo(BuildContext context, String destination, {Map<String, dynamic>? args}) {
    Navigator.of(context).pushNamed(destination, arguments: args);
  }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
