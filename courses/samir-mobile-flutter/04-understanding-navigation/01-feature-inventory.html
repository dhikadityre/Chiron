📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menyediakan inventori lengkap dari seluruh fitur, halaman antarmuka (screens), dan dialog yang dibangun di dalam modul SAMIR Flutter (flutter_app_project), mencatat rute navigasi, status hosting, data input/output, serta perannya dalam siklus pinjaman fintech SAMIR.

Status Verifikasi: [Verified] (diverifikasi langsung dari kode routing 🦊 flutter/lib/common/router/route_paths.dart learn/Flutter-Arch ↗, 🦊 flutter/lib/common/router/routers.dart learn/Flutter-Arch ↗, dan direktori flutter/lib/pages/).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Mengidentifikasi seluruh halaman yang aktif di dalam modul Flutter SAMIR.
  2. Membedakan antara Root Tab Screens (di-host dalam IndexedStack) dan Secondary Pushed Screens.
  3. Menjelaskan fungsi bisnis dari masing-masing layar bagi nasabah pinjaman online SAMIR.
  4. Mengetahui layar khusus pengujian (debug tools) yang tersedia pada build non-PROD.

📋 B. Prerequisites

Telah membaca Level 1 hingga Level 3.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan denah sebuah gedung kantor pelayanan publik:

  • Lantai Utama (Root Container): Memiliki dua loket utama berdampingan yang selalu terbuka, yaitu Loket Pembayaran / Tagihan (Repay) dan Loket Layanan Akun Nasabah (Mine).
  • Ruang Dokumen Pribadi (Personal Auth): Terletak di belakang loket akun nasabah; nasabah dipersilakan masuk ke ruangan ini jika ingin memeriksa atau memperbarui kelengkapan dokumen KTP.
  • Pintu Rahasia Teknisi (Proxy Debug & Chucker): Panel tersembunyi di sudut ruangan yang hanya bisa dibuka oleh teknisi gedung untuk menginspeksi pipa saluran air dan kabel listrik (lalu lintas jaringan).

📌 E. Rincian Fungsional Masing-Masing Layar

1. `FlutterRootPage` (`/root`)

  • Fungsi: Wadah persisten tunggal yang menjaga state kedua tab native tetap hidup di memori.
  • Komponen Utama:
  • IndexedStack: Membungkus MineHomePage dan RepayHomePage.
  • AnnotatedRegion<SystemUiOverlayStyle>: Menjaga warna ikon status bar tetap kontras gelap (AppSystemUiStyle.onLightBackground).
  • PageLifecycleVisibility: Mendistribusikan visibilitas ke child yang sedang aktif.

2. `RepayHomePage` (`/repay`)

  • Fungsi: Pusat manajemen pelunasan pinjaman aktif nasabah.
  • Fitur Utama:
  • Ringkasan Tagihan: Total nominal jatuh tempo, tanggal tenggat pembayaran, dan status keterlambatan (denda).
  • Daftar Kontrak Pinjaman: Kartu perincian per transaksi (RepayOrderCard).
  • Kode Pembayaran / Virtual Account: Mengambil kode bayar dari endpoint queryAbroadDeDuctList untuk bank BCA, Mandiri, BRI, BNI, Permata, Alfamart, dan Indomaret.
  • Pop-up Insentif Pelunasan: Memicu requestRepayBenefitPopup('repay_home') ke host native untuk menampilkan diskon pelunasan tepat waktu.
  • Tautan Customer Support: Tombol pintas bantuan langsung ke tim penagihan.

3. `MineHomePage` (`/mine`)

  • Fungsi: Dasbor akun nasabah dan pusat pengaturan aplikasi.
  • Fitur Utama:
  • Header Nasabah: Avatar, nomor ponsel tersamarkan (0812****7890), status kredit, dan badge limit pinjaman.
  • Grid Menu Navigasi:
  • Riwayat Pinjaman (/samir/loan-record via WebView/Native).
  • Daftar Kupon Promo (/samir/coupon/list).
  • Peningkatan Limit Kredit (/samir/credit-enhancement).
  • Kelengkapan Dokumen KYC (samir://mine/infoAuthList).
  • Pusat Bantuan FAQ (/samir/faq).
  • Tentang Kami (samir://mine/aboutUs).
  • Pengaturan Privasi & Akun (samir://mine/setting).
  • Hubungi Layanan Pelanggan (customerAction).
  • Lencana Pesan (Badge): Menampilkan titik merah jika ada notifikasi baru dari msg/queryCount.
  • Kanal Media Sosial: Seksi resmi Instagram, Facebook, dan WhatsApp di bagian bawah halaman.

4. `MinePersonalPage` (`/mine/personal`)

  • Fungsi: Menampilkan daftar rincian verifikasi data nasabah (e-KTP, informasi pekerjaan, kontak darurat, rekening bank).
  • Karakteristik Navigasi: Ketika halaman ini dibuka, NativeRouteChrome otomatis menyembunyikan Tab Bar native agar layar terasa luas dan fokus.

5. `ProxyDebugPage`

  • Fungsi: Sarana pengetesan jaringan untuk tim QA dan developer di environment non-PROD (Dev & Test).
  • Fitur: Memasukkan IP dan port proxy lokal (misal 192.168.1.10:8888) untuk menghubungkan koneksi Dio Flutter ke Charles Proxy atau Proxyman tanpa perlu root certificate manual di OS.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Inventori Terbatas Menjamin Kecepatan:

Modul Flutter SAMIR sengaja difokuskan hanya pada modul Tagihan dan Akun Nasabah, sementara modul Pengajuan Pinjaman (Loan Application) dan Kamera KYC tetap di Native. Strategi ini meminimalkan ukuran biner framework Flutter sambil memaksimalkan portabilitas logika penagihan di kedua platform.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika nasabah belum login dan membuka Tab Tagihan:

  1. RepayHomePage mendeteksi isLogin == false.
  2. Widget merender RepayEmptyState dengan tombol besar "Masuk / Daftar".
  3. Ketika tombol ditekan, Flutter memanggil FlutterNativeChannelRoute.openNativeRoute('repayLoginAction') untuk membuka form login OTP di modul Native Swift.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Tight Coupling pada Antarmuka Routing & Hardcoded String Paths

Navigasi antar layar dan pembukaan modal masih mengandalkan string URL scheme atau navigasi langsung controller-ke-controller, menyulitkan pelacakan dependensi dan memicu runtime crash jika parameter route tidak valid.

⚠️ Smells 2: Pencampuran Presentasi UI dengan Koordinasi Rute (Melanggar SRP)

ViewController atau Widget UI mengetahui secara langsung hierarki layar berikutnya dan cara menyajikannya (push vs present modal), mengurangi reusabilitas tampilan pada modul lain.

🚀 Blueprint Refactoring Standar Industri: Pola Navigation Coordinator & Typed Route Handlers

Mengabstraksikan seluruh orkestrasi layar ke dalam modul Coordinator independen. UI hanya memancarkan event intent navigasi tanpa mengetahui implementasi rute konkret.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class AppRouteCoordinator {
  void navigateTo(BuildContext context, String destination, {Map<String, dynamic>? args});
}

class StandardRepayCoordinator implements AppRouteCoordinator {
  @override
  void navigateTo(BuildContext context, String destination, {Map<String, dynamic>? args}) {
    Navigator.of(context).pushNamed(destination, arguments: args);
  }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:

Kuis 1 (Memory Recall): Apa bahaya utama dari menggunakan hardcoded URL scheme string di seluruh navigasi layar?

Kuis 2 (Architectural Decision): Bagaimana pola Coordinator membantu memisahkan tanggung jawab (SRP) pada ViewController atau Widget?

Kuis 3 (Debugging & Maintenance): Apa yang harus dilakukan saat deep link masuk saat otentikasi pengguna belum selesai diverifikasi?
