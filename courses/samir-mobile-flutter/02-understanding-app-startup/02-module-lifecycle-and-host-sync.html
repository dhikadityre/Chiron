02 — Module Lifecycle & Host Sync

Manajemen Siklus Hidup & Sinyal Host

📚 Modul: 02-module-lifecycle-and-host-sync 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menjelaskan bagaimana modul SAMIR Flutter memantau perubahan status siklus hidup aplikasi (App Lifecycle) dari host native, mengelola visibilitas halaman di dalam tumpukan widget (PageLifecycleMixin dan PageLifecycleVisibility), serta merespons sinyal refresh instan (refreshMineHome dan refreshRepayHome) yang dikirimkan oleh sistem host iOS/Android.

Status Verifikasi: [Verified] (diverifikasi langsung dari 🦊 flutter/lib/common/lifecycle/page_lifecycle.dart learn/Flutter-Arch ↗, 🦊 flutter/lib/common/platform/flutter_native_page_signal.dart learn/Flutter-Arch ↗, dan 🦊 flutter/lib/pages/root/flutter_root_page.dart learn/Flutter-Arch ↗).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memahami perbedaan antara OS App Lifecycle (AppLifecycleState) dan Page Lifecycle di Flutter Add-to-App.
  2. Menjelaskan mengapa IndexedStack membutuhkan pembungkus PageLifecycleVisibility dan TickerMode.
  3. Memahami peran PageLifecycleMixin dalam menghentikan/melanjutkan timer, animasi, dan pelacakan analytics saat pengguna berpindah tab.
  4. Menelusuri bagaimana sinyal refresh dari native (refreshMineHome dan refreshRepayHome) diterima dan didistribusikan ke State widget.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan sebuah panggung teater dengan dua set dekorasi yang sudah terpasang berdampingan: Set A (Tagihan) dan Set B (Profil):

  • Lampu sorot hanya menyala di satu set pada satu waktu.
  • Ketika sutradara mematikan lampu di Set A dan menyalakan lampu di Set B, para aktor di Set A harus berhenti bernyanyi dan menari (TickerMode(enabled: false)) agar tidak membuang tenaga, meskipun mereka tetap berdiri di panggung (IndexedStack).
  • Jika kantor pusat menelepon: "Ada surat tagihan baru masuk!" (refreshRepayHome), staf di balik panggung segera memperbarui papan informasi Set A, sehingga ketika lampu sorot kembali menyala, data langsung tampil mutakhir.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Masalah Bawaan `IndexedStack` dan Solusi `PageLifecycleVisibility`

Dalam framework Flutter standar, widget IndexedStack menjaga seluruh child-nya tetap di-mount di element tree. Konsekuensinya:

  • Child yang tidak aktif tidak menerima event dispose() atau initState().
  • Jika child memiliki animasi berputar atau timer, kalkulasi akan terus membebani CPU di background.

Untuk mengatasi ini, SAMIR Flutter menerapkan kombinasi arsitektur di 🦊 flutter/lib/pages/root/flutter_root_page.dart learn/Flutter-Arch ↗ (baris 59–65):

children: List<Widget>.generate(_pages.length, (int index) {
  final bool visible = index == selectedIndex;
  return PageLifecycleVisibility(
    visible: visible,
    child: TickerMode(enabled: visible, child: _pages[index]),
  );
}, growable: false),
  1. TickerMode(enabled: visible): Mematikan seluruh controller animasi (AnimationController, Lottie) ketika tab sedang tidak aktif, menghemat daya baterai dan penggunaan GPU.
  2. PageLifecycleVisibility(visible: visible): Mendistribusikan status visible ke bawah widget tree sehingga State yang menggunakan PageLifecycleMixin tahu kapan harus memulai atau menghentikan refresh data.

2. Kelas `PageLifecycleMixin`

File 🦊 flutter/lib/common/lifecycle/page_lifecycle.dart learn/Flutter-Arch ↗ menyediakan mixin untuk State widget:

mixin PageLifecycleMixin<T extends StatefulWidget> on State<T> {
  bool _isPageVisible = false;
  bool get isPageVisible => _isPageVisible;

  @protected
  void onPageVisible() {}

  @protected
  void onPageInvisible() {}
}

Halaman utama seperti MineHomePage dan RepayHomePage mengimplementasikan mixin ini:

  • Ketika tab dipilih, onPageVisible() dipicu otomatis.
  • Halaman memicu TrackPageViewMixin untuk mengirimkan log analytics page view (me untuk Mine, repayment untuk Repay) ke host native.

3. Sinyal Refresh dari Host Native (`FlutterNativePageSignal`)

File 🦊 flutter/lib/common/platform/flutter_native_page_signal.dart learn/Flutter-Arch ↗ menyediakan mekanisme event stream tanpa dependensi yang rumit:

class FlutterNativePageSignal {
  FlutterNativePageSignal._();

  static final StreamController<void> _mineHomeRefreshController =
      StreamController<void>.broadcast();
  static final StreamController<void> _repayHomeRefreshController =
      StreamController<void>.broadcast();

  static Stream<void> get onMineHomeRefresh =>
      _mineHomeRefreshController.stream;
  static Stream<void> get onRepayHomeRefresh =>
      _repayHomeRefreshController.stream;

  static void refreshMineHome() {
    _mineHomeRefreshController.add(null);
  }

  static void refreshRepayHome() {
    _repayHomeRefreshController.add(null);
  }
}

Ketika native host memanggil method channel:

  1. FlutterNativeRouteDispatcher._handleNativeCall menerima method refreshMineHome atau refreshRepayHome.
  2. Dispatcher memanggil FlutterNativePageSignal.refreshMineHome().
  3. MineHomePage yang berlangganan pada initState() langsung memicu fungsi pengambilan data terbaru (_loadData()).

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Menggunakan Broadcast Stream Controller Alih-Alih Callback Statis?

Broadcast Stream memungkinkan banyak listener berlangganan secara serentak (misal halaman utama dan floating badge notifikasi) tanpa menciptakan keterikatan ketat (tight coupling) antar class.

  • Sinkronisasi Lifecycle Saat Kembali dari Background:

Kelas _NativeRouteLifecycleObserver di 🦊 flutter_native_route_dispatcher.dart learn/Flutter-Arch ↗ memantau AppLifecycleState.resumed. Saat aplikasi kembali ke foreground, ia memicu NativeRouteChrome.syncForCurrentRoute() untuk memastikan status tab bar host native tetap selaras dan tidak tertutup.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika pengguna berpindah dari Tab 0 (Beranda Native) ke Tab 1 (Tagihan Flutter):

  1. Native host mendeteksi klik tab dan memanggil showFlutterRoute('/repay').
  2. FlutterNativeRouteDispatcher mengubah index IndexedStack menjadi 1.
  3. PageLifecycleVisibility mendeteksi perubahan menjadi visible: true.
  4. TickerMode diaktifkan, dan RepayHomePage.onPageVisible() dipicu untuk merefresh perhitungan timer jatuh tempo secara real-time.

⚠️ H. Common Mistakes & Debugging

  • Lupa Melakukan cancel() pada StreamSubscription di dispose():
  • Jika listener FlutterNativePageSignal.onMineHomeRefresh tidak dibatalkan saat widget di-dispose, memory leak akan terjadi dan callback dapat dipicu pada widget yang sudah unmounted (setState() called after dispose()).
  • Menjalankan Animasi Tanpa Memeriksa TickerMode:
  • Menggunakan loop manual Future.delayed alih-alih AnimationController akan mengabaikan TickerMode, sehingga proses background tetap memakan baterai meskipun pengguna sedang berada di tab native.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Pelanggaran SRP: God Object Coordinator pada Alur Startup

Class modul startup utama pada SAMIR Mobile Flutter menangani terlalu banyak tanggung jawab: registrasi APM, inisialisasi jaringan, pemanasan runtime engine, serta registrasi push notifications secara monolitik.

⚠️ Smells 2: Pelanggaran DIP: Keterikatan Statis Singleton (0% Unit Testability)

Komponen memanggil static shared singleton secara langsung tanpa melalui abstraksi antarmuka (Dependency Inversion Principle), membuat pengujian terisolasi di automated unit test menjadi mustahil tanpa memicu efek samping jaringan dan APM produksi.

🚀 Blueprint Refactoring Standar Industri: Penerapan Composite Startup Task Architecture

Memecah alur peluncuran aplikasi menjadi serangkaian task mandiri yang mengimplementasikan protokol tunggal (Open/Closed Principle) dan dapat dieksekusi secara terkoordinasi (sync/async).

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class AppStartupTask {
  String get identifier;
  Future<void> execute();
}

class StartupTaskCoordinator {
  final List<AppStartupTask> tasks;
  StartupTaskCoordinator(this.tasks);

  Future<void> runAll() async {
    for (final task in tasks) {
      await task.execute();
    }
  }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
