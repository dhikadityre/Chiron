💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan Anda membuka sebuah restoran siap saji di dalam stasiun kereta:

  1. Langkah 1: Anda menyalakan listrik dan mengecek daftar menu dari kantor pusat (Global.init()).
  2. Langkah 2: Anda menyalakan mesin kasir dan kompor (httpClient.init()).
  3. Langkah 3: Anda menyalakan saluran radio komunikasi dengan pengelola stasiun kereta (FlutterNativeRouteDispatcher.setup()).
  4. Langkah 4: Anda membuka pintu gerai dan menata meja (runApp(const MyApp())).
  5. Langkah 5: Begitu semua hidangan tertata rapi di etalase (endOfFrame), Anda menekan tombol lampu hijau di dinding untuk memberi tahu kepala stasiun: "Gerai siap melayani penumpang!" (notifyNativeReady()).

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Bedah Fungsi `main()`

Fungsi main() di 🦊 flutter/lib/main.dart learn/Flutter-Arch ↗ (baris 11–19):

Future<void> main() async {
  await Global.init();
  // Rebuild Dio after Global is ready so headers include fields such as appVersion.
  httpClient.init();
  FlutterNativeRouteDispatcher.setup();
  runApp(const MyApp());
  await WidgetsBinding.instance.endOfFrame;
  await FlutterNativeRouteDispatcher.notifyNativeReady();
}

Urutan 5 langkah eksekusi:

LangkahPemanggilan KodeTujuan Teknis
1await Global.init()Menginisialisasi WidgetsFlutterBinding.ensureInitialized() dan mengambil konfigurasi environment dari host via MethodChannel getNativeAppEnv.
2httpClient.init()Menginisialisasi instance singleton Dio dengan baseUrl yang telah ditentukan dari step 1, serta memasang interceptor loading & log.
3FlutterNativeRouteDispatcher.setup()Memasang listener FlutterNativeChannel.commonChannel.setMethodCallHandler untuk menerima pesan routing dari native (showFlutterRoute, refresh signals).
4runApp(const MyApp())Memulai rendering tree widget Flutter di bawah kendali MaterialApp.router.
5await endOfFrame & notifyNativeReady()Menunggu GPU dan engine Flutter selesai merender frame visual pertama, lalu memanggil method channel flutterReady ke host native.

2. Bedah Widget `MyApp`

Widget MyApp di 🦊 flutter/lib/main.dart learn/Flutter-Arch ↗ (baris 21–50) bertindak sebagai root aplikasi:

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  static final AppBackButtonDispatcher _backButtonDispatcher =
      AppBackButtonDispatcher();

  @override
  Widget build(BuildContext context) {
    final ThemeData theme = FontUtils.applyToTheme(
      ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
        fontFamily: FontUtils.lato,
      ),
    );

    return MaterialApp.router(
      title: 'Flutter Demo',
      routeInformationProvider: appRouter.routeInformationProvider,
      routeInformationParser: appRouter.routeInformationParser,
      routerDelegate: appRouter.routerDelegate,
      backButtonDispatcher: _backButtonDispatcher,
      theme: theme,
      builder: (BuildContext context, Widget? child) {
        return AppLoadingOverlay(
          child: AppDialogHost(child: child ?? const SizedBox.shrink()),
        );
      },
    );
  }
}

Fitur-fitur kritis pada MyApp:

  1. Font Standar: Menggunakan keluarga font Lato melalui utilitas FontUtils.applyToTheme().
  2. GoRouter Integration: Menggunakan MaterialApp.router yang didelegasikan ke instance singleton appRouter.
  3. Custom Back Button: Menggunakan AppBackButtonDispatcher untuk menangani tombol back fisik (khusus Android atau gesture navigasi).
  4. Lapisan Overlay Global:
  • AppDialogHost: Mengelola tampilan dialog konfirmasi bisnis tanpa mengganggu router utama.
  • AppLoadingOverlay: Menampilkan spinner loading modal transparan saat request jaringan berlangsung.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Wajib Menunggu endOfFrame Sebelum Memanggil flutterReady?

Jika native host langsung menampilkan tampilan Flutter sebelum frame pertama selesai digambar oleh Skia/Impeller, pengguna akan melihat layar hitam atau putih sesaat (blank frame flicker). Dengan menunggu WidgetsBinding.instance.endOfFrame, Flutter menjamin bahwa visual UI sudah siap 100% sebelum host melepaskan splash screen native.

  • Mengapa httpClient.init() Dijalankan Ulang di main()?

Meskipun HttpClient memiliki singleton constructor yang memanggil init(), header default seperti appId dan appVersion baru terisi setelah Global.init() selesai membaca data dari native. Memanggil ulang httpClient.init() memastikan seluruh request HTTP membawa identitas tenant yang valid.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika host iOS memanggil method showFlutterRoute saat aplikasi baru saja dibuka:

  • FlutterNativeRouteDispatcher.setup() sudah dipanggil di baris 15 main.dart, sebelum runApp().
  • Artinya, listener method channel sudah aktif dan siap menerima rute dari native bahkan sebelum frame UI pertama selesai digambar, mencegah terbuangnya event routing yang dikirim oleh host.

⚠️ H. Common Mistakes & Debugging

  • Memanggil Panggilan Jaringan Sebelum Global.init() Selesai:
  • Request akan dikirimkan tanpa parameter appId atau dengan baseUrl default yang salah (mengarah ke domain test secara tidak sengaja).
  • Menghilangkan await WidgetsBinding.instance.endOfFrame:
  • Dapat memicu keluhan QA mengenai kedipan layar putih (white flash) saat pengguna pertama kali berpindah ke Tab Tagihan.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Pelanggaran SRP: God Object Coordinator pada Alur Startup

Class modul startup utama pada SAMIR Mobile Flutter menangani terlalu banyak tanggung jawab: registrasi APM, inisialisasi jaringan, pemanasan runtime engine, serta registrasi push notifications secara monolitik.

⚠️ Smells 2: Pelanggaran DIP: Keterikatan Statis Singleton (0% Unit Testability)

Komponen memanggil static shared singleton secara langsung tanpa melalui abstraksi antarmuka (Dependency Inversion Principle), membuat pengujian terisolasi di automated unit test menjadi mustahil tanpa memicu efek samping jaringan dan APM produksi.

🚀 Blueprint Refactoring Standar Industri: Penerapan Composite Startup Task Architecture

Memecah alur peluncuran aplikasi menjadi serangkaian task mandiri yang mengimplementasikan protokol tunggal (Open/Closed Principle) dan dapat dieksekusi secara terkoordinasi (sync/async).

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class AppStartupTask {
  String get identifier;
  Future<void> execute();
}

class StartupTaskCoordinator {
  final List<AppStartupTask> tasks;
  StartupTaskCoordinator(this.tasks);

  Future<void> runAll() async {
    for (final task in tasks) {
      await task.execute();
    }
  }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
