💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Bedah `FlutterRootController`

File 🦊 flutter/lib/common/router/flutter_root_controller.dart learn/Flutter-Arch ↗ bertindak sebagai State Store reaktif murni tanpa dependensi eksternal:

abstract final class FlutterRootController {
  FlutterRootController._();

  static final ValueNotifier<String?> selectedPath = ValueNotifier<String?>(null);

  static bool supports(String? location) {
    return RootRoutes.isTabRoot(location);
  }

  static bool isSelected(String location) {
    return selectedPath.value == RootRoutes.normalize(location);
  }

  static void select(String location) {
    final String path = RootRoutes.normalize(location);
    if (!supports(path) || selectedPath.value == path) {
      return;
    }
    selectedPath.value = path;
  }
}

Karakteristik penting:

  • Menggunakan ValueNotifier<String?>: Ringan dan efisien, hanya memicu update pada listener yang terdaftar tanpa perlu rebuild global.
  • supports(location): Memvalidasi apakah path rute adalah rute root yang didukung (/mine atau /repay).
  • Idempoten: Jika path yang dipilih sama dengan path saat ini (selectedPath.value == path), notifikasi diabaikan untuk mencegah siklus render sia-sia.

2. Bedah `FlutterRootPage`

File 🦊 flutter/lib/pages/root/flutter_root_page.dart learn/Flutter-Arch ↗:

class FlutterRootPage extends StatefulWidget {
  const FlutterRootPage({super.key});

  @override
  State<FlutterRootPage> createState() => _FlutterRootPageState();
}

class _FlutterRootPageState extends State<FlutterRootPage> {
  static const List<String> _paths = <String>[
    RoutePaths.mineHome,
    RoutePaths.repayHome,
  ];

  late final List<Widget> _pages = const <Widget>[
    MineHomePage(),
    RepayHomePage(),
  ];

  @override
  void initState() {
    super.initState();
    FlutterRootController.selectedPath.addListener(_handleSelectionChanged);
  }

  @override
  void dispose() {
    FlutterRootController.selectedPath.removeListener(_handleSelectionChanged);
    super.dispose();
  }

  void _handleSelectionChanged() {
    if (mounted) {
      setState(() {});
    }
  }

  @override
  Widget build(BuildContext context) {
    final String? selectedPath = FlutterRootController.selectedPath.value;
    final int selectedIndex = selectedPath == null
        ? -1
        : _paths.indexOf(selectedPath);

    return AnnotatedRegion<SystemUiOverlayStyle>(
      value: AppSystemUiStyle.onLightBackground,
      child: IndexedStack(
        index: selectedIndex < 0 ? null : selectedIndex,
        sizing: StackFit.expand,
        children: List<Widget>.generate(_pages.length, (int index) {
          final bool visible = index == selectedIndex;
          return PageLifecycleVisibility(
            visible: visible,
            child: TickerMode(enabled: visible, child: _pages[index]),
          );
        }, growable: false),
      ),
    );
  }
}

🪜 E. Step-by-Step Walkthrough: Alur Pergantian Tab (Switching Flow)

  1. User Mengetuk Tab Tagihan di Host iOS:

IDMainTabBarController native mendeteksi perpindahan ke index 1 (Tagihan).

  1. Native Memanggil Channel:

Host mengirimkan pesan method channel showFlutterRoute dengan payload {"route": "/repay"}.

  1. Routers Mengarahkan:

FlutterNativeRouteDispatcher memanggil Routers.go('/repay').

  1. Controller Memperbarui State:

Routers.go mendeteksi bahwa /repay didukung oleh FlutterRootController, lalu memanggil FlutterRootController.select('/repay').

  1. Listener FlutterRootPage Terpicu:

Fungsi _handleSelectionChanged() menerima notifikasi nilai baru, lalu memanggil setState().

  1. Pergantian Indeks Visual:

Nilai selectedIndex berubah dari 0 ke 1. IndexedStack seketika memunculkan RepayHomePage() di layar.

  1. Lifecycle & Ticker Update:
  • MineHomePage (Index 0): visible = false, TickerMode dimatikan.
  • RepayHomePage (Index 1): visible = true, TickerMode diaktifkan, dan event onPageVisible() dipicu.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Menghilangkan Tab Switching Latency:

Jika Flutter menghancurkan (destroy) widget halaman setiap kali pengguna berpindah tab, pengguna akan mengalami jeda pemuatan (loading skeleton) dan scrolling position akan reset ke paling atas. IndexedStack mempertahankan state form dan posisi scroll secara utuh di memori.

  • Konsistensi Status Bar dengan AnnotatedRegion:

Aplikasi SAMIR menggunakan tema antarmuka terang (light background). Pembungkus AnnotatedRegion<SystemUiOverlayStyle>(value: AppSystemUiStyle.onLightBackground) memastikan ikon status bar (jam, baterai, wifi) selalu berwarna hitam legam di perangkat iOS dan Android, menghindari teks status bar menjadi putih tak terbaca di atas latar belakang terang.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Pengguna sedang mengisi form bantuan di halaman profil (Mine), lalu berpindah ke tab Tagihan untuk memeriksa tanggal jatuh tempo, dan kemudian kembali ke tab profil:

  • Berkat IndexedStack, seluruh teks yang sudah diketik di form halaman Mine tidak hilang.
  • Pengguna dapat melanjutkan pengetikan tanpa frustrasi.

⚠️ H. Common Mistakes & Debugging

  • Lupa Melepas Listener pada dispose():
  • FlutterRootController.selectedPath.removeListener(_handleSelectionChanged) wajib dipanggil di fungsi dispose() untuk mencegah memory leak.
  • Memberikan Index Negatif ke IndexedStack:
  • Pada baris 57: index: selectedIndex < 0 ? null : selectedIndex. Jika selectedPath belum terdefinisi saat booting awal, memberikan null akan membuat IndexedStack tidak menampilkan child manapun daripada memicu runtime RangeError.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Pelanggaran SRP: God Object Coordinator pada Alur Startup

Class modul startup utama pada SAMIR Mobile Flutter menangani terlalu banyak tanggung jawab: registrasi APM, inisialisasi jaringan, pemanasan runtime engine, serta registrasi push notifications secara monolitik.

⚠️ Smells 2: Pelanggaran DIP: Keterikatan Statis Singleton (0% Unit Testability)

Komponen memanggil static shared singleton secara langsung tanpa melalui abstraksi antarmuka (Dependency Inversion Principle), membuat pengujian terisolasi di automated unit test menjadi mustahil tanpa memicu efek samping jaringan dan APM produksi.

🚀 Blueprint Refactoring Standar Industri: Penerapan Composite Startup Task Architecture

Memecah alur peluncuran aplikasi menjadi serangkaian task mandiri yang mengimplementasikan protokol tunggal (Open/Closed Principle) dan dapat dieksekusi secara terkoordinasi (sync/async).

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class AppStartupTask {
  String get identifier;
  Future<void> execute();
}

class StartupTaskCoordinator {
  final List<AppStartupTask> tasks;
  StartupTaskCoordinator(this.tasks);

  Future<void> runAll() async {
    for (final task in tasks) {
      await task.execute();
    }
  }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
