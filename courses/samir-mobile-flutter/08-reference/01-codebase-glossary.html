Core Knowledge

Dokumentasi ini menyediakan kamus istilah resmi (canonical glossary) yang memuat definisi terminologi teknis, akronim arsitektur, parameter otentikasi, serta istilah domain bisnis finansial P2P lending yang digunakan di dalam modul SAMIR Flutter (flutter_app_project).

Status Verifikasi: [Verified] (diverifikasi langsung dari kode sumber aktif dan kontrak API).

📌 A. Terminologi Arsitektur Mobile & Add-to-App

**Add-to-App**

Pola integrasi di mana framework Flutter tidak menguasai seluruh siklus hidup aplikasi (greenfield), melainkan disematkan sebagai modul library ke dalam aplikasi host native iOS (IDSamirLoan) dan Android yang sudah ada.

**Single-Engine Architecture**

Pola desain di mana hanya satu instance FlutterEngine yang dibuat dan disimpan di memori host native (FlutterEngineManager). Engine tunggal ini digunakan secara bersama oleh Tab Tagihan (Repay) dan Tab Saya (Mine) untuk menghemat RAM dan menjaga status otentikasi tetap sinkron.

**Prewarming**

Proses menjalankan engine Flutter di latar belakang (run(withEntrypoint: nil)) sesaat setelah aplikasi native dibuka (didFinishLaunchingWithOptions), jauh sebelum pengguna membuka tab Flutter. Prewarming mengeliminasi waktu tunggu inisialisasi Dart VM sehingga tampilan Flutter terbuka secara instan.

**IndexedStack**

Widget bawaan Flutter yang menampung daftar tumpukan widget (children), di mana hanya satu widget yang terlihat pada satu waktu berdasarkan index. Widget lain yang tidak aktif tetap dipertahankan di memori element tree, menjaga form input dan posisi scroll tidak hilang saat berpindah tab.

**Native Route Chrome**

Mekanisme koordinasi tampilan di mana modul Flutter memerintahkan host native untuk menyembunyikan atau menampilkan elemen antarmuka luar (khususnya UITabBar bawah) sebelum animasi navigasi dimulai via NativeRouteChrome.prepareForLocation().

**MethodChannel**

Pipa komunikasi asynchronous dua arah antara Dart dan kode native (Swift / Kotlin) berbasis binary message encoding. Di SAMIR, terdapat dua kanal resmi: samir_native_channel dan samir_tracking_channel.

📌 B. Terminologi Sesi, Keamanan, & Jaringan

**`mid` (Member ID)**

Token otentikasi sesi utama pengguna yang dikembalikan oleh backend saat login berhasil. Bersifat rahasia dan wajib disertakan di setiap request HTTP yang membutuhkan otorisasi.

**`userNo`**

Nomor identitas unik nasabah di dalam sistem core banking SAMIR (contoh format: U20261022001). Digunakan untuk mengaitkan kontrak pinjaman, rekening bank, dan skor kredit.

**`custId`**

Customer ID nasabah yang digunakan pada integrasi CRM dan sistem penagihan eksternal.

**`dynamicSignKey`**

Kunci enkripsi dinamis yang diterbitkan oleh backend atau host native per sesi login untuk menghitung tanda tangan parameter request (sign).

**`Two-Pass MD5 Signature`**

Mekanisme verifikasi integritas data request di mana parameter diurutkan secara alfabetis (SplayTreeMap), digabungkan dengan kunci rahasia, di-hash dengan MD5 tahap 1, lalu digabungkan kembali dengan salt kedua (qwer1234_Samir) dan di-hash dengan MD5 tahap 2.

**Error Code `10006`**

Kode respon bisnis standar backend SAMIR yang menandakan bahwa token sesi telah kedaluwarsa (Token Expired) atau sesi telah diambil alih oleh perangkat lain. Memicu pembersihan sesi otomatis via Global.clearUser() dan pembukaan layar login native.

📌 C. Terminologi Bisnis Pinjaman P2P Lending

**Repay / Repayment**

Proses pelunasan pinjaman oleh nasabah penerima dana (borrower), mencakup pengembalian pokok pinjaman, bunga berjalan, dan denda keterlambatan jika ada.

**Virtual Account (VA)**

Nomor rekening bank virtual sementara yang dialokasikan khusus untuk satu nasabah per transaksi pinjaman (BCA, Mandiri, BRI, BNI, Permata) yang memungkinkan verifikasi pelunasan secara otomatis dan real-time.

**Deductor Code (Kode Potong / Kode Bayar)**

Kode transaksi pembayaran khusus yang dapat ditunjukkan nasabah ke kasir gerai ritel minimarket (Alfamart atau Indomaret) untuk melunasi tagihan pinjaman secara tunai.

**Overdue Days**

Jumlah hari keterlambatan pembayaran dihitung sejak tanggal jatuh tempo (due date) terlewati. Memicu kalkulasi akumulasi denda harian pada model RepayOrderModel.

**e-KYC (Know Your Customer)**

Proses verifikasi identitas nasabah secara elektronik yang mencakup pengenalan karakter optik e-KTP (OCR), pengisian informasi pekerjaan, dan deteksi keaslian wajah (Liveness Detection).

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
