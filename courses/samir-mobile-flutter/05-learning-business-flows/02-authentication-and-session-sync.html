02 — Authentication & Session Sync

Sinkronisasi Sesi & Otentikasi

📚 Modul: 02-authentication-and-session-sync 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menjelaskan arsitektur sinkronisasi sesi otentikasi antara aplikasi host native iOS/Android dan modul SAMIR Flutter (flutter_app_project), cara kerja pengambilan data sesi melalui method channel getRootPageData, pengelolaan status login di memori (Global), serta penanganan otomatis token kedaluwarsa (Token Expiration) saat backend mengembalikan kode error 10006.

Status Verifikasi: [Verified] (diverifikasi langsung dari inspeksi kode 🦊 flutter/lib/common/global.dart learn/Flutter-Arch ↗, 🦊 flutter/lib/common/platform/flutter_native_channel_method.dart learn/Flutter-Arch ↗, dan 🦊 flutter/lib/common/http/http_client.dart learn/Flutter-Arch ↗).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Menjelaskan mengapa modul Flutter tidak menyimpan token login di local storage permanen (SharedPreferences/SQLite).
  2. Menelusuri mekanisme method channel getRootPageData dalam menghidrasi state Global.
  3. Memahami 5 atribut kredensial pengguna di Global: mid, userNo, custId, dynamicSignKey, dan isLogin.
  4. Menjelaskan rantai eksekusi pembersihan sesi otomatis saat API mengembalikan error bisnis 10006.

📋 B. Prerequisites

Telah membaca 01-user-journey-overview.md dan Level 3: Arsitektur Hybrid.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan sebuah gelang akses masuk kamar hotel pintar:

  • Kunci Induk Fisik (Native Host): Disimpan aman di dalam brankas resepsionis hotel (iOS Keychain).
  • Gelang Digital Tamu (Flutter Module): Ketika tamu masuk ke restoran hotel (Modul Flutter), resepsionis hotel memprogram gelang digital tamu dengan kode kamar dan nama tamu melalui pemindai nirkabel (getRootPageData).
  • Gelang tersebut tidak menyimpan kunci permanen; jika tamu melepas gelang atau keluar hotel, memori gelang kosong seketika.
  • Jika kasir restoran mendeteksi bahwa masa sewa kamar tamu telah habis (Error 10006), kasir langsung menyetel ulang gelang menjadi kosong (Global.clearUser()) dan mengarahkan tamu kembali ke meja resepsionis untuk check-in ulang (Routers.gotoLogin()).

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. In-Memory Session Store: `Global`

File 🦊 flutter/lib/common/global.dart learn/Flutter-Arch ↗ mengelola sesi pengguna selama runtime proses Flutter:

class Global {
  static String appId = '';
  static String appName = 'Samir';
  static String packageName = 'com.samir.loan';
  static String appVersion = '1.3.5';

  static String? mid;              // Member ID / Token otentikasi sesi
  static String? userNo;           // Nomor identifikasi unik nasabah di sistem
  static String? dynamicSignKey;   // Kunci dinamis untuk tanda tangan request
  static String? custId;           // Customer ID CRM

  static bool isLogin = false;

  static Future<void> saveUser({
    String? mid,
    String? userNo,
    String? dynamicSignKey,
    String? custId,
  }) async {
    if (mid != null) Global.mid = mid;
    if (userNo != null) Global.userNo = userNo;
    if (dynamicSignKey != null) Global.dynamicSignKey = dynamicSignKey;
    if (custId != null) Global.custId = custId;
    isLogin = Global.mid != null && Global.mid!.isNotEmpty;
  }

  static void clearUser() {
    mid = null;
    userNo = null;
    custId = null;
    dynamicSignKey = null;
    isLogin = false;
  }
}

2. Pengambilan Status Sesi dari Host Native (`getRootPageData`)

Diimplementasikan pada 🦊 flutter/lib/common/platform/flutter_native_channel_method.dart learn/Flutter-Arch ↗ (baris 22–26):

static Future<Map<dynamic, dynamic>?> getRootPageData() {
  return FlutterNativeChannel.invokeCommon<Map<dynamic, dynamic>>(
    'getRootPageData',
  );
}

Di sisi host iOS (file ios/IDSamirLoan/Application/SamirCommonModule/Classes/FChannel/FlutterNativeChannel+method.swift), native mengembalikan payload dictionary:

{
  "isLogin": true,
  "mid": "eyJhbGciOiJIUzI1NiIsIn...",
  "userNo": "U20261022001",
  "custId": "C998877",
  "dynamicSignKey": "a8f3b21c-99de-4412-bcde",
  "showSocialMedia": true

Ketika MineHomeService atau RepayHomeService memuat halaman:

  1. Layanan memanggil getRootPageData().
  2. Data sesi langsung diinjeksikan ke Global.saveUser().
  3. Variabel Global.isLogin otomatis terbarui menjadi true.

3. Penanganan Otomatis Sesi Kedaluwarsa (Error 10006)

Pada 🦊 flutter/lib/common/http/http_client.dart learn/Flutter-Arch ↗ (baris 133–149):

dynamic _getResponse(Response<dynamic> response) {
  final BaseResponse<dynamic> baseResponse = BaseResponse<dynamic>.fromJson(
    response.data is Map<String, dynamic>
        ? response.data as Map<String, dynamic>
        : null,
  );
  if (baseResponse.code == '200') {
    // Sukses, kembalikan data payload
  } else {
    if (baseResponse.code == '10006') {
      Global.clearUser();
      Routers.gotoLogin();
    }
    showToast(baseResponse.msg);
  }
  return baseResponse.data;
}

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Zero-Storage Security di Flutter:

Modul Flutter SAMIR tidak menyimpan file database sqflite atau shared_preferences untuk token login. Seluruh data kredensial hanya hidup di memori RAM objek Global. Jika aplikasi ditutup paksa atau di-kill oleh OS, tidak ada jejak kredensial yang tersisa di sandbox file Flutter. Kredensial terlindungi aman di dalam Secure Enclave / Keychain native.

  • Konsistensi Lintas Modul:

Ketika pengguna logout di Beranda Native, modul Flutter tidak perlu menghapus file database lokal yang lambat. Pemanggilan getRootPageData berikutnya akan mengembalikan isLogin = false, dan antarmuka Flutter seketika beralih ke RepayEmptyState.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika seorang nasabah mengganti kartu SIM dan mencoba membuka menu profil di Tab Saya:

  1. Token lama ditolak oleh server dengan response code: '10006'.
  2. Pengguna tidak mengalami crash; sistem otomatis menampilkan Toast "Sesi Anda telah berakhir, silakan masuk kembali".
  3. Layar login native seketika muncul untuk meminta verifikasi nomor SIM baru nasabah.

⚠️ H. Common Mistakes & Debugging

  • Mengubah Nilai Global.mid Secara Manual di Widget:
  • Dilarang keras memodifikasi Global.mid = '...' di luar fungsi saveUser() atau clearUser(). Mengubah atribut ini secara terpisah dapat membuat isLogin tidak tersinkronisasi.
  • Lupa Mengantisipasi Nilai Null pada Global.userNo:
  • Pada status guest, Global.userNo bernilai null. Selalu gunakan null-aware operator (Global.userNo?.isNotEmpty ?? false) sebelum menyisipkan parameter ini ke URL atau query.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: State Mutation Tersebar & Kurangnya Single Source of Truth

Status transaksi pinjaman dan otentikasi disimpan di beberapa singleton berbeda secara terpisah, rentan memicu race condition dan state inconsistency antar tab.

⚠️ Smells 2: Kurangnya Abstraksi Domain Layer (Business Logic Terikat ke UI)

Logika validasi kredit dan kalkulasi bunga dilakukan langsung di lapisan presentasi tampilan, menyulitkan pemeliharaan dan pengujian regresi.

🚀 Blueprint Refactoring Standar Industri: Pola Clean Architecture Use Case (Domain Interactor Pattern)

Mengisolasi logika bisnis finansial ke dalam Use Case murni yang bebas dari UIKit atau Widget Flutter, menjamin 100% testability dan integritas transaksi.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class GetLoanStatusUseCase {
  Future<LoanStatusResult> execute(String userId);
}

class DefaultGetLoanStatusUseCase implements GetLoanStatusUseCase {
  final LoanRepository repository;
  DefaultGetLoanStatusUseCase(this.repository);

  @override
  Future<LoanStatusResult> execute(String userId) => repository.fetchLoanStatus(userId);
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
