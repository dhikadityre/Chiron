Core Knowledge

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Menjelaskan bagaimana MineHomePage merender profil nasabah dan skema menu secara dinamis dari backend.
  2. Memahami alur pengambilan jumlah pesan belum dibaca via ServerApi.messageCount.
  3. Mengetahui arsitektur subhalaman MinePersonalPage dalam memetakan status kelengkapan verifikasi KTP.
  4. Menjelaskan mekanisme tersembunyi (Easter Egg) ketukan 5 kali pada nomor versi untuk membuka ProxyDebugPage.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan kartu keanggotaan klub eksklusif dan buku paspor Anda:

  • Halaman Dasbor Profil (MineHomePage): Seperti kartu keanggotaan yang menampilkan foto profil, nomor telepon, status keaktifan keanggotaan, serta deretan tombol fasilitas klub (kolam renang, restoran, pusat kebugaran).
  • Halaman Verifikasi (MinePersonalPage): Seperti lembaran paspor resmi yang menunjukkan cap status kelengkapan data imigrasi: apakah e-KTP sudah diverifikasi, apakah foto selfie sudah lolos uji keaslian wajah, dan apakah nomor rekening bank sudah tervalidasi.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Skema Pengambilan Data: `MineHomeService`

Diimplementasikan pada 🦊 flutter/lib/pages/mine/home/services/mine_home_service.dart learn/Flutter-Arch ↗:

class MineHomeService {
  MineHomeService._();

  static Future<MineHomeModel> fetchMineHomeData() async {
    final Map<dynamic, dynamic>? rootData =
        await FlutterNativeChannelMethod.getRootPageData();
    final bool isLogin = rootData?['isLogin'] == true;

    if (!isLogin) {
      Global.clearUser();
      return const MineHomeModel(isLogin: false);
    }

    await Global.saveUser(
      mid: rootData?['mid']?.toString(),
      userNo: rootData?['userNo']?.toString(),
      dynamicSignKey: rootData?['dynamicSignKey']?.toString(),
      custId: rootData?['custId']?.toString(),
    );

    final dynamic responseData = await httpClient.post(
      ServerApi.personalAuthSchema, // 'product/V4/mergeUserCenterSchema'
      showLoading: false,
    );

    return MineHomeModel.fromJson(
      responseData is Map<String, dynamic> ? responseData : null,
      isLogin: true,
    );
  }

  static Future<int> fetchMessageCount() async {
    if (!Global.isLogin) return 0;
    final dynamic responseData = await httpClient.post(
      ServerApi.messageCount, // 'msg/queryCount'
      showLoading: false,
    );
    // Mengembalikan jumlah pesan belum dibaca
    return responseData?['unreadCount'] ?? 0;
  }
}

5. Pintu Rahasia Pengujian Jaringan (*Easter Egg*)

Pada MinePersonalPage (baris 80–92):

int _debugTapCount = 0;

void _onVersionTap() {
  if (AppEnv.isProd) {
    _debugTapCount = 0;
    return;
  }
  _debugTapCount++;
  if (_debugTapCount >= 5) {
    _debugTapCount = 0;
    Navigator.of(context).push(
      MaterialPageRoute<void>(builder: (_) => const ProxyDebugPage()),
    );
  }
}

Ketika developer atau QA mengetuk nomor versi aplikasi sebanyak 5 kali berturut-turut pada build non-PROD, aplikasi langsung membuka ProxyDebugPage untuk mengatur proxy IP inspect traffic.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Skema Menu Berbasis Backend (Dynamic Server-Driven UI):

Dengan mengonsumsi mergeUserCenterSchema, tim backend dan product manager dapat menampilkan atau menyembunyikan menu promo tertentu (misalnya program undian THR atau promo Ramadhan) dari jarak jauh tanpa perlu merilis pembaruan biner ke App Store / Google Play.

  • Isolasi Keamanan Menu Debug:

Pengecekan if (AppEnv.isProd) return; memastikan kode debugging proxy tidak dapat dibuka oleh nasabah umum di lingkungan production, menjaga kepatuhan terhadap audit keamanan siber finansial.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika nasabah baru saja diverifikasi e-KTP-nya di modul kamera native:

  • Native mengirim sinyal refreshMineHome.
  • MineHomePage memuat ulang skema profil.
  • Status di samping avatar seketika berubah dari "Belum Terverifikasi" menjadi centang hijau "Terverifikasi".

  • Lupa Mereset Counter Ketukan Versi:
  • Variabel _debugTapCount harus di-reset ke 0 setelah membuka halaman debug untuk mencegah terpicunya navigasi ganda yang tidak diinginkan.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: State Mutation Tersebar & Kurangnya Single Source of Truth

Status transaksi pinjaman dan otentikasi disimpan di beberapa singleton berbeda secara terpisah, rentan memicu race condition dan state inconsistency antar tab.

⚠️ Smells 2: Kurangnya Abstraksi Domain Layer (Business Logic Terikat ke UI)

Logika validasi kredit dan kalkulasi bunga dilakukan langsung di lapisan presentasi tampilan, menyulitkan pemeliharaan dan pengujian regresi.

🚀 Blueprint Refactoring Standar Industri: Pola Clean Architecture Use Case (Domain Interactor Pattern)

Mengisolasi logika bisnis finansial ke dalam Use Case murni yang bebas dari UIKit atau Widget Flutter, menjamin 100% testability dan integritas transaksi.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class GetLoanStatusUseCase {
  Future<LoanStatusResult> execute(String userId);
}

class DefaultGetLoanStatusUseCase implements GetLoanStatusUseCase {
  final LoanRepository repository;
  DefaultGetLoanStatusUseCase(this.repository);

  @override
  Future<LoanStatusResult> execute(String userId) => repository.fetchLoanStatus(userId);
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
