05 — Cross-Boundary Journeys

Alur Bisnis Lintas Batas Hybrid

📚 Modul: 05-cross-boundary-journeys 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menjelaskan skenario perjalanan pengguna yang melintasi batas (cross-boundary) antara modul SAMIR Flutter dan aplikasi host native iOS/Android, menelusuri penanganan token kedaluwarsa lintas batas, transisi ke modul kamera KYC native, pembukaan modul Live Chat Customer Service, serta pelacakan analitik terpadu.

Status Verifikasi: [Verified] (diverifikasi langsung dari inspeksi kode 🦊 flutter/lib/common/platform/flutter_native_channel_route.dart learn/Flutter-Arch ↗, 🦊 flutter/lib/common/platform/flutter_native_channel_track.dart learn/Flutter-Arch ↗, dan 🦊 flutter/lib/common/utils/track_utils.dart learn/Flutter-Arch ↗).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Menjelaskan 4 skenario interaksi lintas batas antara Flutter dan Native Host.
  2. Memahami siklus lengkap re-autentikasi saat token kedaluwarsa (Loop Error 10006).
  3. Menelusuri transisi dari menu Flutter ke alur kamera e-KYC OCR Native (samir://mine/infoAuthList).
  4. Memahami bagaimana event analytics page view di Flutter diteruskan ke SDK analitik host native via samir_tracking_channel.

📋 B. Prerequisites

Telah membaca 02-authentication-and-session-sync.md hingga 04-mine-and-personal-flows.md.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan perjalanan antar-negara di Uni Eropa:

  • Anda dapat berkendara bebas di dalam wilayah satu negara tanpa paspor (Navigasi internal GoRouter di modul Flutter).
  • Namun, ketika Anda ingin menaiki pesawat penerbangan internasional (Verifikasi Wajah / e-KYC), Anda harus melewati gerbang pemeriksaan paspor imigrasi bandara (Modul Native).
  • Sistem keamanan bandara memeriksa paspor Anda, mencap bukti keberangkatan, dan setelah penerbangan selesai, Anda kembali melangkah ke terminal kedatangan dengan status paspor yang sudah diperbarui.

2. Skenario 2: Transisi ke Modul Verifikasi e-KYC & Kamera Native

Ketika nasabah di MineHomePage menekan menu "Sertifikasi Informasi":

  1. Flutter mengeksekusi: 
   FlutterNativeChannelRoute.openNativeRoute('samir://mine/infoAuthList');
  1. Native host menangkap skema URL samir://mine/infoAuthList pada router internal CZSwiftRouterLib.
  2. Native memunculkan IDAuthLiveViewController (modul Native Swift) yang memanfaatkan SDK kamera hardware untuk:
    • Deteksi keaslian wajah (Liveness Detection berkedip & menoleh).
    • Pengambilan foto e-KTP dengan pemrosesan tepi gambar berkecepatan 60 FPS.
  3. Setelah verifikasi sukses, native menutup layar kamera dan mengirimkan sinyal refreshMineHome ke Flutter.
  4. Halaman profil Flutter seketika menampilkan status KYC lengkap.

3. Skenario 3: Pembukaan Layanan Pelanggan (CS Live Chat)

Ketika nasabah menekan tombol layanan pelanggan di RepayHomePage atau MineHomePage:

  1. Flutter mengeksekusi: 
   FlutterNativeChannelRoute.openNativeRoute('customerAction');
  1. Host native memanggil inisialisasi SDK Live Chat pihak ketiga (seperti Meiqia / Zendesk).
  2. Layar obrolan chat dibuka sebagai modal controller native.
  3. Seluruh percakapan dan pengunggahan berkas bukti transfer ditangani oleh SDK native.
  4. Saat pengguna menutup chat, antarmuka Flutter di latar belakang tetap berada pada posisi scroll dan status yang sama tanpa reload ulang.

4. Skenario 4: Pipeline Pelacakan Analitik Terpadu

Pelacakan page view diimplementasikan menggunakan mixin di 🦊 flutter/lib/common/utils/track_utils.dart learn/Flutter-Arch ↗:

mixin TrackPageViewMixin<T extends StatefulWidget> on State<T> {
  String get trackPageEventName;

  void trackPageView() {
    FlutterNativeChannelTrack.trackEvent(
      'page_view',
      <String, dynamic>{
        'page_name': trackPageEventName,
        'timestamp': DateTime.now().millisecondsSinceEpoch,
      },
    );
  }
}
  • MineHomePage mendefinisikan trackPageEventName => 'me'.
  • RepayHomePage mendefinisikan trackPageEventName => 'repayment'.
  • Setiap kali halaman menjadi aktif, event dikirim via samir_tracking_channel ke pipeline analitik native host (Sensors Analytics / Firebase / Tingyun APM) sehingga data dashboard metrik tim produk tetap konsisten antara layar native dan Flutter.

⚖️ E. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Menghindari Duplikasi SDK Berat:

SDK kamera liveness detection dan live chat customer service berukuran sangat besar (bisa mencapai 20–40 MB binary size). Mengintegrasikannya dua kali (di Native dan di Flutter) akan membuat ukuran instalasi aplikasi membengkak secara drastis. Dengan mendelegasikan aksi melalui openNativeRoute, Flutter memanfaatkan SDK yang sudah ada di native host.

  • Konsistensi Single Pipeline Analytics:

Jika Flutter mengirim analitik langsung ke server via HTTP tersendiri, parameter perangkat keras (seperti IDFA, IMEI, akselerometer, dan status jaringan seluler) bisa berbeda dengan yang dicatat oleh native. Meneruskan event ke samir_tracking_channel menjamin seluruh log analytics memiliki metadata perangkat yang seragam.

🔬 F. Practical Example (Skenario Penggunaan Nyata)

Seorang pengguna menerima SMS tagihan dengan link samir://repay:

  1. Pengguna mengetuk link di aplikasi Pesan iPhone.
  2. iOS SpringBoard membuka aplikasi SAMIR via URL Scheme samir://.
  3. CZAppDelegate di native mendeteksi rute repay dan memilih tab 1.
  4. Native mengirimkan showFlutterRoute('/repay') ke Flutter Engine.
  5. Flutter langsung menampilkan RepayHomePage dengan daftar tagihan yang relevan.

⚠️ G. Common Mistakes & Debugging

  • Mengirim String Parameter Native Tanpa Serialisasi yang Valid:
    • Saat memanggil openNativeRoute(url, params: {...}), seluruh nilai di dalam map harus bertipe tipe primitif Dart (String, int, double, bool). Mengirim objek custom akan memicu crash PlatformException: Unsupported value.

🧠 H. Knowledge Check

  1. Apa nama method channel yang digunakan khusus untuk menyalurkan event analytics dari Flutter ke native?
  2. Bagaimana modul kamera liveness detection diakses dari dalam halaman profil Flutter?
  3. Sebutkan nama event page view yang dikirimkan saat pengguna membuka halaman Tagihan!

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: State Mutation Tersebar & Kurangnya Single Source of Truth

Status transaksi pinjaman dan otentikasi disimpan di beberapa singleton berbeda secara terpisah, rentan memicu race condition dan state inconsistency antar tab.

⚠️ Smells 2: Kurangnya Abstraksi Domain Layer (Business Logic Terikat ke UI)

Logika validasi kredit dan kalkulasi bunga dilakukan langsung di lapisan presentasi tampilan, menyulitkan pemeliharaan dan pengujian regresi.

🚀 Blueprint Refactoring Standar Industri: Pola Clean Architecture Use Case (Domain Interactor Pattern)

Mengisolasi logika bisnis finansial ke dalam Use Case murni yang bebas dari UIKit atau Widget Flutter, menjamin 100% testability dan integritas transaksi.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class GetLoanStatusUseCase {
  Future<LoanStatusResult> execute(String userId);
}

class DefaultGetLoanStatusUseCase implements GetLoanStatusUseCase {
  final LoanRepository repository;
  DefaultGetLoanStatusUseCase(this.repository);

  @override
  Future<LoanStatusResult> execute(String userId) => repository.fetchLoanStatus(userId);
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
