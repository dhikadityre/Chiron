Core Knowledge

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memahami peranan BasePage sebagai Scaffold terstandarisasi untuk semua layar sekunder di Flutter SAMIR.
  2. Menggunakan NavTitleBar untuk konfigurasi judul, tombol kembali, dan tombol aksi di bilah atas.
  3. Menjelaskan mekanisme kerja AppLoadingOverlay yang dikendalikan oleh LoadingInterceptor Dio.
  4. Memahami keunggulan AppDialogHost yang memisahkan dialog bisnis dari tumpukan navigasi GoRouter.
  5. Menggunakan AppSocialMediaSection untuk standarisasi informasi kanal resmi CS dan media sosial SAMIR.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan merancang seragam dan perlengkapan standar untuk staf bank:

  • BasePage adalah setelan jas resmi yang sudah dilengkapi name tag dan lencana bank; setiap teller baru cukup mengenakannya tanpa perlu menjahit baju dari nol.
  • AppLoadingOverlay adalah tirai penutup kaca loket otomatis: ketika teller sedang mengambil uang dari brankas pusat (request API), tirai turun secara halus agar nasabah tahu proses sedang berlangsung.
  • AppDialogHost adalah ruang konsultasi terpisah: jika ada berkas penting yang perlu ditandatangani nasabah, berkas tersebut diajukan di meja khusus tanpa mengganggu antrean loket utama.

💻 D. Actual Implementation (Bukti di Kode Sumber)

1. Standarisasi Layar dengan `BasePage`

File 🦊 flutter/lib/common/widgets/basePage/base_page.dart learn/Flutter-Arch ↗ adalah widget Scaffold pembungkus kanonikal:

class BasePage extends StatefulWidget {
  const BasePage({
    super.key,
    this.title,
    this.navTitleBar,
    this.backgroundColor,
    this.resizeToAvoidBottomInset,
    this.floatingActionButton,
    required this.body,
    this.onBack,
  });

  final String? title;
  final PreferredSizeWidget? navTitleBar;
  final Color? backgroundColor;
  final bool? resizeToAvoidBottomInset;
  final Widget? floatingActionButton;
  final Widget body;
  final VoidCallback? onBack;
  // ...
}

Keuntungan utama BasePage:

  1. Otomatisasi Navigation Bar: Jika properti title diisi teks (misal: "Pengaturan Akun"), BasePage otomatis merakit NavTitleBar lengkap dengan tombol kembali dan style font Lato.
  2. Status Bar Overlay Konsisten: Membungkus antarmuka dengan AnnotatedRegion<SystemUiOverlayStyle> agar warna jam dan ikon baterai selalu hitam kontras di atas tema terang.
  3. Penanganan Back Terpadu: Callback onBack dapat di-override untuk intercept tombol kembali (misal menampilkan dialog konfirmasi "Batalkan perubahan?" sebelum menutup halaman).

2. Loading Spinner Global: `AppLoadingOverlay`

Dikonfigurasi di root MyApp.builder dan diimplementasikan di 🦊 flutter/lib/common/widgets/loading/loading.dart learn/Flutter-Arch ↗:

class AppLoadingOverlay extends StatefulWidget {
  const AppLoadingOverlay({super.key, required this.child});
  final Widget child;
  // ...
}

Alur kerja:

  • Ketika httpClient.post(..., showLoading: true) dipanggil, LoadingInterceptor otomatis memanggil Loading.show().
  • AppLoadingOverlay menampilkan lapisan transparan gelap (modal barrier) dengan indikator loading berputar di tengah layar.
  • Lapisan ini mencegah pengguna mengetuk tombol lain secara tidak sengaja (double-click prevention) saat request sedang terbang ke server.
  • Begitu response diterima atau timeout terjadi, LoadingInterceptor memanggil Loading.hide() untuk menghapus overlay.

3. Dialog Terisolasi: `AppDialogHost` & `AppDialog`

File 🦊 flutter/lib/common/router/app_dialog.dart learn/Flutter-Arch ↗:

class AppDialogHost extends StatefulWidget {
  const AppDialogHost({super.key, required this.child});
  final Widget child;
  // ...
}

Mengapa ini penting?

  • Di Flutter standar, dialog ditampilkan via showDialog(), yang memasukkan dialog sebagai Route baru ke dalam Navigator.
  • Jika GoRouter.go('/root') dipanggil saat dialog masih terbuka, rute dialog bisa menyebabkan bentrok navigasi atau tersangkut di stack.
  • AppDialogHost membungkus aplikasi di luar GoRouter. Dialog bisnis dapat ditampilkan dan ditutup secara independen tanpa memengaruhi riwayat URL routing.

4. Kanal Resmi: `AppSocialMediaSection`

File 🦊 flutter/lib/common/widgets/contact/app_social_media_section.dart learn/Flutter-Arch ↗ menyediakan komponen standar untuk menampilkan tautan resmi:

  • WhatsApp Customer Care
  • Akun Instagram resmi SAMIR (@samir_co_id)
  • Halaman Facebook
  • Call center / Telepon pengaduan

Komponen ini digunakan secara seragam di bagian bawah tab Tagihan (RepayHomePage) dan tab Profil (MineHomePage).

🪜 E. Step-by-Step Walkthrough: Membuat Halaman Baru Menggunakan `BasePage`

import 'package:flutter/material.dart';
import 'package:flutter_app_project/common/widgets/basePage/base_page.dart';

class FaqDetailPage extends StatelessWidget {
  const FaqDetailPage({super.key});

  @override
  Widget build(BuildContext context) {
    return BasePage(
      title: 'Pusat Bantuan',
      backgroundColor: Colors.white,
      body: SingleChildScrollView(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: const [
            Text('Pertanyaan yang sering diajukan mengenai pembayaran...'),
          ],
        ),
      ),
    );
  }
}

Hasil:

  • Status bar perangkat otomatis terkonfigurasi.
  • Header atas otomatis menampilkan tombol kembali yang memanggil Routers.pop().
  • Latar belakang halaman diwarnai putih bersih sesuai design system SAMIR.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Eliminasi Kode Boilerplate:

Tanpa BasePage, setiap engineer harus mendeklarasikan Scaffold, AppBar, AnnotatedRegion, WillPopScope/PopScope, dan penyesuaian padding status bar secara berulang di setiap file halaman. BasePage mereduksi duplikasi kode hingga lebih dari 60 baris per halaman.

  • Konsistensi UI Antara iOS & Android:

Komponen NavTitleBar memastikan tombol kembali dan penempatan judul berada di koordinat yang estetis dan proporsional di kedua platform, menghindari inkonsistensi layout bawaan AppBar Material yang berbeda antara iOS (tengah) dan Android (kiri).

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika desainer UI memutuskan untuk memperbarui warna latar belakang seluruh halaman sekunder dari putih ke abu-abu terang (#F7F8FA):

  • Cukup ubah default parameter backgroundColor di dalam BasePage.
  • Seluruh halaman sekunder aplikasi seketika mengadopsi warna baru secara serempak.

⚠️ H. Common Mistakes & Debugging

  • Menggunakan Scaffold Biasa Alih-Alih BasePage:
  • Menyebabkan status bar perangkat berubah menjadi putih (ikon tak terlihat) dan tombol back tidak mengikuti aturan navigasi NativeRouteChrome.
  • Menampilkan Dialog dengan showDialog() Bawaan Navigator:
  • Dapat memicu konflik stack dengan GoRouter. Selalu gunakan AppDialog.show() yang disediakan modul SAMIR.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
