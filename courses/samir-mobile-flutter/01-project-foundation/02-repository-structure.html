02 — Repository Structure

Anatomi Direktori SAMIR Flutter

📚 Modul: 02-repository-structure 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menjelaskan hierarki dan struktur organisasi file pada modul SAMIR Flutter (flutter_app_project), memetakan pembagian tanggung jawab folder di bawah flutter/lib, serta menjelaskan peran file konfigurasi penting.

Status Verifikasi: [Verified] (diverifikasi langsung dari inspeksi tree repositori pada path Mobile/Develop/samir-mobile-develop/flutter).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Memetakan letak seluruh kode sumber Dart, file aset gambar, dan konfigurasi build.
  2. Memahami pembagian domain antara subdirektori common/ dan pages/.
  3. Menjelaskan konvensi modularisasi subfitur (pola models/, services/, dan widgets/).
  4. Membedakan folder source code aktif dari folder platform wrapper bawaan (.android/, .ios/).

📋 B. Prerequisites

Telah membaca 01-application-overview.md.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan sebuah pabrik komponen otomotif:

  • Folder common/ adalah bengkel perkakas bersama dan stasiun kontrol umum (kunci pas, baut, jalur pipa oli, jembatan radio dengan stasiun pusat). Semua lini produksi menggunakannya.
  • Folder pages/ adalah stasiun perakitan modul spesifik. Stasiun repay/ khusus merakit loket tagihan, sedangkan mine/ khusus merakit dasbor profil pelanggan.
  • File pubspec.yaml adalah manifest izin dan daftar suku cadang resmi pabrik.

🪜 E. Step-by-Step Walkthrough: Menelusuri File Fitur Baru

Jika seorang developer ditugaskan untuk menambahkan menu baru di halaman MineHomePage:

  1. Buka 🦊 flutter/lib/pages/mine/home/widgets/mine_home_menu.dart learn/Flutter-Arch ↗.
  2. Periksa mapping rute pada event onTap.
  3. Jika menu membutuhkan endpoint data baru, tambahkan konstanta path di 🦊 flutter/lib/common/api/server_api.dart learn/Flutter-Arch ↗.
  4. Buat pemanggil API baru di 🦊 flutter/lib/pages/mine/home/services/mine_home_service.dart learn/Flutter-Arch ↗.
  5. Buat model parsing di 🦊 flutter/lib/pages/mine/home/models/mine_home_model.dart learn/Flutter-Arch ↗.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Menggunakan Sintaks part dan part of pada Folder Widgets?

Komponen UI seperti mine_home_header.dart menggunakan part of 'mine_home_page.dart'. Hal ini memungkinkan sub-komponen mengakses state internal, method pembantu privat (_showLoading(), _model), tanpa perlu meneruskan puluhan callback parameter secara manual, sambil menjaga file utama tetap ramping dan terstruktur.

  • Mengapa .android/ dan .ios/ Berawalan Titik (.)?

Folder ini dibuat otomatis oleh Flutter tooling sebagai sandbox wrapper. Modul Add-to-App yang sesungguhnya diintegrasikan ke folder ios/ dan android/ di level terluar monorepo SAMIR, bukan di dalam direktori flutter/.android/ atau flutter/.ios/.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Ketika ada kebutuhan untuk mengubah domain API staging, developer tidak perlu mencari ke setiap file page. Cukup buka satu file konfigurasi terpusat: 🦊 flutter/lib/common/constants/app_env.dart learn/Flutter-Arch ↗.

⚠️ H. Common Mistakes & Debugging

  • Mengubah file di dalam .ios/ atau .android/:
  • File-file ini bersifat transient dan dapat ditimpa ulang (overwritten) secara otomatis setiap kali perintah flutter packages get atau flutter build dijalankan. Perubahan konfigurasi native wajib dilakukan di folder host asli: ios/ atau android/.
  • Menaruh Business Logic di dalam widgets/:
  • Pelanggaran Separation of Concerns terjadi jika widget memanggil httpClient.post() secara langsung. Panggilan jaringan wajib diisolasi di dalam folder services/.

🧠 I. Knowledge Check

  1. Di folder mana kode penandatanganan request (signature cryptographic hashing) disimpan?
  2. Apa tujuan membagi kode per fitur menjadi models/, services/, dan widgets/?
  3. Apa fungsi file flutter/lib/common/router/native_route_chrome.dart?

Latihan Observasi:

Buka file 🦊 flutter/lib/common/api/server_api.dart learn/Flutter-Arch ↗ dan catat seluruh string konstanta endpoint yang ada di dalamnya.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:
