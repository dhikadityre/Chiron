03 — Technology Stack & Build Tooling

Flutter Add-to-App

📚 Modul: 03-technology-stack-and-build 🎯 Scope: SAMIR Mobile (Flutter Add-to-App & MethodChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/Flutter-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumentasi ini menjelaskan konfigurasi pustaka (dependency stack), versi framework Flutter dan Dart, aturan analisis statis (linting), serta mekanisme build dan integrasi modul Flutter ke dalam proyek host native iOS dan Android.

Status Verifikasi: [Verified] (diverifikasi langsung dari 🦊 flutter/pubspec.yaml learn/Flutter-Arch ↗, 🦊 flutter/analysis_options.yaml learn/Flutter-Arch ↗, dan 🦊 ios/Podfile learn/Flutter-Arch ↗).

🎯 A. Learning Objective

Setelah menyelesaikan dokumen ini, pembaca akan mampu:

  1. Menyebutkan versi runtime resmi Flutter dan Dart yang kompatibel dengan codebase SAMIR.
  2. Memahami fungsi dan peranan setiap dependency pihak ketiga di dalam pubspec.yaml.
  3. Menjelaskan mekanisme podhelper.rb yang menghubungkan modul Flutter ke CocoaPods iOS.
  4. Menjalankan perintah build, dependency update, dan code analysis tanpa merusak integrasi host.

📋 B. Prerequisites

Telah membaca 01-application-overview.md dan 02-repository-structure.md.

💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan modul Flutter sebagai mesin bertenaga listrik yang dipasang ke dalam chassis mobil berbahan bakar konvensional (Host Native):

  • Supaya mesin listrik tersebut pas dan bekerja tanpa getaran, dibutuhkan kabel penghubung khusus dan bracket transmisi standar.
  • Di iOS, kabel penghubung tersebut dinamakan podhelper.rb yang disediakan oleh Flutter SDK. Skrip ini memberi tahu CocoaPods: "Kompilasi kode Dart ini menjadi framework biner, lalu masukkan ke dalam bundle Xcode IDSamirLoan."
  • Baterai dan controller mesin tersebut dikelola oleh paket-paket standar: Dio sebagai saluran pipa bahan bakar data, dan GoRouter sebagai roda kemudi navigasi.

3. Integrasi CocoaPods iOS via podhelper.rb

Host iOS mengonsumsi modul Flutter melalui file 🦊 ios/Podfile learn/Flutter-Arch ↗:

# ios/Podfile (Baris 14-20)
flutter_application_path = '../flutter'
load File.join(flutter_application_path, '.ios', 'Flutter', 'podhelper.rb')

target 'IDSamirLoan' do
  # ...
  install_all_flutter_pods(flutter_application_path)
end

Ketika pod install dijalankan di folder ios/:

  1. podhelper.rb mengevaluasi plugin Flutter yang terdaftar di .flutter-plugins-dependencies.
  2. Skrip membangun symlink dan podspec lokal untuk framework App.framework (berisi kode Dart yang dikompilasi AOT) dan Flutter.framework (berisi Flutter Engine biner).
  3. Pods ini ditautkan ke target Xcode IDSamirLoan.

🪜 E. Step-by-Step Walkthrough: Alur Kerja Developer (Daily Workflow)

1. Menginstal / Mengunduh Dependency Baru

Jika Anda menambahkan paket baru di flutter/pubspec.yaml:

# 1. Masuk ke direktori flutter
cd Mobile/Develop/samir-mobile-develop/flutter

# 2. Unduh paket
flutter pub get

# 3. Sinkronisasikan ke host iOS
cd ../ios
pod install

2. Memeriksa Kualitas Kode (Static Analysis)

Proyek SAMIR menggunakan aturan ketat dari flutter_lints ^6.0.0 sebagaimana tercantum di 🦊 flutter/analysis_options.yaml learn/Flutter-Arch ↗:

cd Mobile/Develop/samir-mobile-develop/flutter
flutter analyze

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Versi SDK Terkunci Ketat?

Perubahan minor pada Flutter Engine (misalnya melompat dari Flutter 3.24 ke 3.27) dapat mengubah struktur API C++ di FlutterEngine, yang berpotensi memutus binding runtime FlutterViewController pada kode Objective-C / Swift di host iOS (FlutterEngineManager.swift). Seluruh anggota tim mobile wajib menggunakan versi Flutter SDK yang seragam.

  • Mengapa Menggunakan go_router dan Bukan Navigator 1.0 Imperatif?

Aplikasi SAMIR menerima sinyal route dari native host berupa string URL path semantik (seperti showFlutterRoute(route: '/repay')). GoRouter secara alami membaca URL string dan memetakannya langsung ke komponen halaman melalui deklarasi rute yang terstruktur.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Jika tim QA melaporkan error kompilasi CocoaPods podhelper.rb: No such file or directory:

  • Penyebab: Folder .ios/ di dalam direktori flutter/ belum digenerate oleh Flutter tools.
  • Solusi: Cukup jalankan perintah flutter pub get di dalam direktori flutter/ agar Flutter tooling membuat ulang file .ios/Flutter/podhelper.rb.

⚠️ H. Common Mistakes & Debugging

  • Menjalankan pod update tanpa flutter pub get terlebih dahulu:
    • CocoaPods akan mengacu pada snapshot plugin lama dan memicu error Plugin not found in podhelper.rb.
  • Mengabaikan peringatan Linter:
    • Hindari penggunaan print() biasa di production code; selalu gunakan debugPrint() atau LogUtils agar log sensitif tidak bocor di release build.

🧠 I. Knowledge Check

  1. Mengapa developer harus menjalankan pod install di folder ios/ setelah menambahkan dependency di flutter/pubspec.yaml?
  2. Apa kegunaan pustaka crypto di dalam proyek SAMIR Flutter?
  3. File apa di host iOS yang bertugas mengimpor seluruh pod Flutter ke proyek Xcode?

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
abstract class SessionContract {
  String? get userToken;
  bool get isLoggedIn;
}

class GlobalSessionManager implements SessionContract {
  @override
  String? userToken;
  @override
  bool get isLoggedIn => userToken != null && userToken!.isNotEmpty;
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:

Kuis 1 (Memory Recall): Berdasarkan standar Clean Architecture, apa peran utama dari domain layer pada modul FLUTTER?

Kuis 2 (Architectural Decision): Mengapa penerapan Dependency Inversion Principle (DIP) sangat krusial dalam pembuatan unit test?

Kuis 3 (Debugging & Maintenance): Apa keuntungan utama membatasi dependensi antar modul ke arah satu arah (Unidirectional Dependency)?
