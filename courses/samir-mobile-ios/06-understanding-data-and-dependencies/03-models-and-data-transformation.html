📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini menjelaskan lapisan model (Model Layer) di SAMIR iOS: pustaka KakaJSON, implementasi protokol Convertible, pemetaan nama kunci custom, serialisasi NSCoding pada data sesi, serta bagaimana data mentah dari backend ditransformasikan menjadi representasi visual di antarmuka pengguna.

Status Verifikasi: [Verified] (diverifikasi langsung dari class model di SamirLoginModule, SamirLoanModule, dan SamirAuthModule).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Memahami cara kerja pustaka KakaJSON (kj.model dan kj.modelArray) dalam memetakan JSON ke model Swift.
  2. Menggunakan method kustomisasi kj_modelKey untuk menangani ketidakcocokan nama properti JSON dengan nama properti Swift.
  3. Menjelaskan implementasi NSCoding / NSSecureCoding pada IDLoginCodeModel untuk persistensi disk terenkripsi.
  4. Menelusuri transformasi data kompleks dari model produk backend menjadi daftar baris sel tabel di Beranda (IDLoanService.getCellListAry).

📋 B. Prerequisites

  • Sudah membaca 02-networking-and-api-flow.md.
  • Mengetahui konsep JSON parsing, Swift Codable, dan protokol NSCoding.

💡 C. Simple Explanation (Analogi Penerjemah Dokumen Asing)

Ketika dokumen hukum tiba dari luar negeri dalam bahasa asing (JSON mentah dari backend):

  • Penerjemah Kilat (KakaJSON): Membaca lembaran dokumen asing tersebut dan langsung menyalinnya ke dalam formulir resmi berbahasa Indonesia (Model Struct / Class Swift).
  • Kamus Istilah Khusus (kj_modelKey): Jika dokumen asing menyebutkan kata "cust_id", penerjemah tahu bahwa di formulir kita istilah tersebut harus dimasukkan ke kolom "customerId".
  • Penata Meja Display (Data Transformation): Data angka mentah (misal: 5000000 dan 30) diubah menjadi teks yang enak dibaca pengunjung mall: "Plafon Rp 5.000.000 • Tenor 30 Hari".

1. Pola Dasar Model KakaJSON

Path: 🦊 ios/IDSamirLoan/Application/SamirLoanModule/Classes/IDModel/IDProductModel.swift learn/iOS-Arch ↗

Hampir seluruh model di aplikasi mengadopsi protokol Convertible dari pustaka KakaJSON:

import Foundation
import KakaJSON

public struct IDProductModel: Convertible {
    public var productId: String?
    public var productName: String?
    public var maxAmount: Double = 0.0
    public var minAmount: Double = 0.0
    public var termDays: Int = 0
    public var interestRate: String?
    public var buttonText: String?
    public var jumpUrl: String?
    
    // Inisialisasi default
    public init() {}
}
Cara Parsing di Service Layer:
// Parsing objek tunggal
if let dict = responseDict["result"] as? [String: Any] {
    let product = dict.kj.model(IDProductModel.self)
}

// Parsing daftar array objek
if let array = responseDict["result"] as? [[String: Any]] {
    let productList = array.kj.modelArray(IDProductModel.self)
}

2. Kustomisasi Pemetaan Kunci (kj_modelKey)

Terkadang backend menggunakan konvensi penamaan snake_case (misal: created_at atau user_mobile), sementara kode Swift menggunakan camelCase. KakaJSON menyediakan fungsi pemetaan:

public struct IDLoanRepaidModel: Convertible {
    public var orderId: String?
    public var repaymentAmount: Double = 0.0
    public var isOverdue: Bool = false
    
    public init() {}
    
    // Pemetaan custom key
    public mutating func kj_modelKey(from property: Property) -> ModelKey {
        switch property.name {
        case "orderId": return "order_no"
        case "repaymentAmount": return "repay_amt"
        case "isOverdue": return "is_over_due"
        default: return property.name
        }
    }
}

3. Model Sesi Pengguna: IDLoginCodeModel (NSCoding)

Path: 🦊 ios/IDSamirLoan/Application/SamirLoginModule/Classes/IDModel/IDLoginCodeModel.swift learn/iOS-Arch ↗

Berbeda dari model lainnya yang hanya di-parse dari JSON, IDLoginCodeModel wajib mendukung serialisasi binary disk karena akan disimpan ke dalam file terenkripsi idn_userFile.plist:

public class IDLoginCodeModel: NSObject, NSCoding, Convertible {
    public var mid: NSNumber?
    public var userNo: String?
    public var staticKey: String?
    public var mobile: String?
    public var token: String?
    
    public required init() {}
    
    // 1. Encode properti ke NSCoder saat di-archive
    public func encode(with coder: NSCoder) {
        coder.encode(mid, forKey: "mid")
        coder.encode(userNo, forKey: "userNo")
        coder.encode(staticKey, forKey: "staticKey")
        coder.encode(mobile, forKey: "mobile")
        coder.encode(token, forKey: "token")
    }
    
    // 2. Decode properti dari NSCoder saat di-unarchive
    public required init?(coder: NSCoder) {
        self.mid = coder.decodeObject(forKey: "mid") as? NSNumber
        self.userNo = coder.decodeObject(forKey: "userNo") as? String
        self.staticKey = coder.decodeObject(forKey: "staticKey") as? String
        self.mobile = coder.decodeObject(forKey: "mobile") as? String
        self.token = coder.decodeObject(forKey: "token") as? String
    }
}

⚖️ F. Why It Matters: KakaJSON vs Apple Swift Codable

Mengapa SAMIR iOS menggunakan KakaJSON dan bukan protokol standar bawaan Apple Codable?

  • *Ketahanan Terhadap Tipe Data yang Berubah (Type Tolerance)*:

Di backend, terkadang field nominal dikembalikan sebagai String "50000" di satu endpoint dan sebagai Integer 50000 di endpoint lain. Codable bawaan Swift akan langsung melempar exception DecodingError.typeMismatch dan membatalkan seluruh parsing. Sebaliknya, KakaJSON memiliki fitur auto-casting yang secara toleran mengubah string angka menjadi Double atau Int tanpa melempar crash!

  • Kecepatan Parsing: KakaJSON mengalokasikan memori secara langsung (memory layout inspection) yang sangat cepat untuk payload array besar.

🔬 G. Practical Example: Format Mata Uang Rupiah di Model

Beberapa model menyediakan getter komputasi (computed properties) untuk mempermudah format tampilan di UI:

extension IDProductModel {
    public var formattedMaxAmount: String {
        let formatter = NumberFormatter()
        formatter.numberStyle = .currency
        formatter.locale = Locale(identifier: "id_ID")
        return formatter.string(from: NSNumber(value: maxAmount)) ?? "Rp 0"
    }
}

⚠️ H. Common Mistakes & Debugging

  • Lupa Menambahkan init() {}:
    • KakaJSON mewajibkan struct atau class yang mengadopsi Convertible memiliki konstruktor kosong init(). Jika lupa, kompilasi akan menampilkan error Initializer 'init()' must be declared.
  • Nilai Default untuk Tipe Primitif:
    • Selalu berikan nilai default pada tipe non-opsional (misal: var count: Int = 0 atau gunakan opsional var count: Int?). Properti non-opsional tanpa nilai default dapat menyebabkan inisialisasi model gagal saat field tersebut absen dari response JSON.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
