Core Knowledge

Dokumen ini menjelaskan secara menyeluruh arsitektur integrasi hybrid Native iOS dan Flutter di SAMIR iOS: bagaimana modul Flutter disematkan ke dalam aplikasi native menggunakan pola Single Prewarmed Engine, bagaimana IDMainTabBarController meng-host tampilan Flutter tanpa membuat tab tambahan, mekanisme pergantian rute berbasis IndexedStack, hingga protokol komunikasi dua arah melalui FlutterMethodChannel.

Status Verifikasi: [Verified] (diverifikasi langsung dari FlutterEngineManager.swift, FlutterNativeChannel.swift, IDMainTabBarController.swift, dan flutter/lib/main.dart).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Memahami arsitektur integrasi Flutter Add-to-App melalui podhelper.rb di CocoaPods.
  2. Menjelaskan pola Single Prewarmed Engine (FlutterEngineManager) untuk menghemat konsumsi RAM dan menghilangkan jeda peluncuran Dart VM.
  3. Menjelaskan teknik Persistent Host Container pada IDMainTabBarController yang menampung tampilan Flutter di bawah tab bar native tanpa merusak tab count.
  4. Menelusuri seluruh metode komunikasi pada channel samir_native_channel dan samir_tracking_channel.
  5. Memahami bagaimana layout safe area (notch & tab bar) disinkronkan antara iOS UIKit dan Flutter RenderFlex.

  • Sudah membaca 01-technology-stack-and-build.md dan 04-cross-feature-journeys.md.

1. Pola Single Prewarmed Engine (FlutterEngineManager)

Path: 🦊 ios/IDSamirLoan/Application/SamirCommonModule/Classes/FChannel/FlutterEngineManager.swift learn/iOS-Arch ↗

Daripada membuat instance FlutterEngine baru setiap kali layar dibuka (yang memakan ~30 MB RAM per instance), aplikasi menggunakan satu engine singleton tunggal:

public final class FlutterEngineManager {
    public static let shared = FlutterEngineManager()
    private let engine = FlutterEngine(name: "samir_single_flutter_engine")
    private var viewController: SamirFlutterViewController?
    private var hasRun = false

    public func prewarm() {
        startEngineIfNeeded()
        inactive()
    }

    private func startEngineIfNeeded() {
        assert(Thread.isMainThread, "FlutterEngine must be started on the main thread")
        guard !hasRun else { return }

        // Start engine dengan entry point default dan initial route "/root"
        hasRun = engine.run(withEntrypoint: nil, initialRoute: "/root")
        FlutterNativeChannel.shared.setup(with: engine.binaryMessenger)
        GeneratedPluginRegistrant.register(with: engine)
    }
}
  • prewarm() dipanggil saat startup native di IDSamirMainModule.
  • Entry point Dart dijalankan dengan rute awal "/root".
  • GeneratedPluginRegistrant.register(with: engine) mendaftarkan seluruh plugin Flutter (seperti path_provider, shared_preferences, dll).

2. Teknik Persistent Host Container (IDMainTabBarController)

Path: 🦊 ios/IDSamirLoan/Application/SamirMainModule/Classes/IDController/IDMainTabBarController.swift learn/iOS-Arch ↗

Tantangan arsitektur terbesar: UITabBarController memperlakukan setiap child ViewController sebagai satu tab fisik. Jika kita menambahkan FlutterViewController langsung ke array viewControllers, akan muncul tab ke-4 yang tidak diinginkan di layar!

Solusi Elegan SAMIR:
private func installPersistentFlutterHost() {
    flutterContainerView.backgroundColor = UIColor(red: 245/255, green: 245/255, blue: 245/255, alpha: 1)
    flutterContainerView.isHidden = true
    
    // 1. Sisipkan view container persisten TEPAT DI BAWAH tabBar native
    view.insertSubview(flutterContainerView, belowSubview: tabBar)
    
    let nativeTabCount = viewControllers?.count
    
    // 2. Install Flutter view controller ke dalam container
    flutterViewController = FlutterEngineManager.shared.installPersistentRoot(in: flutterContainerView)
    
    // 3. Pastikan tab count native tetap 3!
    assert(viewControllers?.count == nativeTabCount, "Flutter host must not register an extra tab")
    FlutterEngineManager.shared.setPersistentRootVisible(false)
}

Ketika user memilih Tab 1 (IDRepayViewController) atau Tab 2 (IDMineViewController), controller native tersebut hanyalah "shell kosong" 50 baris yang bertugas menyalakan visibilitas flutterContainerView!

3. Struktur Routing Flutter (IndexedStack)

Path: 🦊 flutter/lib/pages/root/flutter_root_page.dart learn/iOS-Arch ↗

Di sisi Dart, FlutterRootPage menggunakan IndexedStack untuk menjaga state kedua halaman tetap hidup di memori:

class _FlutterRootPageState extends State<FlutterRootPage> {
  static const List<String> _paths = [
    RoutePaths.mineHome,  // "/mine"
    RoutePaths.repayHome, // "/repay"
  ];

  late final List<Widget> _pages = const [
    MineHomePage(),
    RepayHomePage(),
  ];

  @override
  Widget build(BuildContext context) {
    final String? selectedPath = FlutterRootController.selectedPath.value;
    final int selectedIndex = selectedPath == null ? -1 : _paths.indexOf(selectedPath);

    return IndexedStack(
      index: selectedIndex < 0 ? null : selectedIndex,
      children: _pages,
    );
  }
}

Ketika native memanggil showFlutterRoute("/repay"), Dart cukup mengganti index IndexedStack dari 0 ke 1 tanpa melakukan rebuild widget dari nol!

5. Sinkronisasi Safe Area & Dynamic Island

Path: 🦊 ios/IDSamirLoan/Application/SamirCommonModule/Classes/FChannel/FlutterEngineManager.swift learn/iOS-Arch ↗

Tampilan Flutter berada di bawah UITabBar native, sehingga insets safe area harus dihitung secara manual oleh native:

fileprivate func updatePersistentSafeArea(top: CGFloat, bottom: CGFloat) {
    let systemTop = max(0, view.safeAreaInsets.top - additionalSafeAreaInsets.top)
    let systemBottom = max(0, view.safeAreaInsets.bottom - additionalSafeAreaInsets.bottom)
    let nextInsets = UIEdgeInsets(
        top: max(0, top - systemTop),
        left: 0,
        bottom: max(0, bottom - systemBottom),
        right: 0
    )
    guard additionalSafeAreaInsets != nextInsets else { return }
    additionalSafeAreaInsets = nextInsets
    view.setNeedsLayout()
}

Fungsi ini menjamin teks atau tombol di layar Flutter tidak akan tertutup oleh Dynamic Island / poni notch di bagian atas atau bilah navigasi tab bar di bagian bawah.

🪜 E. Step-by-Step Walkthrough: Menambahkan Method Channel Baru

Misalkan Anda ingin membuat fungsi baru di Flutter untuk meminta native memeriksa apakah biometrik Face ID aktif di perangkat:

  1. Definisikan di Dart: 
   // flutter/lib/common/platform/flutter_native_route_dispatcher.dart
   static Future<Bool> isBiometricEnabled() async {
     final bool result = await _methodChannel.invokeMethod('isBiometricEnabled');
     return result ?? false;
   }
  1. Tambahkan Handler di Swift:

Buka ios/IDSamirLoan/Application/SamirCommonModule/Classes/FChannel/FlutterNativeChannel+method.swift:

   extension FlutterNativeChannel {
       func isBiometricEnabled(result: @escaping FlutterResult) {
           let context = LAContext()
           var error: NSError?
           let canEvaluate = context.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &error)
           result(canEvaluate)
       }
   }
  1. Daftarkan di Switch Case:

Buka FlutterNativeChannel.swift baris 110–135, tambahkan:

   case "isBiometricEnabled":
       self.isBiometricEnabled(result: result)

🔬 G. Practical Example: Navigasi ke Halaman Sekunder Flutter (/mine/personal)

Ketika nasabah mengklik kartu identitas di halaman profil Flutter:

  1. Flutter memanggil Routers.push(RoutePaths.minePersonal).
  2. Class NativeRouteChrome.prepareForLocation otomatis mengirim pesan setNativeTabBarHidden(hidden: true) ke native.

⚠️ H. Common Mistakes & Debugging

  • Lupa Menambahkan Plugin ke GeneratedPluginRegistrant:
    • Jika Anda menambahkan package Flutter baru di pubspec.yaml yang membutuhkan native plugin (misal: image_picker), jalankan pod install di folder ios/ agar hook CocoaPods mendaftarkan plugin tersebut ke proyek Xcode.
  • Assertion Failure pada Container View:
    • FlutterEngineManager memiliki guard assertionFailure("The persistent Flutter view cannot change container"). Sekali installPersistentRoot dipasang ke IDMainTabBarController, view tersebut tidak boleh dipindahkan ke window atau ViewController lain.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
