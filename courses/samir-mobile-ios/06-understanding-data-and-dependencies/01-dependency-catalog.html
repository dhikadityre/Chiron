📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini menyajikan inventarisasi komprehensif seluruh dependensi langsung (direct dependencies), framework biner pihak ketiga (vendor closed-source SDKs), pustaka Apple, serta tooling build yang digunakan dalam aplikasi SAMIR iOS.

Status Verifikasi: [Verified] (diverifikasi langsung dari ios/Podfile, Podfile.lock, dan header framework biner).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Menjelaskan fungsi, peran teknis, dan alasan kebutuhan dari 17 pustaka eksternal utama di SAMIR iOS.
  2. Menilai dampak runtime (runtime impact) dan dampak kegagalan (failure impact) jika suatu SDK eksternal mengalami gangguan.
  3. Memahami risiko upgrade dependensi dan kebiasaan pemeliharaan yang aman.

📋 B. Prerequisites

  • Sudah membaca 03-technology-stack-and-build.md.
  • Mengetahui cara kerja CocoaPods dan static linking di iOS.

💡 C. Simple Explanation (Analogi Suku Cadang dan Vendor Luar)

Sebuah bank tidak memproduksi mesin ATM, kamera CCTV, dan generator listriknya sendiri:

  • Pustaka Open Source Standar (SnapKit, Kingfisher, Alamofire): Seperti meja, kursi, dan telepon kantor yang dibeli dari toko umum. Mudah diperbarui dan kode sumbernya terbuka.
  • SDK Vendor Keamanan Tertutup (TrustDecision, Advance AI, LibNetSignGenerator): Seperti brankas uang lapis baja dari perusahaan keamanan khusus militer. Kodenya terenkripsi (closed-source), cara kerjanya rahasia, dan jika rusak, seluruh operasional bank bisa terhenti.

Senior engineer harus memahami karakteristik setiap suku cadang tersebut agar dapat mengantisipasi risiko kegagalan.

💻 D. Actual Implementation: Analisis Mendalam Dependensi Kunci

1. `LibNetSignGenerator.framework`

  • Tipe: Vendor Closed-Source Binary Framework (disimpan di SamirNetworkModule/Frameworks/).
  • Fungsi & Alasan Kebutuhan: Paling Kritis. Menghasilkan string tanda tangan sign pada setiap request HTTP in-house menggunakan algoritma enkripsi rahasia dan staticKey.
  • Komponen Konsumen: IDNetworkSignatureHandler.swift.
  • Runtime Impact: Menambah waktu komputasi mikrodetik sebelum setiap request jaringan dikirim.
  • Dampak Jika Gagal: FATAL (Catastrophic). Seluruh request API in-house akan ditolak oleh backend server dengan error signature invalid. Aplikasi menjadi 100% tidak dapat digunakan.
  • Risiko Upgrade: Sangat tinggi. Wajib dikoordinasikan langsung dengan tim backend dan penyedia vendor.
  • Confidence: [Verified].

2. `TrustDecisionPro` (`4.3.1.3`) & `TrustDecisionLiveness-Lite` (`2.5.1`)

  • Tipe: Closed-Source Risk Profiling & Facial Motion SDK via CocoaPods.
  • Fungsi: Mengumpulkan karakteristik perangkat (sidik jari hardware, sensor orientasi, status VPN/proxy) untuk menghasilkan token risiko blackBox, serta mendeteksi keaslian wajah.
  • Komponen Konsumen: IDTrustDecisionManager.swift, IDAuthLiveViewController.swift.
  • Runtime Impact: Mengakses sensor perangkat saat startup (setelah izin ATT diberikan) dan saat verifikasi wajah.
  • Dampak Jika Gagal: Pengajuan pinjaman nasabah akan ditolak oleh risk engine backend karena blackBox kosong atau skor risiko dinilai mencurigakan.
  • Risiko Upgrade: Menengah-Tinggi. Memerlukan penyesuaian izin Info.plist (NSMotionUsageDescription).
  • Confidence: [Verified].

3. `AAINetwork` & `AAILiveness` (V3.0.7)

  • Tipe: Vendor SDK via tarball HTTP Aliyun OSS (.tar.bz2).
  • Fungsi: SDK deteksi keaslian wajah (Liveness Detection) dari Advance AI untuk kebutuhan e-KYC.
  • Komponen Konsumen: IDAuthLiveViewController.swift.
  • Runtime Impact: Membuka kamera depan dengan pemrosesan visi komputer intensif (CPU/GPU) untuk mendeteksi kedipan mata dan buka mulut.
  • Dampak Jika Gagal: Nasabah baru tidak dapat menyelesaikan tahap akhir e-KYC sehingga tidak bisa mendapatkan limit kuota.
  • Risiko Upgrade: Menengah. URL download berasal dari OSS Aliyun Indonesia; jika link mati, pod install akan gagal.
  • Confidence: [Verified].

4. `Alamofire`

  • Tipe: Open-Source HTTP Networking Library (Swift).
  • Fungsi: Mengelola session configuration, URLRequest building, header injection, dan stream data jaringan yang dibungkus oleh CZAlamofireBridge.
  • Komponen Konsumen: CZNetworkCenter.swift, IDNetworkRequest.swift.
  • Runtime Impact: Pengelolaan pool koneksi HTTP/1.1 dan HTTP/2.
  • Dampak Jika Gagal: Gagal melakukan request jaringan.
  • Confidence: [Verified].

5. `SnapKit` (`5.6.0`)

  • Tipe: Open-Source Auto Layout DSL (Swift).
  • Fungsi: Membangun 100% tampilan antarmuka (UI) secara programatik di seluruh modul native tanpa Storyboard.
  • Komponen Konsumen: Seluruh ViewController, View, dan TableViewCell di Application/.
  • Runtime Impact: Layout constraint solver saat rendering tampilan pertama kali.
  • Dampak Jika Gagal: Kompilasi gagal atau tampilan UI hancur.
  • Confidence: [Verified].

6. `KakaJSON` (`~> 1.1.2`)

  • Tipe: Open-Source Fast JSON Serialization / Deserialization (Swift).
  • Fungsi: Mengonversi JSON dictionary dari backend menjadi struct / class model Swift (kj.model).
  • Komponen Konsumen: Seluruh Service Layer di SamirMainModule, SamirLoanModule, SamirAuthModule, SamirRepayModule.
  • Runtime Impact: Serialisasi data berbasis pointer memory yang sangat cepat.
  • Dampak Jika Gagal: Response API gagal diparsing, menyebabkan tampilan data kosong.
  • Confidence: [Verified].

7. `RxSwift` & `RxCocoa` (`6.9.0`)

  • Tipe: Functional Reactive Programming Framework (Swift).
  • Fungsi: Mengelola state reaktif, stream kalkulasi biaya, dan binding UI khusus di dalam LoanConfirmModule.
  • Komponen Konsumen: LoanConfirmViewController_Rx.swift, LoanConfirmViewModel.swift.
  • Runtime Impact: Alokasi closure dan disposable bag pada memori.
  • Dampak Jika Gagal: Halaman konfirmasi pinjaman tidak dapat dibuka atau crash.
  • Confidence: [Verified].

8. `AppsFlyerFramework` (`6.17.7`)

  • Tipe: Marketing Attribution & Deep Linking SDK.
  • Fungsi: Mengatribusikan sumber instalasi aplikasi (iklan Google/Facebook/TikTok) dan mengurai deep link.
  • Komponen Konsumen: IDAppsFlyerManager.swift, IDSamirMainModule.swift.
  • Runtime Impact: Menghubungi server AppsFlyer saat aplikasi dibuka (applicationDidBecomeActive).
  • Dampak Jika Gagal: Kehilangan data atribusi pemasaran dan deep link iklan gagal membuka layar tujuan.
  • Confidence: [Verified].

9. `FirebaseAnalytics` & `FirebaseMessaging` (`11.14.0`)

  • Tipe: Google Mobile SDK.
  • Fungsi: Pelacakan event perilaku nasabah dan pengelolaan token push notification (FCM).
  • Komponen Konsumen: IDFirebaseManager.swift, IDFCMManager.swift, IDSamirMainModule.swift.
  • Dampak Jika Gagal: Notifikasi push promo dan pengingat jatuh tempo tidak sampai ke ponsel pengguna.
  • Confidence: [Verified].

10. `tingyunApp` (`2.17.7`)

  • Tipe: APM (Application Performance Monitoring) & Crash Logger SDK.
  • Fungsi: Memonitor latency jaringan, waktu startup, penggunaan memori, dan crash report ke dashboard Tingyun.
  • Komponen Konsumen: main.swift, TYUtils.swift.
  • Runtime Impact: Berjalan sejak detik ke-0 di main.swift.
  • Confidence: [Verified].

⚖️ F. Why It Matters: Risiko Menggunakan Pod Tarball Aliyun OSS

Perhatikan baris 50–51 di 🦊 ios/Podfile learn/iOS-Arch ↗:

pod 'AAINetwork', :http => 'https://prod-guardian-cv.oss-ap-southeast-5.aliyuncs.com/.../AAINetwork-V1.0.2-PrivacyInfo.tar.bz2', type: :tbz
pod 'AAILiveness', :http => 'https://prod-guardian-cv.oss-ap-southeast-5.aliyuncs.com/.../iOS-Liveness-SDK-V3.0.7.tar.bz2' , type: :tbz
  • Risiko Infrastruktur: Dependensi ini tidak diambil dari server resmi CocoaPods Trunk, melainkan langsung dari bucket cloud Aliyun OSS di kawasan Jakarta (ap-southeast-5).
  • Mitigasi: Jika bucket OSS tersebut mengalami gangguan akses atau file dihapus oleh vendor, seluruh tim pengembang tidak akan dapat menjalankan pod install. Tim mobile disarankan menyimpan backup tarball ini di internal artifact repository (seperti Nexus atau JFrog Artifactory).

🔬 G. Practical Example: Audit Transitive Dependency

Saat pod install dijalankan, pustaka seperti FirebaseAnalytics secara otomatis menarik puluhan sub-dependensi Google (seperti GoogleUtilities, nanopb, PromisesObjC). Hal ini berkontribusi pada ukuran biner aplikasi sekitar 40–50 MB saat dirilis ke App Store.

⚠️ H. Common Mistakes & Debugging

  • Menjalankan pod update Tanpa Konfirmasi:
  • Bahaya: Menjalankan pod update alih-alih pod install dapat menaikkan versi pustaka tanpa disengaja (misal: Kingfisher atau Firebase) yang dapat menimbulkan breaking changes pada kode Swift yang ada.
  • Aturan: Selalu gunakan pod install.
  • Arsitektur Framework Simulator (x86_64 vs arm64):
  • Framework binary closed-source (LibNetSignGenerator) kadang menimbulkan error linker saat dijalankan di Mac Apple Silicon jika skrip thinning lipo tidak berjalan sempurna. Pastikan Run Script fase 4 di Xcode tetap aktif.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
