04 — Shared Components & Services

Komponen Bersama & Layanan Lintas Modul

📚 Modul: 04-shared-components-and-services 🎯 Scope: SAMIR Mobile (iOS Native UIKit & FChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/iOS-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini mendokumentasikan secara rinci seluruh layanan bersama (shared services) di SamirServiceModule, pustaka komponen antarmuka bersama (CZSwiftUIKit), serta utilitas global (CZSwiftUtils) yang digunakan secara masif di seluruh modul SAMIR iOS.

Status Verifikasi: [Verified] (diverifikasi langsung dari implementasi class di SamirServiceModule, CZSwiftUIKit, dan CZSwiftUtils).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Memahami API surface dari 4 protokol layanan di SamirServiceModule (IDLoginModuleServiceProtocol, IDMainModuleServiceProtocol, IDLoanModuleServiceProtocol, IDRepayModuleServiceProtocol).
  2. Mengetahui komponen visual bersama di CZSwiftUIKit (Toast, Alert, EmptyView, HUD).
  3. Menggunakan utilitas helper di CZSwiftUtils (Debouncer, Thread Dispatcher, JSON converter, Logger).

📋 B. Prerequisites

  • Sudah membaca 01-architecture-overview.md hingga 03-dependency-direction.md.
  • Mengetahui cara kerja Service Locator di Swift.

💡 C. Simple Explanation (Analogi Kotak Perkakas Bersama)

Bayangkan sebuah bengkel besar dengan banyak mekanik yang bekerja pada bagian mobil yang berbeda:

  • Kotak Perkakas Dasar (CZSwiftUtils & CZSwiftUIKit): Obeng, tang, dan kunci pas standar yang boleh diambil oleh semua mekanik kapan saja (contoh: fungsi pemformatan mata uang Rupiah, animasi loading, tombol toast).
  • Meja Pusat Komunikasi (SamirServiceModule): Loket terpusat tempat para mekanik saling bertanya status ("Apakah sparepart sudah siap?", "Apakah pemilik mobil sudah melunasi deposit?").

Dengan meletakkan alat-alat ini di tempat bersama, mekanik tidak perlu membuat obeng atau tang baru untuk pekerjaannya sendiri.

Tersedia fasad singleton IDServiceManager untuk mengakses 4 protokol utama:

// IDServiceManager.swift
public class IDServiceManager: NSObject {
    public class func loginService() -> IDLoginModuleServiceProtocol?
    public class func mainService() -> IDMainModuleServiceProtocol?
    public class func loanService() -> IDLoanModuleServiceProtocol?
    public class func reapyService() -> IDRepayModuleServiceProtocol? // (Catatan typo historis: reapyService)

Rincian Fungsi Per Protokol:
ProtokolClass Handler KonkretMethod Kunci & Kemampuan
IDLoginModuleServiceProtocolIDLoginModuleServiceHandler- isLogin() -> Bool: Memeriksa status login.
- loginInfo() -> IDLoginCodeModel?: Data sesi user (mid, userNo, staticKey).
- loginAction(): Memunculkan modal popup login.
- reloginWhenRequestError(): Reset sesi saat token kedaluwarsa (error 10006).
- postLoginOutRequest(...): Logout server & lokal.
IDMainModuleServiceProtocolIDMainModuleServiceHandler- getAppConfig() -> IDAppConfigModel?: Konfigurasi global dari server.
- requstAppConfig(): Mengambil konfigurasi server terbaru secara async.
IDLoanModuleServiceProtocolIDLoanModuleServiceHandler- jumpLoanAssess(params): Memicu navigasi ke halaman penilaian limit kuota kredit.
- jumpLoanConfirm(params): Memicu navigasi ke halaman konfirmasi pencairan pinjaman.
IDRepayModuleServiceProtocolIDRepayModuleServiceHandler- jumpRepay(params): Memicu navigasi ke halaman tagihan/pelunasan.

[!NOTE] Typo Unik di Kode Sumber: Pada IDServiceManager.swift baris 33, method pengakses layanan tagihan bernama reapyService() (bukan repayService). Typo ini sudah menyebar di berbagai modul sehingga harus tetap digunakan sesuai aslinya untuk menjaga kompatibilitas kompilasi.

2. Pustaka Komponen UI Bersama (CZSwiftUIKit)

Path: 🦊 ios/IDSamirLoan/Application/CZSwiftUIKit/ learn/iOS-Arch ↗

Folder ini berisi fondasi antarmuka in-house yang sangat kaya:

  • CZCircleProgressView: Indikator lingkaran animasi untuk progres verifikasi KYC dan persentase skor kredit.

  • IDAlertView / IDNPopupController: Dialog modal konfirmasi kontrak, peringatan, dan popup interaktif.
  • IDEmptyView: Tampilan state kosong (empty data / network error) dengan tombol reload id_clickEmptyBlock.
  • Custom Font: MosnDigitBoldFont.otf (di folder Assets/) khusus untuk merender angka nominal pinjaman dan suku bunga dengan tipografi tebal khas finansial.
B. Pustaka Tooling UI (Classes/CZTools/)
  • CZWeakTimer: Pembungkus Timer / CADisplayLink dengan target lemah (weak reference proxy) untuk mencegah retain cycle dan memory leak saat polling.
  • CZDarkModeUtil & CZThemeProvider: Abstraksi pendeteksian mode gelap (Dark Mode) iOS 13+ dan penyedia palet warna dinamis.
  • CZWaterFallLayout: Layout custom UICollectionView berbasis grid air terjun (waterfall grid).
  • CZPhotoAlbumUtil: Utilitas seleksi foto galeri dan kamera dengan penanganan izin privasi runtime.

Seluruh utilitas UIKit SAMIR dibungkus dalam namespace khusus .cz.:

  • UIViewController.cz.topViewController(): Mencari ViewController teratas yang sedang aktif di layar secara rekursif (sangat vital untuk router dan dialog modal).
  • UIView.showToast(withMessage:): Menampilkan pop-up toast pesan singkat tanpa mengganggu interaksi UI utama.
  • UIColor.cz.colorWithHex(...): Parsing warna heksadesimal (misal: #00C288 untuk warna hijau SAMIR).
  • UIBarButtonItem.createCustomItem(...): Membuat tombol navigasi bar kustom dengan hit area (touch extend inset) yang nyaman disentuh.

3. Audit Arsitektur: Apakah IDNPopupConfig Sudah Best Practice?

Struktur konfigurasi popup terletak di 🦊 IDNPopup.swift:L113-142 learn/iOS-Arch ↗:

public struct IDNPopupConfig {
    public var bgColor: UIColor = IDThemeColor.PickerBgColor
    public var enableUserInteraction = true
    public var animationType: IDNPopupAnimationType = .dialog
    public var withoutAnimation = false
    public var isDismissible = true
    public var enableDrag = true
    public var direction: IDNPopupAnimationDirection = .unowned
    public var enableAutoDismiss = false
    public var autoDismissDuration: IDNTimerDuration = .seconds(value: 2)
    public var toastPosition: IDNToastPosition = IDNIsSupportDynamicIsLand ? .dynamicIsland : .center
    
    // Preset Static Styles
    public static var dialog = IDNPopupConfig(enableDrag: false)
    public static var bottomSheet = IDNPopupConfig(animationType: .bottomSheet)
    public static var drawer = IDNPopupConfig(animationType: .drawer, direction: .left)
}
A. Evaluasi Objektif:
  1. Sisi Positif:
  • Berbentuk struct (Value Type) sehingga memiliki semantik penyalinan (copy-on-write), mencegah mutasi data yang tidak disengaja antar instance individu.
  • Menyediakan preset bawaan yang memudahkan pemanggilan cepat (.dialog, .bottomSheet, .drawer).
  1. Kekurangan / Pelanggaran Best Practice (Code Smells):
  • static var Mutable Global State: Properti preset dideklarasikan sebagai static var (bukan static let). Jika ada kode yang menulis IDNPopupConfig.dialog.bgColor = .red, seluruh dialog di modul lain yang menggunakan preset tersebut akan ikut berubah warna secara global!
  • Typo pada API Publik: Banyak nama parameter dan variabel yang salah ketik pada layer animasi, seperti contianerView (seharusnya containerView) dan transitonContext (seharusnya transitionContext).
  • *Menemukan Kembali Roda (Reinventing the Wheel)*: IDNPopup menempelkan view secara manual di atas UIWindow / subview tree alih-alih mengadopsi standar resmi Apple seperti UISheetPresentationController (iOS 15+) atau UIViewControllerTransitioningDelegate. Ini memicu masalah pada adaptasi rotasi layar, VoiceOver accessibility, dan keyboard avoidance.
  • Kopling Global: Nilai default toastPosition terikat langsung ke konstanta global IDNIsSupportDynamicIsLand.
B. Refactoring Blueprint (Standar Modern):

Gunakan static let atau Factory Method, serta integrasikan dengan native presentation controller:

public struct IDNPopupConfig {
    // Gunakan static let untuk mencegah mutasi shared state
    public static let dialog = IDNPopupConfig(enableDrag: false)
    public static let bottomSheet = IDNPopupConfig(animationType: .bottomSheet)
    
    // Atau Builder Pattern / Factory Method
    public static func makeDefault() -> IDNPopupConfig { ... }
}

4. Bedah Arsitektur CZSwiftAntiFraudLib: Mengapa Pakai Objective-C?

Path: 🦊 ios/IDSamirLoan/Application/CZSwiftAntiFraudLib/ learn/iOS-Arch ↗

Modul ini merupakan pustaka hybrid (gabungan Swift dan Objective-C):

  • File Objective-C: CZCommonManager.m, CZDiskMemoryManager.m, NSData+CZEncryption.m.
  • File Swift: CZAntiFraudManager.swift, CZFpidManager.swift, CZDeviceManager.swift, CZJailbroken.swift.
A. Mengapa Menggunakan Objective-C?
  1. Akses Langsung ke BSD POSIX & Mach Kernel C-APIs:
  • Untuk mengumpulkan metrik keamanan hardware tingkat rendah (#include <mach/mach.h>, #include <sys/sysctl.h>, mach_absolute_time(), host_statistics), Objective-C dapat memanggil fungsi dan struct pointer C secara langsung tanpa overhead konversi.
  • Di Swift murni, pemanggilan pointer C seperti vm_statistics_data_t atau sysctl membutuhkan syntax unsafe pointer yang sangat verbose dan rentan crash jika alignment memory tidak presisi.
  1. Kriptografi Lawas & Operasi Buffer Memori:
  • NSData+CZEncryption.m membungkus pustaka C <CommonCrypto/CommonCryptor.h> untuk enkripsi AES secara cepat pada raw memory bytes.
  1. Pustaka Fingerprint Historis:
  • Modul deteksi anti-fraud perangkat fintech sering kali merupakan biner atau source code battle-tested yang diwarisi dari library C/ObjC lama.
B. Cara Kerja CZSwiftAntiFraudLib:
  1. *Pengumpulan Sinyal (Telemetry Harvesting)*: Mengukur persentase sisa memori RAM, kapasitas disk (czGetTotalDiskSpace), status baterai (UIDeviceBatteryState), waktu boot mesin (bootTime), dan kecerahan layar.
  2. Deteksi Root / Jailbreak (CZJailbroken.swift): Memeriksa keberadaan file mencurigakan (/Applications/Cydia.app, /bin/bash), permission menulis ke direktori terlarang /private, dan symbolic links.
  3. Penyimpanan Fingerprint: Menyimpan device token di iOS Keychain via CZKeychainManager.swift agar tetap bertahan saat aplikasi di-reinstall.
C. Cara Membuat Modul Serupa di Project Baru:
  • Opsi Modern (100% Swift):

Buat Swift Package / Framework, gunakan wrapper Swift modern untuk sysctl:

  var size = 0
  sysctlbyname("hw.machine", nil, &size, nil, 0)
  var machine = [CChar](repeating: 0, count: size)
  sysctlbyname("hw.machine", &machine, &size, nil, 0)
  let platform = String(cString: machine)

Gunakan CryptoKit bawaan Apple (AES.GCM) menggantikan CommonCrypto.

  • Opsi Hybrid (ObjC + Swift):
  1. Tambahkan file .m dan .h ke direktori proyek.
  2. Buka Project Settings -> Build Settings -> cari Objective-C Bridging Header.
  3. Daftarkan header .h tersebut (misal: CZCommonManager.h).
  4. Aktifkan Defines Module = YES agar class ObjC dapat dipanggil dari Swift via import YourModule atau langsung dikenali di satu target yang sama.

🪜 E. Step-by-Step Walkthrough: Cara Menggunakan IDServiceManager di Fitur Baru

Jika Anda sedang membuat fitur di SamirMineModule dan ingin memeriksa apakah user sudah login sebelum membuka halaman pengaturan rekening:

// 1. Import SamirServiceModule
import SamirServiceModule

// 2. Akses loginService melalui IDServiceManager
guard let loginService = IDServiceManager.loginService(), loginService.isLogin() else {
    // 3. Jika belum login, picu loginAction() modal
    IDServiceManager.loginService()?.loginAction()
    return
}

// 4. Jika sudah login, ambil informasi user
if let userInfo = loginService.loginInfo() {
    print("User No: \(userInfo.userNo ?? ""), Mobile: \(userInfo.mobile ?? "")")
    // Lanjutkan membuka layar rekening
}

⚖️ F. Why It Matters: Keuntungan Standarisasi Komponen Bersama

  • Konsistensi Tampilan (Design System):

Penggunaan CZSwiftUIKit memastikan warna tombol, font, sudut lengkung (border radius), dan gaya dialog popup seragam di seluruh modul dari Beranda hingga Akun Saya.

  • Mencegah Duplikasi Kode:

Fungsi-fungsi umum (seperti validasi regex nomor KTP atau pencarian top ViewController) terpusat di CZSwiftUtils, sehingga tidak ada tim yang membuat fungsi helper redundan.

🔬 G. Practical Example: Menggunakan Debouncer pada Tombol Ajukan

Untuk mencegah nasabah menekan tombol "Ajukan Pinjaman" berkali-kali secara cepat (yang dapat menghasilkan transaksi ganda di server):

// Menggunakan CZDebouncer di ViewController
private let debouncer = CZDebouncer(delay: 0.5)

@objc private func didTapSubmitButton() {
    debouncer.run { [weak self] in
        self?.presenter.submitLoanApplication()
    }
}

⚠️ H. Common Mistakes & Debugging

  • Lupa Menangani Kasus Handler nil:
  • Kesalahan: Menggunakan force-unwrap pada service: IDServiceManager.loginService()!.isLogin().
  • Bahaya: Jika runtime belum selesai menginisialisasi registry, aplikasi akan crash instan! Selalu gunakan optional chaining loginService()?.isLogin() ?? false.
  • Salah Panggil reapyService() vs repayService():
  • Ingat selalu nama method di IDServiceManager adalah reapyService().

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
