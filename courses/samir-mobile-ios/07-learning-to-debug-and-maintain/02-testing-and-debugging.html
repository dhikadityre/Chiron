Belajar Debugging & Maintenance — 02. Testing and Debugging

📚 Modul: 02-testing-and-debugging 🎯 Scope: SAMIR Mobile (iOS Native UIKit & FChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/iOS-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini membedah ekosistem pengujian (testing) dan metodologi debugging di codebase iOS SAMIR. Anda akan mempelajari realitas ketiadaan automated test suite, cara kerja floating debug console bawaan (DebugUI), teknik verifikasi signature API, hingga strategi observasi traffic jaringan.

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, Anda diharapkan mampu:

  1. Mengetahui status terkini arsitektur pengujian di SAMIR (ketiadaan target XCTest/automated unit testing).
  2. Memahami arsitektur dan lifecycle DebugUI, floating window logger in-app yang aktif pada build TEST.
  3. Mengoperasikan tab-tab logging: request, thirdEvent, realtimeEvent, dan console log.
  4. Menjalankan skenario debugging krusial: verifikasi API signature mismatch, inspeksi token autentikasi, pengujian deep link, dan isolasi crash.
  5. Menggunakan proxy debugging eksternal (Charles / Proxyman) secara efektif berdampingan dengan internal logging.

📋 B. Prerequisites

Sebelum membaca dokumen ini, Anda disarankan telah membaca:

  • 01-project-foundation/03-technology-stack-and-build.md — Memahami 4 Xcode scheme dan flag CZPreBuildMacro.cz_buildTest().
  • 06-understanding-data-and-dependencies/02-networking-and-api-flow.md — Memahami struktur envelope API, header, dan LibNetSignGenerator.
  • 07-learning-to-debug-and-maintain/01-error-handling.md — Memahami taksonomi kode error dan mapping network error.

💡 C. Simple Explanation: "Kotak Perkakas Lapangan Tanpa Lab Otomatis"

Bayangkan sebuah pesawat yang tidak memiliki simulasi uji coba otomatis di hanggar sebelum terbang (tidak ada unit test). Namun, teknisi memasang dashboard monitor portabel ekstra di kokpit (floating debug tool) yang menampilkan setiap kabel yang dialiri listrik dan setiap sensor yang mengirim sinyal saat pesawat sedang diterbangkan di udara.

Di SAMIR iOS:

  1. Tidak ada Unit Test atau UI Test otomatis yang dijalankan pada Xcode target maupun CI pipeline.
  2. Setiap kali Anda menjalankan build skema TEST, sebuah tombol oranye melayang (DataCollectDraggableButton) muncul di atas semua layar aplikasi.
  3. Mengetuk tombol tersebut akan membuka terminal log in-app yang mencegat semua request HTTP, response JSON, event tracking analitik (AppsFlyer/Burying Point), dan error console tanpa perlu menyambungkan kabel USB ke Xcode Console!

💻 D. Actual Implementation

1. Status Automated Testing: Zero Test Target [Verified]

Pemeriksaan pada IDSamirLoan.xcodeproj/project.pbxproj dan pencarian simbol XCTest membuktikan temuan penting:

  • Test Target: 0 target unit test (IDSamirLoanTests tidak ada).
  • UI Test Target: 0 target UI test (IDSamirLoanUITests tidak ada).
  • Konsekuensi: Kualitas rilis bergantung 100% pada Manual QA testing, exploratory testing, dan regression testing manual di lingkungan staging.

2. In-App Debug Console: Modul Debug & DebugUI [Verified]

Sistem debugging in-app terletak di direktori 🦊 ios/IDSamirLoan/Application/Debug/ learn/iOS-Arch ↗:

  • Manager/DebugUI.swift: Singleton pengelola lifecycle floating window dan interceptor.
  • Manager/DataCollectDebugLogManager.swift: In-memory log store dengan pembatasan jumlah item maksimum (default buffer).
  • Controller/DebugListViewController.swift: UI konsol log berisikan UISearchBar, segment picker, dan expandable table view.
  • View/DataCollectDraggableButton.swift: Tombol melayang oranye bebas digeser (pan gesture) di atas key window.

[!NOTE] Modul Debug Digunakan untuk Apa? Modul Debug adalah in-app developer & QA cockpit portabel. Tujuannya adalah mengeliminasi kebutuhan menyambungkan kabel USB ke Xcode atau memasang software proxy (Charles/Proxyman) saat testing di lapangan. Modul ini memungkinkan QA dan developer memeriksa secara instan di layar HP: 1. Apakah request HTTP berhasil dikirim beserta seluruh parameter dan kalkulasi sign. 2. Apakah response backend sesuai format yang diharapkan (200 vs 10006). 3. Apakah event analitik pihak ketiga (AppsFlyer, Facebook, TikTok) dan telemetri risiko SAMIR (burying points) terpicu dengan benar saat suatu tombol diklik.

Aktivasi Bersyarat (Scheme Guard)

Floating debug console tidak pernah tampil di skema PROD demi keamanan data pengguna. Inisialisasi dilakukan pada tab bar root:

  • Lokasi file: ios/IDSamirLoan/Application/SamirMainModule/Classes/IDController/IDMainTabBarController.swift:L39-41 
if CZPreBuildMacro.cz_buildTest() {
    DebugUI.setup()
}
Arsitektur Window Level

DebugUI membuat dua UIWindow khusus yang berdiri di atas keyWindow aplikasi normal:

+-------------------------------------------------------------+
| UIWindow (buttonFloatWindow, windowLevel = .alert + 2)      |  <-- Tombol oranye melayang (60x60)
+-------------------------------------------------------------+
| UIWindow (debugListFloatWindow, windowLevel = .alert + 1)   |  <-- Setengah layar atas: Konsol Log
+-------------------------------------------------------------+
| UIWindow (Main KeyWindow, windowLevel = .normal)            |  <-- Tampilan utama aplikasi SAMIR
+-------------------------------------------------------------+

Implementasi window pada DebugUI.swift:L57-79:

  • buttonFloatWindow.windowLevel = .alert + 2
  • debugListFloatWindow.windowLevel = .alert + 1 (ketinggian setengah layar: UIScreen.main.bounds.height / 2).

3. Kategori Log yang Dicegat (DataCollectType) [Verified]

Saat DebugUI.setup() dipanggil, tiga tipe log didaftarkan:

  1. DataCollectType.request:
    • Terpasang di IDNetworkRequest.swift:L746 (saat request dikirim dengan URL, parameter, dan header).
    • Terpasang di IDNetworkRequest.swift:L785 (saat response sukses berformat dictionary diterima).
    • Terpasang di IDNetworkRequest.swift:L843 (saat request gagal dengan error string).
  2. DataCollectType.thirdEvent:
    • Terpasang di IDDataReportUtils.swift:L54 saat event AppsFlyer atau vendor third-party lainnya dikirim.
  3. DataCollectType.realtimeEvent:
    • Terpasang di IDCustomPointNetworkManager.swift:L147 saat event tracking bisnis SAMIR (burying points / telemetry) ditembakkan ke endpoint analytics.
  4. DataCollectType.console:
    • Terpasang di DataLogConsole.swift:L53 untuk menangkap logging internal aplikasi.

🪜 E. Step-by-Step Walkthrough: Alur Melakukan Debugging di Lingkungan Nyata

Skenario: Menemukan Penyebab "Gagal Mengambil Kuota Pinjaman" pada Akun Test

  1. Langkah 1 — Jalankan Scheme TEST di Simulator atau Device Fisik:
    • Pastikan skema aktif adalah TEST (bukan PROD).
    • Setelah splash screen selesai dan masuk ke halaman login/home, perhatikan lingkaran oranye di sudut kiri atas layar.
  2. Langkah 2 — Reprodusir Masalah:
    • Masuk ke tab Home (Pinjaman), tarik ke bawah untuk refresh (pull-to-refresh).
    • Jika muncul toast error 99999 atau data kuota tidak berubah, jangan tutup aplikasi.
  3. Langkah 3 — Buka In-App Debug Console:
    • Ketuk lingkaran oranye DataCollectDraggableButton.
    • Window setengah layar DebugListViewController akan meluncur turun dari atas.
  4. Langkah 4 — Filter Log Request:
    • Pada baris segment atas (QTUISegmentView), pilih tab request.
    • Gunakan searchView dan ketik kata kunci endpoint, misalnya: getAppIndexNew atau borrow.
  5. Langkah 5 — Inspeksi Detail Request & Response:
    • Ketuk sel log yang bersangkutan. Sel akan membesar (ExpandableTableView).
    • Di dalam detail, periksa:
      • URL: Pastikan base URL mengarah ke server gateway dev (.../app/...).
      • Header: Periksa nilai token (apakah ada nilai hex MD5 atau string kosong), timestamp, dan sign.
      • Response Data: Periksa JSON body apakah code == 10006 (token kadaluarsa) atau code == 20001 (sedang ada order aktif).
  6. Langkah 6 — Salin Data untuk Tiket Bug:
    • Anda dapat memilih teks JSON respons langsung dari layar dan menyalinnya ke catatan pelaporan bug Jira/Slack.

🔬 G. Practical Example: Menelusuri Signature Mismatch Error (code: 10004)

Jika backend menolak permintaan dengan pesan error signature tidak valid:

  1. Pasang breakpoint di ios/IDSamirLoan/Application/SamirNetworkModule/Classes/Common/IDNetworkRequest.swift:L480 (sebelum pemanggilan generator signature).
  2. Periksa dictionary parameter yang dikumpulkan: 
   po params
  1. Periksa string signature yang dihasilkan oleh library LibNetSignGenerator: 
   po self.cz_requestSign
  1. Buka DebugUI pada perangkat, pilih tab request, lalu cocokkan apakah query parameters mengandung karakter khusus URL (+, /, =, spasi) yang tidak ter-encode dengan benar antara Swift URL encoding dan backend parser.

⚠️ H. Common Mistakes and Debugging

1. Tombol Debug Oranye Hilang atau Tertutup View

  • Gejala: Anda menjalankan skema TEST, tetapi tombol oranye DebugUI tidak muncul.
  • Penyebab:
    1. Anda login menggunakan skema PROD atau PROD-TEST di mana CZPreBuildMacro.cz_buildTest() bernilai false.
    2. Subview dari modal dialog native atau plugin third-party (seperti Advance AI liveness window) dibuat dengan UIWindow.windowLevel = .statusBar + 100, menutupi buttonFloatWindow.
  • Solusi: Pastikan skema aktif adalah TEST. Jika tertutup modal khusus, selesaikan alur modal terlebih dahulu agar window level kembali normal.

2. Traffic Flutter Tidak Muncul di DebugUI

  • Gejala: Saat membuka Tab "Bayar" (Repay) atau Tab "Saya" (Mine), aktivitas API tidak muncul di tab request DebugUI.
  • Penyebab: Tab Repay dan Mine dirender oleh Flutter engine. Jika request HTTP di dalam Flutter menggunakan package Dart http atau dio, request tersebut tidak melewati IDNetworkRequest.swift native iOS!
  • Solusi: Gunakan Charles / Proxyman dengan SSL Proxying terpasang pada simulator/device untuk memantau traffic jaringan Flutter secara terpadu.

3. Log Penuh dan Aplikasi Menjadi Patah-Patah (Lag)

  • Gejala: Scroll pada aplikasi tersendat setelah melakukan stress testing ratusan request.
  • Penyebab: Ukuran array di DataCollectDebugLogManager menumpuk tanpa batas pembersihan berkala.
  • Solusi: Buka konsol DebugUI, geser tab ke paling kanan, lalu ketuk Clear untuk mengosongkan buffer memori log.

  3. Mengapa tombol melayang debug menggunakan windowLevel = .alert + 2 daripada sekadar ditambahkan sebagai subview di keyWindow.rootViewController.view?

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
