04 — Navigation Conditions & Edge Cases

Penanganan Kasus Ekstrem

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini menjelaskan kondisi-kondisi khusus (guard conditions), skenario kegagalan navigasi, penanganan token kedaluwarsa (10006), resolusi deep link saat aplikasi dalam kondisi mati (cold start), serta percabangan navigasi yang digerakkan oleh server.

Status Verifikasi: [Verified] (diverifikasi langsung dari IDSamirMainModule.swift, IDNetworkRequest.swift, dan IDLoginModuleServiceHandler.swift).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Menjelaskan mekanisme automatic session recovery & re-login saat API mengembalikan error code 10006.
  2. Memahami bagaimana deep link ditunda (cached) saat cold start dan dieksekusi setelah launch view selesai.
  3. Menjelaskan perbedaan penanganan deep link tipe "1" (URL web) vs tipe "2" (rute bernama).
  4. Mengetahui mitigasi saat route URL server tidak terdaftar di router table aplikasi native.

📋 B. Prerequisites

  • Sudah membaca 02-navigation-fundamentals.md dan 03-complete-navigation-map.md.
  • Mengetahui konsep token JWT / session key dan notifikasi remote push.

💡 C. Simple Explanation (Analogi Tiket Masuk Kadaluwarsa di Tengah Wahana)

Bayangkan Anda berada di taman hiburan:

  • Anda sedang menaiki wahana permainan (misal: mengisi formulir pinjaman), tetapi tiba-tiba sistem mendeteksi tiket Anda sudah kedaluwarsa (Token Sesi Habis / Error 10006).
  • Alih-alih membiarkan Anda terjebak di tengah wahana dengan layar error, staf taman hiburan secara sopan mengantar Anda kembali ke pintu masuk (Reset ke Tab 0 Beranda) dan membukakan loket perpanjangan tiket (Modal Login Otomatis Muncul).
  • Jika Anda datang dari luar taman membawa selebaran promosi VIP (Deep Link Push Notification), sistem akan memastikan Anda sudah melalui pintu pemeriksaan tiket terlebih dahulu sebelum mengantar Anda langsung ke wahana yang dijanjikan di selebaran tersebut.

💻 D. Actual Implementation: Analisis Kasus Ekstrem

1. Skenario Token Sesi Kedaluwarsa (Error Code `10006`)

Path: 🦊 ios/IDSamirLoan/Application/SamirNetworkModule/Classes/Common/IDNetworkRequest.swift learn/iOS-Arch ↗ dan 🦊 SamirLoginModule/Classes/IDPresenter/IDLoginModuleServiceHandler.swift learn/iOS-Arch ↗

Ketika sebuah request API backend mengembalikan status code == "10006":

  2. Pembersihan State: IDLoginManager.removeUserInfoWhenLoginOut() menghapus file sesi pengguna (idn_userFile.plist), menghapus kunci di UserDefaults (idn_mid, idn_mobile, BIZ_ID), dan mereset status SDK pihak ketiga.
  3. Penyelamatan Navigasi:
  • IDSamirMainModuleRouterHandler dipanggil untuk mengembalikan seleksi tab ke Tab 0 (samir://main/tab?tab=home).
  • loginAction() dipanggil seketika untuk memunculkan modal login agar pengguna cukup memasukkan OTP tanpa harus menutup paksa aplikasi.

2. Skenario Resolusi Deep Link (AppsFlyer & Push Notification)

Path: 🦊 ios/IDSamirLoan/Application/SamirMainModule/Classes/IDModule/IDSamirMainModule.swift learn/iOS-Arch ↗

Aplikasi menerima deep link dari dua saluran utama:

  • AppsFlyer: Callback didResolveDeepLink (dari iklan Facebook/TikTok/Google Ads).
  • Push Notification: Callback userNotificationCenter(_:didReceive:) (dari push promo/pengingat tagihan).

Kedua saluran meneruskan payload ke fungsi sentral:

handleDeepLink(link: String?, linkType: String?)

Tipe Deep Link (linkType)Makna & Format NilaiPerilaku Navigasi
"1" (Web URL)URL HTTP / HTTPS (misal: https://m.samir.co.id/samir/repay/detail?bizId=...)Membuka IDBusinessWebViewController dengan metode loadUrlWithAuth (token login otomatis disuntikkan).
"2" (Named Route)Kode string nama rute:
- repay_list
- repay_detail
- homepage
- couponpage
- confirmpage		- repay_list: Pindah ke Tab 1 (Tagihan).
- repay_detail: Ambil bizId terbaru -> Buka web tagihan.
- homepage: Pindah ke Tab 0 (Beranda).
- couponpage: Buka kupon voucher (wajib login).
- confirmpage: Pindah ke beranda & siarkan notifikasi AFyerDeepLinkNotify.
Penanganan Cold Start (Aplikasi Belum Siap):

Jika deep link tiba saat aplikasi baru saja dinyalakan (cold start), UI TabBar belum siap di memori.

  • handleDeepLink menyimpan link di cache:
  UserDefaults.standard.set(link, forKey: "Samir_DeepLink_Str")
  UserDefaults.standard.set(linkType, forKey: "Samir_DeepLink_Type")
  • Setelah IDLaunchViewController selesai hitung mundur (atau user tap "Lewati"), method finishLaunch() membaca cache ini dan mengeksekusi navigasi yang tertunda.
  • Fungsi clearPushCache() dipanggil untuk memastikan deep link yang sama tidak dieksekusi dua kali.

3. Skenario Rute Ditolak / Tidak Ditemukan (`NotFound`)

Ketika server mengirimkan rute URL baru yang belum dikenal oleh aplikasi native yang sedang berjalan:

  1. CZRouterCenter.perform mengeksekusi matches(router).
  2. Jika regex path tidak cocok dengan tabel router modul mana pun, CZRouterCenter mengembalikan CZRouterResponse.initWithStatus(.NotFound).
  3. Aplikasi tidak melakukan crash; eksekusi navigasi dibatalkan secara aman dan dicatat di log debug console.

⚖️ F. Why It Matters: Race Condition pada Penundaan Push Notification

Di dalam 🦊 ios/IDSamirLoan/Application/SamirMainModule/Classes/IDModule/IDSamirMainModule.swift learn/iOS-Arch ↗:

DispatchQueue.main.asyncAfter(deadline: .now() + 0.3) {
    self.handleDeepLink(link: action, linkType: actionType)
}

Penundaan 0.3 detik ini sengaja ditambahkan oleh developer terdahulu untuk memastikan hierarki window.rootViewController sudah selesai melakukan transisi layout sebelum modal atau rute baru didorong ke navigation stack. Tanpa penundaan ini, iOS dapat membatalkan transisi navigasi (Unbalanced calls to begin/end appearance transitions).

🔬 G. Practical Example: Guard Condition pada Alur Flutter

Di layer hybrid Flutter (FlutterNativeChannel+route.swift baris 160–168), setiap rute yang membutuhkan login dilindungi:

private func isLoginRequiredNativeRoute(_ url: String) -> Bool {
    let routes: Set<String> = [
        IDRouterSchemeConstants.Mine.infoAuthList.rawValue,
        IDRouterSchemeConstants.Mine.setting.rawValue
    ]
    return routes.contains(url)
}

Jika seorang tamu mencoba membuka pengaturan atau data pribadi dari tab Flutter, native runtime akan mencegat navigasi tersebut dan menyajikan dialog login terlebih dahulu.

⚠️ H. Common Mistakes & Debugging

  • Bahaya Penggunaan Kode 10006 Sembarangan di Backend:
  • Jika backend engineer membuat endpoint baru dan menggunakan kode 10006 untuk error selain sesi kedaluwarsa (misal: "Saldo tidak mencukupi"), aplikasi iOS akan OTOMATIS ME-LOGOUT PENGGUNA DAN MERESET KE BERANDA!
  • Aturan: Pastikan tim backend hanya menggunakan kode 10006 murni untuk Expired Token / Invalid Session.
  • Deep Link Loop:
  • Lupa memanggil clearPushCache() setelah memproses deep link dapat menyebabkan aplikasi terus-menerus membuka layar yang sama setiap kali kembali ke foreground.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Tight Coupling pada Antarmuka Routing & Hardcoded String Paths

Navigasi antar layar dan pembukaan modal masih mengandalkan string URL scheme atau navigasi langsung controller-ke-controller, menyulitkan pelacakan dependensi dan memicu runtime crash jika parameter route tidak valid.

⚠️ Smells 2: Pencampuran Presentasi UI dengan Koordinasi Rute (Melanggar SRP)

ViewController atau Widget UI mengetahui secara langsung hierarki layar berikutnya dan cara menyajikannya (push vs present modal), mengurangi reusabilitas tampilan pada modul lain.

🚀 Blueprint Refactoring Standar Industri: Pola Navigation Coordinator & Typed Route Handlers

Mengabstraksikan seluruh orkestrasi layar ke dalam modul Coordinator independen. UI hanya memancarkan event intent navigasi tanpa mengetahui implementasi rute konkret.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol Coordinator: AnyObject {
    var navigationController: UINavigationController { get set }
    func start()
}

public final class RepayFlowCoordinator: Coordinator {
    public var navigationController: UINavigationController
    public init(navigationController: UINavigationController) {
        self.navigationController = navigationController
    }
    public func start() {
        let vc = IDRepayViewController()
        navigationController.pushViewController(vc, animated: true)
    }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:

Kuis 1 (Memory Recall): Apa bahaya utama dari menggunakan hardcoded URL scheme string di seluruh navigasi layar?

Kuis 2 (Architectural Decision): Bagaimana pola Coordinator membantu memisahkan tanggung jawab (SRP) pada ViewController atau Widget?

Kuis 3 (Debugging & Maintenance): Apa yang harus dilakukan saat deep link masuk saat otentikasi pengguna belum selesai diverifikasi?
