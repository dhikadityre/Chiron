02 — Navigation Fundamentals

Mekanisme Router Berbasis URL

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini menjelaskan fondasi sistem navigasi di SAMIR iOS: pustaka CZSwiftRouterLib, fasad IDRouterManager, anatomi URL scheme samir://, pencocokan regex pada CZRouterTable, hingga eksekusi pushViewController pada topViewController.

Status Verifikasi: [Verified] (diverifikasi langsung dari implementasi CZRouterCenter.swift, CZRouter.swift, dan IDRouterManager.swift).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Memahami siklus pemrosesan URL dari string teks hingga transisi ViewController.
  2. Menjelaskan komponen URL: scheme (samir), host (nama domain modul), dan path (tujuan layar).
  3. Memahami peran CZRouterTable, filter route sebelum pencocokan (routerFilters), dan penanganan parameter URL.
  4. Mengetahui bahaya assertion fatal pada penambahan host router duplikat.

📋 B. Prerequisites

  • Sudah membaca 01-feature-inventory.md.
  • Memahami konsep URL Scheme dan regular expression (regex) dasar.

💡 C. Simple Explanation (Analogi Kantor Pos & Alamat Surat)

Bayangkan sistem pengiriman surat pos internal:

  • Format Alamat (samir://auth/identity?step=1):
    • samir://: Kode negara pengiriman (Scheme aplikasi).
    • auth: Nama kota tujuan (Host / Modul Autentikasi).
    • /identity: Nama jalan dan nomor rumah tujuan (Path / Halaman Foto KTP).
    • ?step=1: Surat lampiran khusus (Parameter data).
  • Kantor Pos Pusat (CZRouterCenter): Membaca alamat surat. Jika ada alamat khusus dari mitra luar negeri, kantor pos menerjemahkannya ke rute internal terlebih dahulu (Route Filter).
  • Kurir Wilayah (IDSamirAuthModuleRouterHandler): Setelah surat tiba di kota auth, kurir wilayah membuka paket, menyiapkan mobil (IDNewOCRViewController), dan mengantar surat ke penerima (pushViewController).

1. Anatomi Format URL SAMIR

URL router SAMIR mengikuti standar RFC 3986:

  samir://       auth        /identity       ?isEdit=1&step=1
    ▲             ▲              ▲                  ▲
  Scheme         Host           Path              Query Params
 (Tetap)     (Nama Modul)  (Layar Spesifik)    (Kamus Parameter)

Konstanta seluruh rute didefinisikan secara strongly-typed di 🦊 IDRouterConstants.swift learn/iOS-Arch ↗:

public struct IDRouterSchemeConstants {
    public enum Auth: String {
        case identity = "samir://auth/identity"
        case personInfo = "samir://auth/personinfo"
        case careerInfo = "samir://auth/careerInfo"
        case contacts = "samir://auth/contacts"
        case bankCard = "samir://auth/bankcard"
        case changeCard = "samir://auth/changeCard"
        case face = "samir://auth/face"
    }
    public enum Loan: String {
        case confirm = "samir://loan/confirm"
        case creditAssess = "samir://loan/creditAssess"
        case voucherSelect = "samir://loan/voucherSelect"
    }
    public enum Main: String {
        case tab = "samir://main/tab"
    }
    public enum Web: String {
        case open = "samir://web/open"
    }
    // ... rute lainnya
}

2. Pendaftaran Router di Modul (CZRouterTable)

Setiap modul yang ingin menyediakan navigasi mengimplementasikan method routers() dari CZModuleProtocol. Contoh pada SamirAuthModule:

// IDSamirAuthModule.swift
func routers() -> [CZRouter] {
    let router = CZRouter.initWithSchemes(["samir"], withHostParttern: "auth")
    let routerTable = CZRouterTable()
    let paths = [
        IDSamirAuthRouterPath.Identity,
        IDSamirAuthRouterPath.PersonInfo,
        IDSamirAuthRouterPath.CareerInfo,
        // ...
    ]
    let handler = IDSamirAuthModuleRouterHandler()
    for path in paths {
        routerTable.registerHandler(handler, forPathPattern: path)
    }
    router?.addRouterTable(routerTable)
    return [router!]
}

3. Bedah Pustaka CZSwiftRouterLib & Fungsi CZRouter

Path: 🦊 ios/IDSamirLoan/Application/CZSwiftRouterLib/ learn/iOS-Arch ↗

CZSwiftRouterLib adalah pustaka router in-house berbasis URL Scheme yang menjadi tulang punggung navigasi ter-decouple di SAMIR iOS.

A. Untuk Apa CZRouter Digunakan?

CZRouter menyelesaikan masalah ketergantungan silang (circular dependency) antar modul:

  1. Decoupling Antar Modul: Halaman Beranda (SamirMainModule) dapat membuka formulir OCR KTP (SamirAuthModule) atau halaman pengajuan pinjaman (SamirLoanModule) tanpa perlu meng-import class IDNewOCRViewController atau IDLoanViewController.
  2. Deep Linking Universal: Format URL internal (samir://auth/identity) identik dengan URL skema dari push notification, SMS kampanye, maupun halaman web H5 hybrid, sehingga satu engine router melayani seluruh sumber navigasi.
  3. *Penyaringan Rute Terpusat (Route Filter): Kemampuan memetakan alias URL atau mengalihkan (redirect*) rute sebelum handler dijalankan.
B. Komponen Utama di dalam CZSwiftRouterLib:
  1. CZRouter:
    • Merepresentasikan konfigurasi rute untuk satu host tertentu (misal host: "auth", schemes: ["samir"]).
    • Menyimpan koleksi tables: [CZRouterTable].
  2. CZRouterTable:
    • Tabel pencocokan rute. Memetakan pola string/regex path (misal: "/identity") ke objek handler yang sesuai.
  3. CZRouterCenter:
    • Singleton pusat registrasi (CZRouterCenter.shared). Mengumpulkan semua instance CZRouter dari berbagai modul saat startup aplikasi via CZModuleManager.
    • Mengekspos method open(request: CZRouterRequest) dan mengarahkan URL ke tabel yang cocok.
  4. CZRouterRequest & CZRouterResponse:
    • DTO pembungkus parameter URL query, userInfo dictionary, dan callback completion handler.
  5. CZRouterSyncHandlerProtocol & CZRouterAsyncHandlerProtocol:
    • Kontrak yang wajib diimplementasikan oleh setiap handler modul (seperti IDSamirAuthModuleRouterHandler) untuk mengeksekusi transisi UI (pushViewController atau present).

4. Fasad Pemanggilan (IDRouterManager)

Path: 🦊 ios/IDSamirLoan/Application/SamirRouterModule/Classes/IDRouterManager.swift learn/iOS-Arch ↗

Daripada memanggil pustaka internal CZRouterCenter secara langsung, semua pemanggil menggunakan fasad statis IDRouterManager:

IDRouterManager.id_perfromWithURLString("samir://auth/identity", params: ["isEdit": "1"])

5. Resolusi UI & Penampilan Layar

Di dalam class Handler (contoh: IDSamirAuthModuleRouterHandler.swift baris 142–146):

func openVC(_ vc: UIViewController) {
    if let nav = vc.cz.topViewController()?.navigationController {
        nav.pushViewController(vc, animated: true)
    }
}

Helper vc.cz.topViewController() secara cerdas mencari ViewController teratas di layar tanpa memerlukan passing referensi self dari pemanggil!

🪜 E. Step-by-Step Walkthrough: Alur Navigasi Server-Driven

Salah satu keunggulan terbesar URL Router adalah Navigasi yang Digerakkan Server (Server-Driven Navigation):

  1. Server Mengirim Payload: Saat memuat data Beranda (requstQueryJumpRouter), backend mengirim payload tombol JSON: 
   {
       "buttonText": "Verifikasi Identitas Sekarang",
       "jumpUrl": "samir://auth/identity?step=1"
   }
  1. Tombol Diklik: Pengguna mengklik tombol di Beranda.
  2. Eksekusi Router: IDHomeViewController tidak perlu mengetahui logika if/else halaman apa yang harus dibuka; ia cukup meneruskan string tersebut: 
   IDRouterManager.id_perfromWithURLString(jumpUrl)
  1. Pencocokan Otomatis: CZRouterCenter otomatis mencocokkan jumpUrl ke modul Auth dan membuka layar KTP.
  2. Dampak Bisnis: Tim produk dan tim backend dapat mengubah alur perjalanan pengguna (misal: mengarahkan user lama langsung ke konfirmasi pinjaman dan user baru ke verifikasi identitas) murni dari response server tanpa perlu merilis pembaruan aplikasi ke App Store!

⚖️ F. Why It Matters: Bahaya Assertion Fatal pada Host Duplikat

Perhatikan kode kritis di 🦊 CZRouterCenter.swift learn/iOS-Arch ↗:

public func addRouter(_ router: CZRouter?) {
    guard let router = router else { return }
    assert(!self.isDuplicateRouter(router), "Duplicate router: \(String(describing: router.hostParttern))")
    self.routers.append(router)
}

[!WARNING] Trap / Jebakan Kritis Developer Baru: CZRouterCenter menggunakan instruksi assert yang memeriksa apakah pola host sudah pernah didaftarkan sebelumnya. Jika dua modul mendaftarkan host yang sama (misal: Modul A dan Modul B sama-sama mendaftarkan withHostParttern: "repay"), aplikasi akan LANGSUNG CRASH DI DEBUG DENGAN PESAN FATAL: Duplicate router: repay. Setiap modul bisnis wajib memiliki nama host yang unik!

🔬 G. Practical Example: Membuka Halaman Web H5 Melalui Router

Untuk membuka halaman FAQ web dengan otentikasi login:

let faqUrl = "https://m.samir.co.id/samir/faq"
IDBusinessWebViewController.loadUrlWithAuth(
    targetUrl: faqUrl,
    title: "Pusat Bantuan",
    canGoBack: true

Method helper ini secara internal membungkus URL dengan token login dan memicu:

IDRouterManager.id_perfromWithURLString(
    IDRouterSchemeConstants.Web.open.rawValue, 
    params: ["url": authenticatedUrl, "navTitle": "Pusat Bantuan"]
)

⚠️ H. Common Mistakes & Debugging

  • Typo pada Skema atau Host:
    • Memanggil samir://atuh/identity (typo atuh alih-alih auth).
    • Efek: CZRouterCenter tidak menemukan handler yang cocok dan mengembalikan response status .NotFound. Navigasi gagal secara diam-diam tanpa ada pesan error di layar.
  • Lupa Encoding Parameter String:
    • Jika mengirimkan URL di dalam parameter query (misal: samir://web/open?url=https://samir.co.id?a=1&b=2), karakter & dan ? akan merusak parser URL query. Selalu gunakan URL-encoding untuk nilai parameter.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Tight Coupling pada Antarmuka Routing & Hardcoded String Paths

Navigasi antar layar dan pembukaan modal masih mengandalkan string URL scheme atau navigasi langsung controller-ke-controller, menyulitkan pelacakan dependensi dan memicu runtime crash jika parameter route tidak valid.

⚠️ Smells 2: Pencampuran Presentasi UI dengan Koordinasi Rute (Melanggar SRP)

ViewController atau Widget UI mengetahui secara langsung hierarki layar berikutnya dan cara menyajikannya (push vs present modal), mengurangi reusabilitas tampilan pada modul lain.

🚀 Blueprint Refactoring Standar Industri: Pola Navigation Coordinator & Typed Route Handlers

Mengabstraksikan seluruh orkestrasi layar ke dalam modul Coordinator independen. UI hanya memancarkan event intent navigasi tanpa mengetahui implementasi rute konkret.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol Coordinator: AnyObject {
    var navigationController: UINavigationController { get set }
    func start()
}

public final class RepayFlowCoordinator: Coordinator {
    public var navigationController: UINavigationController
    public init(navigationController: UINavigationController) {
        self.navigationController = navigationController
    }
    public func start() {
        let vc = IDRepayViewController()
        navigationController.pushViewController(vc, animated: true)
    }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:
