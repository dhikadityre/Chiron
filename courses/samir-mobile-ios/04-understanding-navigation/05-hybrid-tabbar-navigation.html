05 — Hybrid TabBar & Flutter Persistent Host

Arsitektur Single Flutter Engine, Dynamic Chrome Sync & Anti-Race Tab Switching

📚 Modul: 05-hybrid-tabbar-navigation 🎯 Scope: SAMIR Mobile (iOS Native UIKit & Flutter Channel) ⏱️ Estimasi: 25 Menit 🏷️ Git Branch: learn/iOS-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini mengupas secara tuntas arsitektur navigasi hybrid pada SAMIR iOS: bagaimana satu buah FlutterEngine digunakan bersama oleh beberapa tab native (Tagihan dan Saya), bagaimana sinkronisasi visibilitas UITabBar dilakukan secara dinamis, serta perbedaan mendasar antara showRoot dan showPage dalam mencegah layar berkedip (flicker) dan race condition.

Status Verifikasi: [Verified] (diverifikasi langsung dari IDMainTabBarController.swift, FlutterEngineManager.swift, FlutterNativeChannel+route.swift, dan flutter_native_route_dispatcher.dart).

🎯 A. Learning Objective

Setelah mempelajari modul ini, Anda akan mampu:

  1. Menjelaskan konsep Single Persistent Flutter Host (Overlay Pattern) dan membongkar mitos bahwa Flutter memiliki TabBar tersendiri.
  2. Membedakan penggunaan showRoot vs showPage serta implikasinya terhadap IndexedStack dan Navigator stack Flutter.
  3. Memahami mekanisme setNativeTabBarHidden dalam menyembunyikan TabBar native saat membuka sub-halaman Flutter secara full-screen.
  4. Menjelaskan peran Monotonic Request ID dalam menangkal race condition saat pengguna berpindah tab secara cepat.
  5. Mengidentifikasi titik rawan kebocoran memori, stale state pada singleton, dan desinkronisasi safe area layout.

📋 B. Prerequisites

  • Sudah membaca 02-navigation-fundamentals.html (URL Router).
  • Memahami konsep dasar UITabBarController di UIKit iOS.
  • Memahami konsep dasar Flutter Platform Channel (MethodChannel).

💡 C. Simple Explanation (Analogi Mall Modern dengan Bioskop IMAX Terintegrasi)

Bayangkan Anda mengunjungi sebuah Mall Perbelanjaan:

  • Lantai Dasar Mall (Native UITabBar): Mall memiliki papan navigasi dan lift utama yang membawa Anda ke 3 zona: Zona 1 (Toko Retail Native), Zona 2 (Bioskop IMAX Hall A - Tagihan), dan Zona 3 (Bioskop IMAX Hall B - Saya).
  • Satu Proyektor IMAX Raksasa (Single Flutter Engine): Pihak mall tidak membeli dua proyektor terpisah untuk Hall A dan Hall B karena sangat mahal dan boros listrik (boros RAM). Mereka menggunakan satu proyektor pusat yang sama.
  • Tirai Proyektor (Overlay Container): Ketika Anda pindah ke Toko Retail Native, tirai proyektor ditutup (container.isHidden = true) dan lampu proyektor diredupkan (engine.inactive). Ketika Anda pindah ke bioskop, tirai baru dibuka setelah gambar film berikutnya siap tayang (frameReady).
  • Menonton Film Full-Screen (Sub-Halaman Flutter): Ketika Anda memilih untuk menonton film dokumenter khusus di dalam bioskop (masuk ke /mine/personal), petugas bioskop memadamkan lampu koridor mall dan menutup akses lift (setNativeTabBarHidden = true) agar Anda fokus menonton dalam mode layar penuh tanpa gangguan visual.

💻 D. Actual Implementation: Analisis Arsitektur Terpadu

1. Koreksi Arsitektural: Mitos Dua TabBar

Banyak developer mengira Flutter merender bottom navigation bar-nya sendiri. Faktanya: Hanya ada 1 TabBar fisik di layar, yaitu Native UITabBar.

Di 🦊 IDMainTabBarController.swift learn/iOS-Arch ↗, UITabBarController mendaftarkan 3 child controller:

Index Tab Judul Tab ViewController Terdaftar Sifat Layar
Tab 0 Beranda IDHomeViewController Native UIKit Murni
Tab 1 Tagihan IDRepayViewController Placeholder / Sentinel VC
Tab 2 Saya IDMineViewController Placeholder / Sentinel VC

View Flutter disisipkan sebagai Overlay Tunggal tepat di bawah native tabBar:

// IDMainTabBarController.swift - installPersistentFlutterHost()
flutterContainerView.isHidden = true
view.insertSubview(flutterContainerView, belowSubview: tabBar)
view.bringSubviewToFront(tabBar)

2. Mengapa Ada Dua Tipe: showRoot vs showPage?

Pemisahan ini adalah kunci kebersihan arsitektur hybrid SAMIR:

Dimensi showRoot(route, requestID) showPage(route, presentation)
Tujuan Beralih antar tab root (/mine atau /repay) Membuka halaman formulir/detail anak (misal /mine/personal)
Struktur di Flutter Mengubah IndexedStack di FlutterRootPage.dart Menumpuk ke dalam Navigator Stack (Routers.push)
Riwayat Back (Stack) Tidak menambah history back Menambah history (muncul tombol Back di AppBar)
Sinkronisasi Frame Wajib Sinkron (menunggu frameReady dari GPU) Asinkron (mengikuti transisi slide push standar)
Native TabBar Tetap Ditampilkan (di bagian bawah) Disembunyikan Otomatis (tampil layar penuh)
💡 Mental Model Kunci: Analogi hidesBottomBarWhenPushed iOS Native

Cara paling sederhana dan intuitif memahami perbedaan ini dari sudut pandang iOS Engineer:

  • showRoot (Mode Tab): Karena pengguna masih berada di level menu utama, mereka masih membutuhkan TabBar native untuk berpindah tab → TabBar TIDAK di-hide, dan tinggi layar Flutter dibatasi tepat di atas TabBar (frame.height = tabBarTop - bounds.minY).
  • showPage (Mode Halaman Anak / Full-Screen): Pengguna masuk ke halaman detail/formulir, sehingga ekspektasi UX adalah tampilan layar penuh → TabBar native WAJIB di-hide, dan frame Flutter diperluas 100% memenuhi layar (view.bounds). Navigasi kembali diserahkan ke tombol Back di AppBar.

Pada UIKit konvensional, perilaku showPage ini setara persis dengan menyetel: childVC.hidesBottomBarWhenPushed = true. Namun karena Flutter berjalan di atas satu View Controller persisten yang sama (Single Persistent Host), efek tersebut disimulasikan secara dinamis melalui sinyal Platform Channel setNativeTabBarHidden = true.

3. Mekanisme Anti-Flicker & Monotonic Request ID

Ketika berpindah ke tab Flutter, native tidak langsung menampilkan view. Flutter diinstruksikan menggambar frame visual terlebih dahulu:

// flutter_native_route_dispatcher.dart - _showRootTab()
WidgetsBinding.instance.ensureVisualUpdate();
await WidgetsBinding.instance.endOfFrame; // Tunggu GPU menyelesaikan frame visual
return <String, Object?>{
  'requestId': requestId,
  'frameReady': isLatest && isSelected,
};

Di sisi iOS, respons divalidasi terhadap ID permintaan terbaru untuk mencegah race condition saat pengguna mengetuk tab secara agresif:

// IDMainTabBarController.swift - switchFlutterRoot()
guard responseID == self.flutterRootRequestID,
      route == self.currentFlutterRoot else {
    return // Abaikan respons lama yang terlambat datang
}
self.flutterContainerView.isHidden = false
FlutterEngineManager.shared.setPersistentRootVisible(true)

4. Dynamic Chrome Sync: Sembunyi-Muncul TabBar Otomatis

Di Flutter, class 🦊 native_route_chrome.dart learn/iOS-Arch ↗ bertindak sebagai NavigatorObserver:

  • Saat halaman non-root di-push (misal /mine/personal): Observer mendeteksi rute keluar dari boundary root, lalu mengirim event setNativeTabBarHidden(true).
  • Native mengeksekusi: tabBar.isHidden = true dan mengubah ukuran frame flutterContainerView menjadi view.bounds (layar penuh hingga dasar).
  • Saat pengguna menekan tombol Back dan kembali ke /mine: Observer mendeteksi rute kembali ke root, lalu memanggil setNativeTabBarHidden(false). TabBar native muncul kembali secara instan.

⚖️ F. Why It Matters: Analisis Tradeoff Arsitektur

Aspek Arsitektur Keunggulan (Pros) Konsekuensi & Beban (Cons)
Single Shared Engine Hemat RAM drastis (~35 MB konstan), warm-up engine hanya 1 kali saat startup. Engine tetap memakan memori di background saat user di tab Beranda (Native).
Native TabBar Shell UI terasa 100% native Apple, mendukung dynamic font, safe area insets, dan haptic feedback standar. Perlu sinkronisasi layout manual (updatePersistentFlutterHostLayout) dan safe area bridge.
Monotonic Request ID Mencegah layar tertukar atau salah konten akibat race condition tab switching yang sangat cepat. Menambah kompleksitas callback completion dan tracking state integer di Swift & Dart.

⚠️ H. Common Mistakes & Debugging Gotchas

  1. TabBar Menghilang Permanen Setelah Navigasi:
    Penyebab: User menavigasi ke halaman Flutter yang rutenya tidak terdaftar di RootRoutes.tabPaths, sehingga saat kembali ke root, event setNativeTabBarHidden(false) tidak pernah dikirim.
    Solusi: Pastikan setiap rute root baru didaftarkan di RootRoutes.dart, dan selalu panggil prepareNativeChromeForTabSelection() setiap kali tab native dipilih.
  2. Layar Blank Putih Saat Pindah ke Tab Flutter:
    Penyebab: FlutterEngineManager.shared.resume() lupa dipanggil, menyebabkan Flutter Engine tertidur dalam status AppLifecycleState.inactive.
    Solusi: Pastikan method resume() selalu dijalankan sebelum mengirim event showRoot atau showPage.
  3. Konten Terpotong di Bagian Bawah Layar:
    Penyebab: updatePersistentSafeArea tidak dipanggil setelah perubahan visibilitas TabBar.
    Solusi: Selalu sinkronkan bottom insets di updatePersistentFlutterHostLayout() dengan menghitung selisih antara frame.maxY dan safeAreaLayoutGuide.layoutFrame.maxY.

🏛️ Bagian 2: Architecture Lab & Audit

Engineering Evaluation

1. Audit SOLID & Clean Architecture

Prinsip Status Catatan Temuan Implementasi
SRP (Single Responsibility) ⚠️ Perlu Perhatian IDMainTabBarController merangkap tugas layouting, hosting Flutter, observer lifecycle app, dan routing sub-halaman. Idealnya logika persistent host dipisahkan ke FlutterHostCoordinator.
OCP (Open/Closed) ⚠️ Perlu Perhatian Penambahan tab Flutter baru masih membutuhkan modifikasi hardcoded pada flutterRootRoute(for:) dan pengecekan tipe class (is IDMineViewController).
LSP (Liskov Substitution) ✅ Bagus SamirFlutterViewController mewarisi FlutterViewController secara tepat tanpa melanggar kontrak superclass.
ISP (Interface Segregation) ✅ Bagus Protokol FlutterPersistentHostControlling membatasi API yang diekspos ke engine manager hanya pada fungsi-fungsi yang benar-benar dibutuhkan.
DIP (Dependency Inversion) ⚠️ Perlu Perhatian Penggunaan singleton konkret FlutterEngineManager.shared dan FlutterNativeChannel.shared di banyak tempat menyulitkan pembuatan unit test terisolasi.

2. Refactoring Blueprint: Menuju Clean Architecture

Untuk meningkatkan modularitas, alur navigasi hybrid dapat disempurnakan dengan mendaftarkan route tab melalui protokol dinamis:

// Konsep Abstraksi Rute Tab Dinamis (OCP Compliant)
public protocol FlutterRoutableTab {
    var flutterRootRoute: String { get }
}

extension IDMineViewController: FlutterRoutableTab {
    public var flutterRootRoute: String { "/mine" }
}

extension IDRepayViewController: FlutterRoutableTab {
    public var flutterRootRoute: String { "/repay" }
}

// Controller utama cukup mengevaluasi protokol:
private func flutterRootRoute(for vc: UIViewController?) -> String? {
    (vc as? FlutterRoutableTab)?.flutterRootRoute
}
