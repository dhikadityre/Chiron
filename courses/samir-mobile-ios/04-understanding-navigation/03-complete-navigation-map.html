03 — Complete Navigation Map

Peta Navigasi Lengkap Seluruh Layar

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini memetakan seluruh rute navigasi aplikasi SAMIR iOS, memperlihatkan bagaimana pengguna berpindah dari satu layar ke layar lain, apa pemicu perpindahannya (triggers), parameter data yang dibawa, serta bagaimana alur kembali (unwind / pop).

Status Verifikasi: [Verified] (diverifikasi langsung dari kode routing di semua modul dan handler router).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Memvisualisasikan seluruh graf navigasi aplikasi dari kontainer utama hingga layar terdalam.
  2. Mengetahui alur cabang sukses dan alur cabang alternatif pada setiap fitur.
  3. Memahami interaksi navigasi antara layar Native Swift dan layar Flutter Hybrid.

📋 B. Prerequisites

  • Sudah membaca 01-feature-inventory.md dan 02-navigation-fundamentals.md.
  • Mengetahui struktur UITabBarController dan UINavigationController pada iOS.

💡 C. Simple Explanation (Peta Transportasi Kereta Bawah Tanah)

Bayangkan peta rute MRT / Kereta Api:

  • Stasiun Pusat (Central Hub): IDMainTabBarController dengan 3 peron jalur utama:
    • Jalur Hijau: Peron Beranda (Jalur Pengajuan Pinjaman).
    • Jalur Biru: Peron Tagihan (Jalur Pembayaran Pinjaman).
    • Jalur Kuning: Peron Saya (Jalur Profil & Pengaturan Akun).
  • Stasiun Transit: Layar Login (Modal) dapat dipanggil dari peron mana pun jika pengguna belum memiliki tiket (sesi login).
  • Rute Satu Arah Berurutan: Jalur verifikasi identitas e-KYC (KTP -> Pribadi -> Pekerjaan -> Kontak -> Bank -> Wajah). Anda harus melewati stasiun KTP sebelum diizinkan masuk ke stasiun Rekening Bank.

🪜 E. Step-by-Step Walkthrough: Menelusuri Jalur Pengguna Utama

1. Jalur Pengguna Baru (Zero to First Loan)

  1. Pintu Masuk: User membuka aplikasi pertama kali -> Melihat Splash 3 detik (IDLaunchViewController) -> Masuk Beranda Tab 0.
  2. Autentikasi: User menekan "Ajukan Pinjaman" -> Karena belum login, modal LoginViewV2Controller terbuka -> User input OTP -> Modal tertutup.
  3. Pemeriksaan KYC: Beranda mendeteksi user belum memiliki data KTP -> Memanggil samir://auth/identity.
  4. Rantai KYC:
    • IDNewOCRViewController: Ambil foto e-KTP -> OCR otomatis mengisi NIK & Nama.
    • IDNewAuthBasicViewController: Isi tanggal lahir, status kawin, alamat.
    • IDNewAuthJobViewController: Isi nama kantor, jabatan, gaji.
    • IDNewAuthContactViewController: Input 2 kontak darurat kerabat.
    • IDNewBankViewController: Masukkan no rekening BCA/Mandiri/BRI.
    • IDAuthLiveViewController: Deteksi kedip mata & geleng kepala.
  5. Penilaian Kredit: Selesai liveness -> Sistem otomatis mengarahkan ke samir://loan/creditAssess (IDQuatoAssessViewController) -> Polling analisa risiko selama beberapa detik.
  6. Konfirmasi Pinjaman: Kuota disetujui Rp 3.000.000 -> Navigasi ke samir://loan/confirm (LoanConfirmViewController_Rx) -> User memilih voucher diskon -> User membaca kontrak pinjaman -> User tap "Cairkan Sekarang".
  7. Selesai: Popup sukses tampil -> User kembali ke Beranda (Tab 0).

2. Jalur Pengguna Memeriksa Tagihan & Profil

  1. Dari IDMainTabBarController, user menyentuh icon Tab 1 ("Tagihan").
  2. IDMainTabBarController mendeteksi rute /repay, menyembunyikan view native, dan menampilkan persistent container Flutter.
  3. User menyentuh icon Tab 2 ("Saya").
  4. IDMainTabBarController mendeteksi rute /mine, memperbarui safe area, dan menampilkan profil Flutter.
  5. Dari Profil, user mengklik "Pengaturan":
    • Flutter mengirim pesan method channel openNativeRoute("samir://mine/setting").
    • Native merespon dan melakukan navigationController?.pushViewController(IDMineSettingController(), animated: true).

⚖️ F. Why It Matters: Mekanisme Unwind & Pengembalian Layar

  • Bagaimana Pengguna Kembali dari Alur Terdalam?

Setiap ViewController native menyediakan tombol navigasi kembali di pojok kiri atas yang terhubung ke navigationController?.popViewController(animated: true).

  • Kasus Khusus: Kembali Langsung ke Beranda (Back to Home):

Pada layar web H5 (IDBusinessWebViewController) dan popup konfirmasi pinjaman, terdapat properti backToHome: Bool = true. Ketika properti ini aktif, menekan tombol silang (alert_close) tidak melakukan pop bertahap, melainkan memanggil:

  IDRouterManager.id_perfromWithURLString(
      IDRouterSchemeConstants.Main.tab.rawValue, 
      params: ["tab": "home"]
  )

Ini langsung mereset navigation stack dan memindahkan seleksi tab bar ke Tab 0 (Beranda).

🔬 G. Practical Example: Navigasi Lintas Runtime (Flutter ke Native)

Ketika user berada di halaman profil Flutter dan ingin membuka Pusat Bantuan:

// flutter/lib/pages/mine/home/mine_home_page.dart
void _openFAQ() {
  FlutterNativeRouteDispatcher.openNativeRoute("samir://mine/FAQ");
}

Panggilan ini melewati samir_native_channel ke 🦊 FlutterNativeChannel+route.swift learn/iOS-Arch ↗:

IDRouterManager.id_perfromWithURLString("samir://mine/FAQ")

Yang kemudian membuka IDBusinessWebViewController dengan URL H5 FAQ terotentikasi. Transisi berlangsung mulus tanpa jeda yang terlihat oleh pengguna.

⚠️ H. Common Mistakes & Debugging

  • Stack Navigation Menumpuk (Navigation Stack Leak):
    • Memanggil IDRouterManager.id_perfromWithURLString berulang kali untuk layar yang sama dapat menumpuk puluhan ViewController di memori jika tidak ditutup dengan benar.
  • Gesture Pop Terkunci Setelah KYC:
    • IDNewOCRViewController mematikan gesture swipe back (popGestureClose()). Jika layar ditutup secara tidak wajar tanpa memanggil popGestureOpen(), controller berikutnya mungkin kehilangan kemampuan swipe back.

🧠 I. Knowledge Check & Kunci Jawaban

  1. Ke layar mana pengguna diarahkan setelah verifikasi liveness wajah (IDAuthLiveViewController) selesai dengan sukses?

    Diarahkan langsung ke layar Penilaian Kuota Kredit / Credit Assessment (IDQuatoAssessViewController) dengan rute URL samir://loan/creditAssess (IDRouterSchemeConstants.Loan.creditAssess.rawValue).

    Mekanisme Internal: Pada AuthMananger.swift:L193-198, setelah rekaman biometrik diunggah, SDK memanggil NetworkService.postCreateOrderRequest. Jika draft order berhasil dibuat (bizId), event anti-fraud uploadTrustDecisionCreateOrderEvent dipancarkan, lalu router memanggil IDRouterManager.id_perfromWithURLString("samir://loan/creditAssess", params: creditAssessParams) untuk memulai polling analisa kelayakan kuota kredit.

  2. Bagaimana cara layar web H5 memerintahkan aplikasi kembali langsung ke Beranda?
    • Metode 1 (JSBridge callApp): Layar H5 mengeksekusi pesan JavaScript: 
      window.webkit.messageHandlers.callApp.postMessage({ method: 'goHomePage' });
      Di sisi native iOS (ScriptMessageHandler.swift:L262-267), method @objc func goHomePage menangkap pesan ini dan memanggil: 
      let urlString = "\(IDRouterSchemeConstants.Main.tab.rawValue)?tab=home"
IDRouterManager.id_perfromWithURLString(urlString)
    • Metode 2 (URL Scheme Redirect Langsung): H5 me-redirect window location langsung ke: 
      window.location.href = "samir://main/tab?tab=home";
      IDSamirMainModuleRouterHandler menangkap rute ini, memanggil IDTabbarManager untuk beralih ke Tab 0 (home), serta menutup seluruh tumpukan modal/navigation stack yang sedang aktif.
  3. Sebutkan rute URL yang digunakan untuk membuka formulir pengikatan kartu bank!

    Rute URL resminya adalah samir://auth/bankcard (didefinisikan pada IDRouterSchemeConstants.Auth.bankCard.rawValue).

    Rute ini ditangani oleh IDSamirAuthModuleRouterHandler yang akan menginisialisasi dan mendorong IDNewBankViewController ke navigation stack. (Catatan: Untuk mengganti/memperbarui rekening pada pinjaman aktif, rutenya adalah samir://auth/changeCard yang membuka ChangeBankCardViewController).

🧭 J. Navigation & Coordination Essentials (Pengetahuan Umum & Khusus iOS Engineer)

🌐 A. Pengetahuan Navigasi UMUM (General Routing Architecture)

1. Kapan harus menggunakan URL Routing (CZRouterLib) vs Service Method Protocol (SamirServiceModule)?
  • Gunakan URL Routing (IDRouterManager.id_perfromWithURLString) saat tujuannya adalah perpindahan layar visual antarmodul (misal: Beranda membuka layar KYC samir://auth/identity, atau Profil membuka WebView samir://web/open). URL router memisahkan antarmuka navigasi secara longgar (loose coupling) sehingga modul pemanggil tidak perlu meng-import ViewController tujuan.
  • Gunakan Service Protocol (IDServiceManager.xxxService()) saat membutuhkan pertukaran data murni, query status sinkron, atau eksekusi logika bisnis tanpa pergantian layar (misal: mengecek status loginService()?.isLogin(), mengambil konfigurasi server mainService()?.getAppConfig(), atau memunculkan popup login modal via loginService()?.loginAction()).
2. Bagaimana cara passing parameter kompleks (bukan string primitif) antar ViewController saat routing?

Router SAMIR mendukung dictionary parameter dinamis yang dapat memuat model, closure, atau dictionary bersarang:

let params: [String: Any] = [
    "step": 2,
    "creditAssessParams": ["source": "home_banner", "amount": 5000000],
    "dismissCallback": { print("Modal ditutup") }
]
IDRouterManager.id_perfromWithURLString("samir://auth/identity", params: params)

Di sisi handler (IDSamirAuthModuleRouterHandler), parameter dibaca dan diinjeksi langsung ke properti ViewController sebelum disajikan.

3. Mengapa navigasi tabbar menggunakan query parameter (samir://main/tab?tab=home / tab=repay / tab=mine) dan bagaimana koordinasi state-nya dengan Flutter?

Karena aplikasi SAMIR mengadopsi arsitektur Hybrid Shell: Tab 0 (Beranda) adalah native UIKit, sedangkan Tab 1 (Repay) dan Tab 2 (Mine) menaungi Flutter view engine. Melalui rute sentral samir://main/tab?tab=..., IDMainTabBarController mengkoordinasikan visibilitas container: menyembunyikan atau menampilkan container view Flutter, menyinkronkan status tab index dengan bilah navigasi bawah, serta memastikan inset safe area tidak berkedip (no UI glitching).

🔍 B. Pengetahuan Navigasi KHUSUS (SAMIR Domain & Low-Level Edge Cases)

4. Mengapa pada layar IDNewOCRViewController terdapat pemanggilan popGestureClose() dan apa bahayanya jika tidak di-reset?

Tujuan Bisnis: Pada tahap pemindaian e-KTP dan deteksi wajah, swipe back gesture iOS bawaan (interactivePopGestureRecognizer) sengaja dinonaktifkan via self.popGestureClose() agar nasabah tidak sengaja membatalkan proses scanning kamera yang sedang memproses data biometrik atau OCR.

Risiko Gotcha: Jika navigasi berpindah ke controller lain tanpa memanggil self.popGestureOpen(), status gesture pop pada UINavigationController akan terus terkunci (mati) untuk seluruh layar berikutnya dalam stack navigasi.

5. Bagaimana mekanisme "Urge Stay" (Dialog Konfirmasi Pembatalan saat Back) bekerja di tengah formulir KYC?

Ketika nasabah menekan tombol panah kembali di form kontak darurat (samir://auth/contacts) atau bank card (samir://auth/bankcard), presenter memicu event point urgeStay_bankcard_1/2/3 dan memunculkan popup interaktif: "Yakin ingin membatalkan? Kuota pinjaman Anda sebesar Rp X.000.000 siap dicairkan!". Jika pengguna memilih "Lanjut Isi", dialog dismiss dan posisi input dipertahankan. Jika memilih "Batalkan", presenter memanggil navigationController?.popViewController dan mencatat drop-off funnel di IDCustomPointManager.

6. Apa yang terjadi jika rute URL yang dipanggil tidak valid atau parameter wajibnya hilang (samir://auth/identity tanpa step)?

Jika skema tidak dikenali oleh CZRouterCenter, router mencatat log debugging pada DataCollectDebugLogManager dan secara diam-diam menggagalkan navigasi (fail-safe silent drop) tanpa memicu crash aplikasi fatal. Jika rute valid tetapi parameter hilang, presenter controller menerapkan nilai default fallback (misal default ke step = 0 / Registrasi Baru).

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Tight Coupling pada Antarmuka Routing & Hardcoded String Paths

Navigasi antar layar dan pembukaan modal masih mengandalkan string URL scheme atau navigasi langsung controller-ke-controller, menyulitkan pelacakan dependensi dan memicu runtime crash jika parameter route tidak valid.

⚠️ Smells 2: Pencampuran Presentasi UI dengan Koordinasi Rute (Melanggar SRP)

ViewController atau Widget UI mengetahui secara langsung hierarki layar berikutnya dan cara menyajikannya (push vs present modal), mengurangi reusabilitas tampilan pada modul lain.

🚀 Blueprint Refactoring Standar Industri: Pola Navigation Coordinator & Typed Route Handlers

Mengabstraksikan seluruh orkestrasi layar ke dalam modul Coordinator independen. UI hanya memancarkan event intent navigasi tanpa mengetahui implementasi rute konkret.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol Coordinator: AnyObject {
    var navigationController: UINavigationController { get set }
    func start()
}

public final class RepayFlowCoordinator: Coordinator {
    public var navigationController: UINavigationController
    public init(navigationController: UINavigationController) {
        self.navigationController = navigationController
    }
    public func start() {
        let vc = IDRepayViewController()
        navigationController.pushViewController(vc, animated: true)
    }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
