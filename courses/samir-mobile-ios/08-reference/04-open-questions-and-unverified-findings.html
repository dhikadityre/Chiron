📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Sesuai dengan prinsip kejujuran teknis: "Jika suatu informasi tidak dapat diverifikasi, nyatakan secara eksplisit. Jangan mengarang fitur, business rules, dependency, atau alasan historis."

Dokumen ini mencatat seluruh area abu-abu, dependensi eksternal yang belum terverifikasi, serta pertanyaan terbuka yang memerlukan konfirmasi lebih lanjut dari Product Owner, Tech Lead, atau Backend Team SAMIR.

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, Anda diharapkan mampu:

  1. Mengetahui batas-batas pengetahuan (knowledge boundaries) yang dapat dibuktikan murni dari kode sumber client iOS.
  2. Mengetahui topik-topik arsitektur dan operasional yang memerlukan koordinasi lintas divisi.
  3. Menggunakan daftar pertanyaan ini sebagai agenda wawancara terarah (onboarding technical interview) dengan tim internal SAMIR.

📌 B. Daftar Temuan Belum Terverifikasi (Unverified Findings)

1. Otomasi CI/CD & Alur Rilis App Store [Unverified]

  • Status: Tidak dapat diverifikasi dari repository git.
  • Kondisi Lapangan:
    • Tidak ditemukan direktori .github/workflows/, .gitlab-ci.yml, Bitrise.yml, maupun folder fastlane/.
    • Skema Xcode (IDSamirLoan.xcscheme, TEST.xcscheme, PROD.xcscheme) dikonfigurasi lengkap dengan build configurations terpisah.
  • Pertanyaan Terbuka untuk Tech Lead:
    1. Apakah build IPA dan pengunggahan ke TestFlight/App Store Connect dilakukan secara manual via Xcode Organizer atau menggunakan dedicated CI server (seperti Jenkins / Mac Mini self-hosted)?
    2. Di mana sertifikat signing (Distribution Certificate & Provisioning Profiles) dikelola (apakah via Fastlane Match, manual portal Apple, atau Xcode Managed)?

2. Algoritma Credit Scoring & Ambang Batas Persetujuan Pinjaman [Inferred]

  • Status: Terbukti secara inferensi dari alur polling client.
  • Kondisi Lapangan:
    • Client iOS mengumpulkan data telemetri yang sangat kaya (lokasi GPS, orientasi sensor gerak, device fingerprint TrustDecision, data kontak darurat, foto OCR KTP, dan biometrik Advance AI).
    • Client melakukan polling berkala ke endpoint /app/index/getAppIndexNew atau /app/loan/checkAuditStatus selama 30 hingga 60 detik.
  • Pertanyaan Terbuka untuk Backend / Risk Engine Team:
    1. Berapa ambang batas waktu (timeout) maksimum proses verifikasi otomatis sebelum dialihkan ke manual review oleh tim verifikator manusia?
    2. Apakah ada skenario di mana pengguna diminta melakukan upload dokumen tambahan (seperti mutasi rekening bank atau ID card kantor) secara dinamis jika skor kredit berada di zona batas?

3. Masa Depan Isolasi Reaktif RxSwift di LoanConfirmModule [Unverified]

  • Status: Tidak ada catatan dokumentasi mengenai alasan pemilihan teknologi ini.
  • Kondisi Lapangan:
    • Hanya modul konfirmasi pinjaman yang menggunakan RxSwift/RxCocoa (2.250 baris di LoanConfirmViewController_Rx.swift). Seluruh modul lain menggunakan pola MVC/MVP konvensional.
  • Pertanyaan Terbuka untuk iOS Lead:
    1. Apakah LoanConfirmModule merupakan modul percontohan (pilot project) yang rencananya akan diperluas ke modul lain, ataukah merupakan sisa eksperimen masa lalu yang direncanakan untuk di-refactor kembali ke standar MVP?
    2. Apakah tim memiliki roadmap jangka panjang untuk migrasi ke Swift Concurrency (async/await) atau Combine untuk menggantikan RxSwift?

4. Batasan Ruang Lingkup Upload Aliyun OSS [Inferred]

  • Status: Terbukti penggunaan SDK untuk foto identitas, namun cakupan penuh belum terverifikasi.
  • Kondisi Lapangan:
    • Pod AliyunOSSiOS aktif di Podfile.
    • Terlihat penggunaan upload token sementara (STS) untuk mengirim file gambar KTP terkompresi.
  • Pertanyaan Terbuka untuk Backend Team:
    1. Apakah file log lokal, database SQLite, atau payload telemetri perangkat juga dikirimkan langsung ke bucket OSS Aliyun saat terjadi crash/anomali, ataukah seluruh data analitik hanya dikirim via HTTP gateway?

5. Logika Pendeteksian Reviewer Apple pada appStartHide [Inferred]

  • Status: Mekanisme server-side tidak terlihat dari kode client.
  • Kondisi Lapangan:
    • Aplikasi memanggil endpoint /app/common/appStartHide pada tahap inisialisasi awal di IDSamirMainModule.swift:L48.
    • Jika flag bernilai true, beberapa elemen antarmuka atau promo khusus disembunyikan.
  • Pertanyaan Terbuka untuk Product Owner:
    1. Parameter apa yang digunakan oleh backend untuk membedakan reviewer Apple dari pengguna riil di Indonesia (apakah filter IP geolokasi AS/Cupertino, nomor ponsel dummy reviewer, atau header appVersion yang belum terdaftar di PROD)?

📌 D. Matriks Resolusi Jawaban Teknis (21 Pertanyaan Inti Codebase SAMIR)

Berikut adalah rangkuman verifikasi faktual terhadap 21 pertanyaan teknis yang sering muncul saat mempelajari codebase SAMIR iOS beserta rujukan dokumen pos semestinya:

NoPertanyaan TeknisRingkasan Jawaban Faktual (Code Truth)Pos Dokumen Terkait
1IDModuleList (List Value) di get dari mana?Berasal dari file XML IDModuleList.plist di main bundle, dibaca oleh CZModuleManager.registerAllModules menggunakan NSDictionary(contentsOf: url!), lalu di-load menggunakan refleksi runtime NSClassFromString.02-understanding-app-startup/01-ios-entry-point.md
2IDNPopupConfig apakah sudah best practice?Belum ideal. Kelebihannya adalah struct value type, namun memiliki code smell: static var shared mutable state, typo API (contianerView), kopling ke macro dynamic island, dan menempelkan view manual alih-alih UISheetPresentationController.03-understanding-architecture/04-shared-components-and-services.md
3LibNetSignGenerator untuk apa & cara setup-nya?Framework biner C++/ObjC tertutup untuk enkripsi tanda tangan request HTTP (sign) menggunakan staticKey. Ditaruh di SamirNetworkModule/Frameworks/, didaftarkan di FRAMEWORK_SEARCH_PATHS, dan di-embed dengan CodeSignOnCopy.01-project-foundation/03-technology-stack-and-build.md
4Di IDNewAuthPresenter ada 2 presenter, mengapa?Menerapkan Composite Presenter Pattern. resourcePresenter didelegasikan untuk wilayah/kamus dropdown, bankPresenter untuk pencarian bank, agar IDNewAuthPresenter tidak menjadi God Presenter raksasa.03-understanding-architecture/02-layers-and-responsibilities.md
5CZRouter digunakan untuk apa?Router navigasi internal berbasis URL Scheme (samir://...). Mengeliminasi ketergantungan langsung antar-ViewController dan menyatukan navigasi push notif, webview H5, dan native.04-understanding-navigation/02-navigation-fundamentals.md
6SamirAuthModule ada V1 & V2, mana yang digunakan?V2 yang 100% digunakan aktif (IDNewOCRViewController, dll.). Seluruh route di IDSamirAuthModuleRouterHandler memanggil V2. V1 adalah dead code sisa migrasi.05-learning-business-flows/02-authentication-and-session-flow.md
7Settingan Xcode 16 Synchronized Groups diset manual atau otomatis?Manual untuk project lama (tetap PBXGroup). Xcode 16 hanya menaikkan objectVersion ke 73 secara otomatis, yang memicu patch monkey-patch di Podfile:L2-6 agar CocoaPods tidak error.01-project-foundation/03-technology-stack-and-build.md
8Bagaimana main disetup? Mengapa dibaca pertama kali?File main.swift adalah entry point standar Swift compiler untuk top-level execution (dibuat jadi _main Mach-O LC_MAIN). Dieksekusi paling pertama, menginisialisasi APM Tingyun lalu memanggil UIApplicationMain.02-understanding-app-startup/01-ios-entry-point.md
9LoanConfirmViewModel (RxSwift, Driver) dipelajari lebih dalamMengadopsi arsitektur Clean MVVM reaktif (LoanConfirmViewModelType). Input berupa PublishSubject (tap, slider, voucher), Output berupa Driver<T> (loan data, calculated trial, error).03-understanding-architecture/02-layers-and-responsibilities.md
10Kapan pakai subscribe vs drive?Pakai drive di View Layer untuk binding UI (pasti Main Thread, tidak pernah error, share replay). Pakai subscribe di Service/Domain Layer (background thread, butuh menangkap error jaringan).03-understanding-architecture/02-layers-and-responsibilities.md
11Mana yang pakai viewModel vs presenter?viewModel: Hanya di LoanConfirmModule. presenter: Dipakai di SELURUH modul lainnya (SamirLoginModule, SamirAuthModule, SamirLoanModule, SamirRepayModule, SamirMineModule, SamirCommonModule).03-understanding-architecture/02-layers-and-responsibilities.md
12CZSwiftRouterLibLibrary perutean modular internal yang terdiri dari CZRouterCenter (singleton registry), CZRouterTable (path regex matching), dan CZRouter (scheme & host binding).04-understanding-navigation/02-navigation-fundamentals.md
13CZSwiftAntiFraudLib pakai ObjC? Cara kerja & buat di new project?Hybrid Swift + ObjC. Pakai ObjC untuk akses kernel BSD/Mach (mach/mach.h, sysctl, memory stats, CommonCrypto). Mengumpulkan sinyal hardware, jailbreak, baterai, dan mengenkripsi payload. Di project baru bisa pakai Swift murni (ProcessInfo, CryptoKit).03-understanding-architecture/04-shared-components-and-services.md
14CZNetworkLib masih digunakan?TIDAK AKTIF / DEPRECATED. Import-nya sudah dikomentari di Bridging Header dan IDNetworkManager. Seluruh jaringan saat ini ditangani oleh SamirNetworkModule + Alamofire via CZAlamofireBridge.06-understanding-data-and-dependencies/02-networking-and-api-flow.md
15CZSwiftStorageLib digunakan di mana & cara buat di new project?Berada di Application/CZSwiftStorageLib/ sebagai cache 2-lapis (LRU CZMemoryStorage + CZDiskStorage). Di project baru, buat CacheProtocol, gabungkan NSCache (L1) dan disk JSON file (L2) menjadi TwoLevelCache.06-understanding-data-and-dependencies/04-state-management-and-persistence.md
16Modul Debug digunakan untuk apa?Tombol melayang (floating debug console) in-app untuk mengamati HTTP Request/Response, event pihak ketiga (AppsFlyer, FB, TikTok), dan telemetri risiko langsung di layar HP pada build TEST.07-learning-to-debug-and-maintain/02-testing-and-debugging.md
17CZSwiftUIKit perlu dipelajari pemakaiannyaKit UI in-house berisi namespace extension .cz. (UIViewController, UIView), tooling (CZWeakTimer, CZDarkModeUtil), komponen kustom (CZDrawSignatureView, CZRollingNoticeView), dan font finansial MosnDigitBoldFont.03-understanding-architecture/04-shared-components-and-services.md
18Apa fungsi target IDSamirEnvironment & cara buat di project baru?Aggregate Target (PBXAggregateTarget) untuk menjalankan app_environment.sh guna membuat environment_preprocess.h tanpa build app. Dibuat via Xcode Target + -> Cross-platform Aggregate -> Run Script Phase.01-project-foundation/03-technology-stack-and-build.md
19Apa fungsi LibNetSignGenerator & bagaimana di-import?Menghitung sign request HTTP anti-tampering via C/C++ engine. Di-import via import LibNetSignGenerator (didukung module.modulemap) atau #import <LibNetSignGenerator/LibNetSignGenerator.h>.01-project-foundation/03-technology-stack-and-build.md
20Bagaimana lipo -extract dijalankan?Dijalankan di Run Script Build Phase. Menemukan LibNetSignGenerator.framework, mengekstrak hanya arsitektur $ARCHS via lipo -extract, menggabungkannya via lipo -create, lalu menimpa binary asli untuk menghapus arsitektur simulator.01-project-foundation/03-technology-stack-and-build.md
21Mengapa Kingfisher disetel BUILD_LIBRARY_FOR_DISTRIBUTION = 'NO'?Mematikan generasi .swiftinterface pada Kingfisher untuk mencegah error kompilasi Swift compiler terkait generic image pipeline dan mempercepat build. Karena dikompilasi dari source, module stability tidak diperlukan.01-project-foundation/03-technology-stack-and-build.md

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
