💡 C. Simple Explanation (Analogi & Konsep Sederhana)

Bayangkan aplikasi perbankan mikro di mana nasabah dapat meminjam dana darurat tanpa harus datang ke kantor cabang fisik:

  1. Nasabah mengunduh aplikasi SAMIR dari App Store.
  2. Nasabah mendaftarkan nomor ponsel dan memverifikasi identitas menggunakan e-KTP dan foto wajah (Liveness Detection).
  3. Sistem secara otomatis menganalisis skor kredit dan memberikan limit pinjaman (Plafon Kredit).
  4. Nasabah memilih nominal dan tenor, lalu dana dicairkan ke rekening bank nasabah.
  5. Pada tanggal jatuh tempo, nasabah membayar kembali melalui Virtual Account atau gerai retail.

Karena ini adalah aplikasi finansial, aspek keamanan, integritas data perangkat, anti-fraud, dan tanda tangan digital menjadi pilar paling vital di seluruh arsitektur sistem.

🔍 Bedah Teknis aps-environment:
  • Tujuan Entitlement: Mengaktifkan Apple Push Notification service (APNs). Menentukan gateway Apple APNs mana yang dihubungi oleh daemon iOS (apsd) saat device mendaftarkan push token (registerForRemoteNotifications()):
    • development: Mengarah ke APNs Sandbox Gateway (api.sandbox.push.apple.com). Digunakan untuk pengetesan lokal/debug.
    • production: Mengarah ke APNs Production Gateway (api.push.apple.com). Digunakan untuk rilis TestFlight, AdHoc, dan App Store.
  • Apakah Value TEST dan PROD Sama di Repository?

Ya, pada level source code repository, seluruh skema (TEST, PROD, PRODTEST) merujuk pada file yang sama di build setting CODE_SIGN_ENTITLEMENTS = IDSamirLoan/IDSamirLoan.entitlements dengan value default development agar developer dapat melakukan debugging langsung ke perangkat fisik menggunakan Apple Development Certificate.

  • Di Mana Proses Replace development $\rightarrow$ production Dilakukan?

Pergantian nilai ini tidak dilakukan oleh script custom manual, melainkan otomatis oleh Apple Build & Packaging System (Xcode / codesign) pada tahap Archive & Exporting IPA:

  1. Provisioning Profile Matching: Saat proses xcodebuild -exportArchive atau menu Organizer > Distribute App, Xcode membaca Distribution Provisioning Profile yang terdaftar di Apple Developer Portal (memiliki entitlement aps-environment = production).
  2. Entitlements Merging & Sanitization: Xcode menggabungkan file .entitlements lokal dengan kapabilitas profil distribusi, lalu membuat file manifest sementara (DerivedData/.../IDSamirLoan.app.xcent) di mana nilai development secara otomatis ditimpa (overridden) menjadi production.
  3. Binary Re-Signing: Utilitas codesign menandatangani Mach-O executable bundle dengan entitlement production final.
  4. Verifikasi Output IPA: Nilai akhir dapat diverifikasi melalui terminal: 
     unzip -q IDSamirLoan.ipa
     codesign -d --entitlements :- Payload/IDSamirLoan.app
     # atau cek embedded provisioning profile:
     security cms -D -i Payload/IDSamirLoan.app/embedded.mobileprovision | grep -A 2 aps-environment

[!IMPORTANT] Implikasi Backend: Device token yang di-generate dari mode development (Sandbox) memiliki format enkripsi berbeda dengan mode production. Backend server SAMIR wajib memisahkan gateway pengiriman notifikasi agar tidak menerima error BadDeviceToken (HTTP 400).

B. Pilar 1: Siapa yang Mengonsumsi ID_ENVIRONMENT? (Alur Bundle & Packaging)

ID_ENVIRONMENT adalah User-Defined Setting di Xcode Build Settings yang bertanggung jawab penuh atas identitas fisik APK/IPA dan metadata Info.plist:

  1. Konsumen Langsung (Direct Consumer):
    • Skrip shell build phase 🦊 app_environment.sh learn/iOS-Arch ↗ dieksekusi sebelum proses kompilasi kode dimulai.
    • Skrip ini membaca variabel env=${ID_ENVIRONMENT} lalu men-generate berkas header C sementara: 🦊 environment_preprocess.h learn/iOS-Arch ↗ dengan isi: 
     #define ID_ENVIRONMENT              TEST
     #define ID_ENVIRONMENT_APP_NAME     Samir 26   // Ditambah tanggal jika bukan PROD!
     #define ID_ENVIRONMENT_LAST_COMMIT  1.0.0.33   // Nomor versi + commit git count
  1. Konsumen Turunan (Downstream Consumer):
    • Xcode Info.plist Preprocessor (INFOPLIST_PREPROCESS = YES):

Xcode menginjeksi environment_preprocess.h sebagai prefix header ke 🦊 IDSamirLoan-Info.plist learn/iOS-Arch ↗ untuk mengganti:

  • CFBundleDisplayName $\rightarrow$ ID_ENVIRONMENT_APP_NAME
  • ID_ENVIRONMENT_LAST_COMMIT $\rightarrow$ ID_ENVIRONMENT_LAST_COMMIT
  • Springboard iOS (Home Screen HP):

Ikon aplikasi di iPhone menampilkan nama Samir <hari> (misal Samir 26) pada build non-PROD agar tim QA dapat membedakan build testing di perangkat mereka, dan murni Samir pada build PROD.

C. Pilar 2: Siapa yang Mengonsumsi SWIFT_ACTIVE_COMPILATION_CONDITIONS? (Alur Endpoints & Config Dictionary)

Flag ini diproses oleh compiler Swift (swiftc) untuk mengontrol peta data konfigurasi, kredensial client API, dan URL server:

  1. Konsumen Langsung (Direct Consumer):
    • Di seluruh codebase Swift SAMIR, hanya ada SATU file yang langsung mengevaluasi #if TEST, yaitu 🦊 AppEnv.swift:L26 learn/iOS-Arch ↗.
    • AppEnv menyuplai dictionary konfigurasi sesuai kondisi:
      • apiBaseUrl: "https://domain-loansapp-test.samir.co.id/" (TEST) vs "https://domain-loansapp.samir.co.id/" (PROD).
      • h5BaseUrl: Domain webview syarat & ketentuan / edukasi.
      • clientId: ID registrasi OAuth client (3f321e51... vs 850792dc...).
      • advanceAIUrl, trackReportUrl, trackBaseUrl, dan appleId (6475002606).
  2. Core Facade (Penyimpan State Runtime):
    • 🦊 CZEnvironmentManager.swift:L95 learn/iOS-Arch ↗ menyimpan data dari AppEnv.default.config ke dalam variabel cachedConfigData.
  3. Konsumen Turunan (Downstream Consumers):

Seluruh modul mengambil nilai konfigurasi melalui CZEnvironmentManager.stringValueForKey(...):

  • Jaringan API Native: 🦊 IDNetworkManager.swift:L72 learn/iOS-Arch ↗ menetapkan manager.baseUrl untuk seluruh HTTP/REST request pinjaman.
  • Bridge Host ke Flutter Module: 🦊 FlutterNativeChannel+method.swift:L14 learn/iOS-Arch ↗ mengeksekusi handler method getNativeAppEnv untuk mengoper apiBaseUrl, webBaseUrl, trackBaseUrl, dan clientId ke Flutter Engine, sehingga Tab Tagihan (Repay) dan Tab Saya (Mine) yang berbasis Flutter otomatis mengikuti konfigurasi environment iOS host.
  • Layanan Siklus Pinjaman: 🦊 LoanConfirmRepayPlanService.swift:L190 learn/iOS-Arch ↗ mengambil apiBaseUrl untuk kalkulasi tenor dan jadwal angsuran.
  • Webview H5 Terintegrasi: 🦊 BaseWebViewController.swift:L572 learn/iOS-Arch ↗, 🦊 IDBusinessWebViewController.swift:L413 learn/iOS-Arch ↗, dan 🦊 UnionLoginWebHelper.swift:L46 learn/iOS-Arch ↗ memuat agreement dan form perizinan OJK dari webBaseUrl.

E. FAQ Arsitektur Penting
  1. Mengapa CZBuildEnvironment.m Dibuat Secara Manual?

Berkas 🦊 CZBuildEnvironment.m learn/iOS-Arch ↗ dan 🦊 CZBuildEnvironment.h learn/iOS-Arch ↗ ditulis secara manual oleh engineer iOS SAMIR (SamiriOS) pada 20 November 2023.

  • Alasan Arsitektur: Kompiler C/Clang mengevaluasi preprocessor macro (GCC_PREPROCESSOR_DEFINITIONS) secara instan pada level teks sebelum parsing. Kode Objective-C ini berfungsi sebagai C Preprocessor Bridge yang membungkus macro compiler ke dalam method statis Objective-C, lalu diekspos ke Swift via 🦊 CZPreBuildMacro.swift learn/iOS-Arch ↗.
  1. Mengapa appleId (6475002606) Aman Disimpan di Repo?

Nilai appleId di 🦊 AppEnv.swift learn/iOS-Arch ↗ adalah App Store ID (Track ID) publik yang diterbitkan oleh Apple (URL publik: https://apps.apple.com/app/id6475002606).

  • Digunakan untuk in-app review redirect (itms-apps://itunes.apple.com/app/id6475002606), integrasi Firebase, Universal Links, dan SKAdNetwork.
  • Bukan merupakan data rahasia (secret). Hal yang wajib dirahasiakan adalah sertifikat p8/p12, App Store Connect API Key, dan password keystore.
F. 5 Risiko Kritis & Gotchas yang Wajib Diwaspadai

[!CAUTION] 1. Kebocoran Kode SMS OTP: Jika TEST=1 aktif di build rilis, seluruh user dapat login tanpa verifikasi SMS sungguhan karena OTP tercetak di layar. 2. Split-Brain Network Mismatch: Jika Swift disetel TEST (Base URL staging) namun Preprocessor disetel PROD=1 (validatesDomainName = true), seluruh request API gagal akibat penolakan sertifikat SSL staging. 3. Jebakan Clang #if (defined FOO): Menyetel TEST=0 di Preprocessor Macros tetap dianggap bernilai TRUE karena Clang memeriksa eksistensi definisi kata, bukan angkanya. Untuk mematikan, hapus simbol seutuhnya. 4. Nama Aplikasi di Homescreen: Jika lupa menyelaraskan ID_ENVIRONMENT = PROD, aplikasi akan dirilis ke nasabah dengan nama Samir <tanggal> (misal Samir 26). 5. Bersihkan Cache Setelah Edit: Selalu jalankan Clean Build Folder (Cmd + Shift + K) setelah mengedit setting preprocessor agar artefak lama di environment_preprocess.h tidak tersisa.

⚖️ F. Why It Matters (Trade-Offs & Implikasi Teknis)

  • Mengapa Portrait & Light Mode Only?

Aplikasi finansial dan verifikasi KTP/wajah sangat sensitif terhadap rotasi kamera dan konsistensi kontras warna saat proses OCR. Membatasi orientasi ke portrait dan light-mode mengeliminasi ratusan edge-case bug pada layout kamera dan form tabel.

  • Mengapa Minimal iOS 14.0?

Mulai iOS 14.0, Apple mewajibkan framework AppTrackingTransparency (ATTrackingManager). Selain itu, Flutter Engine terbaru dan pustaka kriptografi modern (CryptoKit) bekerja optimal di iOS 14+.

  • Mengapa Menggunakan Single Prewarmed Flutter Engine?

Tab Repay dan Mine mengonsumsi engine Flutter bersama (FlutterEngineManager.shared). Prewarming engine saat cold start memangkas jeda navigasi (black screen freeze) menjadi instan.

🔬 G. Practical Example (Skenario Penggunaan Nyata)

Ketika seorang user membuka aplikasi di simulator atau perangkat fisik:

  1. CZBuildEnvironment.m memeriksa apakah macro TEST terdefinisi.
  2. CZEnvironmentManager membaca hasil konfigurasi untuk menetapkan appleId (6475002606) dan apiBaseUrl (https://domain-loansapp-test.samir.co.id/).
  3. Singleton jaringan IDNetworkManager menginjeksi header dan Base URL tersebut ke seluruh request API.

⚠️ H. Common Mistakes & Debugging

  • Kesalahan Umum: Mencoba menjalankan aplikasi dengan simulator ber-iOS 13.
    • Efek: Xcode akan menampilkan error build / deploy The run destination is not valid for running the scheme.
    • Solusi: Pastikan simulator atau iPhone fisik menggunakan iOS 14.0 atau lebih baru.
  • Kesalahan Dark Mode: Berasumsi aplikasi mendukung Dark Mode otomatis.
    • Efek: Mengubah warna label menjadi dinamis dapat merusak keterbacaan karena aset background di-hardcode ke palet terang.
  • Kesalahan APNs Environment Mismatch:
    • Gejala: Push notification tidak masuk pada build TestFlight/Production dengan respon server BadDeviceToken (400).
    • Penyebab: Server backend masih menembak ke gateway APNs Sandbox menggunakan token dari build distribusi Production.

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.
