02 — Repository Structure

Peta Direktori & Tata Letak Kode

📚 Modul: 02-repository-structure 🎯 Scope: SAMIR Mobile (iOS Native UIKit & FChannel) ⏱️ Estimasi: 20 Menit 🏷️ Git Branch: learn/iOS-Arch

📖 Bagian 1: Dokumen Pembelajaran Lengkap & Alur Nyata

Core Knowledge

Dokumen ini membedah struktur fisik file dan folder dalam repositori samir-mobile-develop, menjelaskan peran masing-masing direktori, dan bagaimana file saling terhubung antar-layer.

Status Verifikasi: [Verified] (diverifikasi langsung dari struktur direktori fisik workspace).

🎯 A. Learning Objective

Setelah mempelajari dokumen ini, pembaca akan mampu:

  1. Menavigasi struktur folder tingkat tinggi repositori (iOS, Flutter, Android, Docs).
  2. Memahami pembagian direktori di dalam ios/IDSamirLoan/Application/: pustaka fondasi (CZ*), modul bisnis (Samir*Module), dan konfigurasi.
  3. Memahami konsep Xcode 16 Synchronized Groups (objectVersion 73) yang membuat file di filesystem otomatis terdaftar di Xcode project tanpa perlu modifikasi manual project.pbxproj.

📋 B. Prerequisites

  • Sudah membaca 01-application-overview.md.
  • Memiliki pemahaman dasar mengenai struktur proyek iOS CocoaPods dan Flutter Module.

💡 C. Simple Explanation (Analogi Lemari Arsip Bersekat)

Bayangkan sebuah kantor manajemen yang memiliki lemari arsip besar:

  • Laci 1 (CZ*): Alat-alat kantor standar (stepler, pemotong kertas, lem) yang netral dan dapat digunakan oleh siapa saja.
  • Laci 2 (Samir*Module): Berkas kerja spesifik untuk setiap divisi (Divisi Pinjaman, Divisi Penagihan, Divisi Keanggotaan).
  • Laci 3 (flutter/): Meja kerja digital khusus yang menangani halaman-halaman modern tertentu agar dapat berbagi kode dengan Android.
  • Buku Panduan (Configuration/): Daftar nama divisi dan protokol kerja sama antardivisi.

Dengan pembagian yang rapi ini, pengembang modul Pinjaman tidak perlu membongkar berkas milik modul Keanggotaan saat ingin mengubah tampilan formulir pinjaman.

3. Arsitektur Folder ios/IDSamirLoan/Application/

Seluruh logika aplikasi native terpusat di folder Application/. Terbagi menjadi dua kategori utama:

Kategori A: Pustaka Fondasi Internal (CZ*)

Dibuat dengan prefix CZ, pustaka ini tidak mengandung aturan bisnis (business logic-agnostic):

  • 🦊 CZSwiftModuleLib/ learn/iOS-Arch ↗: Kerangka runtime modular, CZModuleManager, CZAppDelegate, dan lifecycle routing.
  • 🦊 CZSwiftRouterLib/ learn/iOS-Arch ↗: URL Router engine, matcher regex, dan router table.
  • 🦊 CZSwiftEnviromentLib/ learn/iOS-Arch ↗: Konfigurasi environment (AppEnv.swift, CZEnvironmentManager).
  • 🦊 CZSwiftStorageLib/ learn/iOS-Arch ↗: Abstraksi cache disk & memory (CZCache).
  • 🦊 CZSwiftAntiFraudLib/ learn/iOS-Arch ↗: Deteksi jailbreak, sidik jari perangkat (CZFpid), dan utilitas anti-fraud.
  • 🦊 CZSwiftUIKit/ learn/iOS-Arch ↗: Komponen UI kustom, banner, empty state, dan puluhan ekstensi UIKit.
  • 🦊 CZSwiftUtils/ learn/iOS-Arch ↗: Helper string, tanggal, regex, debouncer, dan logging.
  • 🦊 CZNetworkLib/ learn/iOS-Arch ↗: Library jaringan warisan (ObjC/AFNetworking).
Kategori B: Modul Bisnis (Samir*Module)

Dibuat dengan prefix Samir, setiap folder merepresentasikan satu domain bisnis mandiri:

  • 🦊 SamirMainModule/ learn/iOS-Arch ↗: Bootstrapping, splash screen, tab bar controller (IDMainTabBarController), konfigurasi global, deep link dispatcher.
  • 🦊 SamirLoginModule/ learn/iOS-Arch ↗: Layar login OTP SMS/WA, password, verifikasi 2FA, dan manajemen sesi pengguna (IDLoginManager).
  • 🦊 SamirAuthModule/ learn/iOS-Arch ↗: Alur verifikasi identitas (e-KYC): OCR KTP (IDNewOCRViewController), info dasar, pekerjaan, kontak darurat, rekening bank, dan liveness detection.
  • 🦊 SamirLoanModule/ learn/iOS-Arch ↗: Halaman Beranda (IDHomeViewController), penilaian kuota kredit (IDQuatoAssessViewController), dan alur konfirmasi pinjaman berbasis RxSwift (LoanConfirmModule/).
  • 🦊 SamirRepayModule/ learn/iOS-Arch ↗: Host native untuk tab Tagihan (IDRepayViewController) yang mendelegasikan rendering ke Flutter.
  • 🦊 SamirMineModule/ learn/iOS-Arch ↗: Host native untuk tab Saya (IDMineViewController) yang mendelegasikan rendering ke Flutter, plus layar native pengaturan/bantuan.
  • 🦊 SamirWebViewModule/ learn/iOS-Arch ↗: Kontainer browser H5 (IDBusinessWebViewController), auto login URL (UnionLoginWebHelper), dan jembatan JavaScript (IDWebViewJsHandler).
  • 🦊 SamirNetworkModule/ learn/iOS-Arch ↗: Pipeline HTTP modern berbasis Alamofire, parameter global default (ApiParamsHelper), dan penandatanganan request vendor (LibNetSignGenerator.framework).
  • 🦊 SamirPointsModule/ learn/iOS-Arch ↗: Abstraksi pelaporan event analitik (Firebase, AppsFlyer, TikTok SDK, custom tracking backend).
  • 🦊 SamirRouterModule/ learn/iOS-Arch ↗: Konstanta skema URL router (IDRouterConstants) dan fasad pemanggilan (IDRouterManager).
  • 🦊 SamirServiceModule/ learn/iOS-Arch ↗: Kontrak antarmuka (protokol) untuk komunikasi data lintas modul tanpa tight coupling.
  • 🦊 SamirCommonModule/ learn/iOS-Arch ↗: Jembatan integrasi Flutter (FlutterEngineManager, FlutterNativeChannel), base class UI, dan konfigurasi umum.
Kategori C: Konfigurasi & Tooling
  • 🦊 Configuration/Module/IDModuleList.plist learn/iOS-Arch ↗: Daftar 6 modul runtime terdaftar.
  • 🦊 Configuration/Module/IDServiceList.plist learn/iOS-Arch ↗: Daftar 4 handler protokol layanan.
  • 🦊 Configuration/Environment/app_environment.sh learn/iOS-Arch ↗: Skrip pembangun makro preprocessor environment_preprocess.h.
  • 🦊 Debug/ learn/iOS-Arch ↗: Tooling in-app debug (DebugUI.swift, DebugListViewController.swift).

🪜 E. Step-by-Step Walkthrough: Konvensi Penempatan File Baru

Jika Anda diminta membuat fitur atau layar baru di SAMIR iOS, ikuti aturan folder berikut:

  1. Tentukan Modul Pemilik:
  • Jika fitur berkaitan dengan pinjaman, tempatkan di bawah SamirLoanModule.
  • Jika fitur verifikasi data user, tempatkan di bawah SamirAuthModule.
  1. Gunakan Subfolder Konvensional:
  • Classes/IDController/: Tempat file UIViewController (contoh: IDNewLoanHistoryViewController.swift).
  • Classes/IDPresenter/: Tempat business logic & koordinasi data.
  • Classes/IDService/: Tempat network service pemanggil API.
  • Classes/IDModel/: Tempat struct/class data model KakaJSON.
  • Classes/IDView/: Tempat UIView kustom, tableview cell, popup view.
  1. Simpan File di Filesystem:
  • Karena proyek ini menggunakan format Xcode 16 Synchronized Groups, Anda cukup membuat file di folder tersebut. Xcode akan otomatis mendeteksi file baru saat kompilasi berikutnya tanpa perlu "Add Files to IDSamirLoan" secara manual.

⚖️ F. Why It Matters (Keuntungan Arsitektur Folder Ini)

  • Menghindari Konflik Merge (Git Merge Conflicts):

Dengan format grup tersinkronisasi Xcode 16 (PBXFileSystemSynchronizedRootGroup), file project.pbxproj tidak lagi mencatat setiap penambahan file Swift baru. Ini mengeliminasi 90% konflik git saat bekerja dalam tim besar!

  • Isolasi Domain Bisnis:

Setiap modul berdiri sendiri. Developer yang sedang mengerjakan modul Auth tidak akan sengaja menyentuh file milik modul Repay.

🔬 G. Practical Example (Studi Kasus)

Mari kita lihat file 🦊 ios/IDSamirLoan/Application/SamirLoanModule/Classes/IDController/IDHomeViewController.swift learn/iOS-Arch ↗.

File ini terbagi menjadi beberapa file extension dalam folder yang sama:

  • IDHomeViewController.swift (~45 KB) — logika controller utama.
  • IDHomeViewController+Popup.swift (~36 KB) — penanganan popup banner & dialog.
  • IDHomeViewController+Deeplink.swift (~5.6 KB) — penanganan navigasi deep link dari push/banner.

Pemisahan file dengan extension membantu merapikan ViewController yang berukuran masif (monolitik).

⚠️ H. Common Mistakes & Debugging

  • Salah Folder Modul: Meletakkan file controller baru langsung di root folder Application/.
  • Dampak: Merusak kerapian modularisasi dan menyulitkan pencarian kepemilikan kode.
  • Nama File Mirip di Folder Berbeda: Terdapat beberapa file historis dengan nama serupa (contoh: IDAuthLiveViewController.swift di SamirAuthModule/Classes/IDViewController vs file di IDViewControllerV2).
  • Cara Menghindari: Selalu periksa folder IDViewControllerV2 untuk implementasi aktif terbaru.

🧠 I. Knowledge Check

  1. Di mana letak file Podfile dan file main.swift dalam struktur repositori?
  2. Sebutkan 3 pustaka fondasi internal dengan prefix CZ dan fungsinya masing-masing!
  3. Mengapa penambahan file baru ke dalam folder Application/SamirLoanModule/ otomatis terbaca oleh Xcode 16?

Latihan Observasi:

Jalankan pencarian nama folder LoanConfirmModule di dalam SamirLoanModule. Perhatikan bahwa modul ini memiliki subfolder Controllers/, ViewModels/, Views/, Services/, dan Models/ tersendiri di dalam modul pinjaman.

🏛️ Bagian 2: Architecture Lab, SOLID Audit & Retention Quizzes

Architecture Lab

🏛️ Audit SOLID & Clean Architecture: Menemukan Titik Lemah pada Implementasi Existing

⚠️ Smells 1: Keterikatan Kuat Antar Sub-Modul & Kurangnya Inversi Dependensi

Implementasi komponen sering mengasumsikan keberadaan lingkungan runtime tertentu tanpa kontrak antarmuka yang didefinisikan secara tegas.

⚠️ Smells 2: Risiko Regresi & Minimnya Kontrak Pengujian Terisolasi

Perubahan pada satu service atau helper berpotensi merusak fungsionalitas di modul lain karena tingginya kohesi tersembunyi antar file.

🚀 Blueprint Refactoring Standar Industri: Pola Service Locator & Interface Segregation (SOLID)

Menerapkan prinsip Interface Segregation (ISP) dan Dependency Injection agar setiap service hanya mengekspos metode yang relevan bagi kliennya.

✅ Rekomendasi Solusi Arsitektur Bersih
public protocol SessionProvider: AnyObject {
    var currentToken: String? { get }
    var isAuthenticated: Bool { get }
}

public final class AppSessionManager: SessionProvider {
    public static let shared = AppSessionManager()
    public var currentToken: String?
    public var isAuthenticated: Bool { currentToken != nil }
}

Keunggulan Arsitektur Refactoring Ini:

  • 100% Mockable & Testable: Memungkinkan pengujian terisolasi tanpa memicu efek samping runtime produksi.
  • Open/Closed Principle (OCP): Penambahan fitur baru dapat dilakukan tanpa memodifikasi class yang sudah stabil.
  • Decoupled Subsystems: Membatasi dampak regresi saat terjadi perubahan dependensi eksternal.

🧠 Interactive Retention & Architectural Quiz

Uji pemahaman alur kode nyata dan keputusan arsitektur Anda:

Kuis 1 (Memory Recall): Berdasarkan standar Clean Architecture, apa peran utama dari domain layer pada modul IOS?

Kuis 2 (Architectural Decision): Mengapa penerapan Dependency Inversion Principle (DIP) sangat krusial dalam pembuatan unit test?

Kuis 3 (Debugging & Maintenance): Apa keuntungan utama membatasi dependensi antar modul ke arah satu arah (Unidirectional Dependency)?
